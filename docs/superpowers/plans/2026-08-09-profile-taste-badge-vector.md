# 프로필 취향 배지·벡터 구현 계획

> 사용자 확정안에 따라 프로필 중심을 외부 연결에서 음식 취향으로 이동한다.

## 작업 1. 배지 카탈로그와 데이터 계약

- FOOD/TASTE/STYLE 및 USER/NAVER/GOOGLE/INFERRED 타입을 정의한다.
- 요청된 배지 전체를 안정적인 ID, 표시명, 대표 문장 명사와 함께 카탈로그로 만든다.
- 카탈로그 유일성·범주·점수 범위를 단위 테스트로 고정한다.

## 작업 2. 사용자 취향 스키마

- 신규 `0017_profile_taste_badges.sql` migration을 추가한다.
- `taste_badges`, `user_taste_badges`를 Drizzle schema에 추가한다.
- 기존 migration은 수정하지 않는다.
- schema contract와 migration 적용 통합 테스트로 검증한다.

## 작업 3. 점수 합성과 활동 기반 추론

- 저장된 출처별 점수와 활동 기반 INFERRED 점수를 합성한다.
- 장소명·카테고리 기반 FOOD/STYLE 매칭과 Flavor Print 기반 TASTE 매칭을 구현한다.
- 비추천 제외, 점수 포화, 출처 가중치, 안정적인 정렬을 TDD로 구현한다.

## 작업 4. 대표 문구 생성

- 상위 FOOD 조합과 FOOD+STYLE 조합을 우선한다.
- 한국어 조사 계산을 포함한다.
- 데이터 부족 문구를 제공한다.
- 대표 배지 최대 7개와 그룹 균형 규칙을 테스트한다.

## 작업 5. 프로필 UI 재구성

- 이니셜 아바타·닉네임·대표 문구·배지를 상단에 배치한다.
- 학습 상태는 작은 안내와 진행도로 축소한다.
- 기존 저장·평가 기록은 유지한다.
- 외부 연결 상태는 페이지 최하단의 네이버·Google 소형 배지 두 개로 축소한다.

## 작업 6. 검증

- 단위·통합·타입·빌드 검증을 수행한다.
- 1440px 데스크톱과 390px 모바일을 Playwright로 캡처한다.
- 가로 넘침, 콘솔 오류, 접근성 이름을 확인한다.
- PR #64의 설명과 화면 증거를 새 구현 기준으로 갱신한다.
