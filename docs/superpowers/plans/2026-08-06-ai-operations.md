# Re:Taste AI 분류·운영 자동화 구현 계획

**목표:** 공공데이터 후보를 Workers AI가 구조화 분류하되 자동 공개하지 않고, 실패·불일치 후보를 수동 검수 큐에 안전하게 남긴다. 동기화·AI 실패와 운영 처리량은 한 화면에서 확인한다.

## Task 1 — 실행 이력과 알림 스키마

- AI 입력 해시, 모델·프롬프트 버전, 출력, 검증 상태, 캐시 원본을 보존한다.
- 동기화·AI·재계산 실패를 중복 집계 가능한 운영 알림으로 저장한다.

## Task 2 — Workers AI 보조 분류

- 상호명·업태·지역·활성 세부 카테고리만 전송한다.
- JSON Schema 출력도 서버에서 다시 검증한다.
- 30일 입력 캐시, 한 번에 100개·하루 500개 한도, 실패 이력을 구현한다.
- AI와 규칙이 일치하고 confidence 0.85 이상인 후보만 `AUTO` 후보가 된다. AI 단독 공개는 금지한다.

## Task 3 — 검수 화면 통합

- 후보 목록에 AI/규칙 출처, 신뢰도, 실패·불일치 이유를 표시한다.
- 관리자가 최대 100개 대기 후보를 AI 분류할 수 있다.
- 분류 실패 후보는 기존 수동 카테고리 선택으로 계속 처리할 수 있어야 한다.

## Task 4 — 운영 대시보드와 실패 알림

- 24시간·7일·30일 후보 수집, 승인·반려, 좌표 누락, AI 성공·실패·캐시, 동기화 실패를 표시한다.
- 외부 이메일은 운영 문의 주소 확정 전까지 제외하고 D1 알림과 관리자 화면만 제공한다.

## Task 5 — 검증·PR·배포

- 단위, D1 통합, 타입, 빌드, 관리자 E2E를 실행한다.
- PR merge 후 D1 export, 0007 migration, 병합 main 배포, 실제 Workers AI 1건과 수동 fallback을 운영 QA한다.
