# 어드민 후보 검수 UI·세분화 카테고리 구현 계획

**목표:** 배민의 음식 탐색 분류를 참고한 Re:Taste 2단계 카테고리를 도입하고, 공공데이터 후보를 빠르게 필터·정렬·검수할 수 있는 지도 중심 어드민 UI를 만든다.

**구조:** `categories.parent_id`로 대분류와 소분류를 표현한다. 공개 장소는 기존 `place_categories`로 대표 1개와 보조 여러 개를 연결한다. 공공데이터 `source_type`과 `business_subtype`은 공개 카테고리와 분리하며, 업태명 기반 추천 함수가 검수자의 선택을 보조한다.

## Task 1: 카테고리 계층과 기본 데이터

- `categories.parent_id`, `description`, `is_active` 추가
- 대분류 12개와 소분류 기본 세트 마이그레이션
- 업태명→추천 소분류 순수 함수와 단위 테스트

## Task 2: 후보 조회 필터·정렬

- 지역, 공공데이터 출처, 원천 세부업태, 좌표 유무 필터
- 최신 갱신순, 상호순, 원천 분류순, 지역순 정렬
- 필터 옵션 집계와 잘못된 입력의 안전한 기본값

## Task 3: 검수 화면 개편

- 데스크톱: 왼쪽 후보 목록, 중앙 네이버 지도, 오른쪽 검수 패널
- 모바일: 필터, 목록, 지도, 선택 후보 검수 순서
- 후보 선택 전에는 승인 폼 미노출
- 대분류 선택에 따라 소분류 제한
- 대표 소분류 1개와 보조 소분류 다중 선택
- 폰트 400~600 중심, 핵심 제목만 700

## Task 4: 승인 서비스 확장

- 대표·보조 카테고리를 한 번에 저장
- 기존 승인/폐업 숨김 동작 회귀 테스트
- 카테고리 중복과 비활성 카테고리 방어

## Task 5: 검증과 배포

- 단위·D1 통합·타입·빌드·브라우저 테스트
- PR diff 검토 및 squash merge
- 원격 D1 마이그레이션 후 병합된 main 배포
