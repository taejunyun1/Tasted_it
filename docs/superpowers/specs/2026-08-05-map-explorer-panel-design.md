# 지도 탐색 패널 설계

## 목표

회원 메인을 장소 탐색에 집중된 화면으로 구성한다. 사용자는 오른쪽 네이버 지도를 계속 보면서 왼쪽 패널에서 검색, 카테고리 필터, 현재 지도 범위의 장소 목록과 선택 장소 정보를 확인할 수 있어야 한다.

## 화면 구조

데스크톱은 왼쪽 탐색 패널과 오른쪽 지도의 2열 구조를 사용한다. 탐색 패널은 약 380~420px 고정 너비이며 나머지 영역을 지도가 사용한다. 사이트 헤더 아래에서 두 영역 모두 화면 높이를 채운다.

왼쪽 패널은 두 가지 상태를 갖는다.

1. 목록 상태
   - 상단 검색창
   - 내 위치로 이동 버튼
   - 가로 스크롤 가능한 대표·세부 카테고리 필터
   - 현재 지도 범위에서 공개 중인 장소 수
   - 장소 목록
2. 상세 상태
   - `← 목록으로` 버튼
   - 대표 이미지 또는 `RE:TASTE NO IMAGE` 대체 화면
   - 카테고리, 상호명, 동네, 주소
   - 추천 비율 또는 `평가 수 부족`
   - 추천·비추천 수
   - `상세 보기`, `네이버 길찾기` 버튼

오른쪽 지도에는 기존 네이버 지도, 현재 위치, 장소 핀과 확대·축소 컨트롤을 유지한다. 선택된 장소 핀은 기존 강조 스타일을 사용한다.

## 상호작용

- 지도 핀을 누르면 URL의 `selected` 값이 변경되고 왼쪽 패널이 상세 상태로 전환된다.
- 목록의 장소를 누르면 동일하게 상세 상태로 전환되고 해당 핀을 강조한다.
- `목록으로`를 누르면 `selected`만 URL에서 제거하고 검색어, 카테고리, 지도 범위는 유지한다.
- 지도 이동 또는 확대가 끝나면 `bbox`를 갱신하고 왼쪽 목록도 현재 범위의 공개 장소로 바꾼다.
- 선택 장소가 새 지도 범위나 필터 결과에서 제외되면 상세 상태를 닫고 목록 상태로 돌아간다.
- 검색과 카테고리 변경 시 선택 상태를 해제해 서로 다른 조건의 장소 상세가 남지 않게 한다.
- `상세 보기`는 `/places/:placeSlug`로 이동한다.
- `네이버 길찾기`는 장소 주소를 검색어로 한 네이버 지도 페이지를 새 탭에서 연다.

## 모바일

모바일에서는 지도를 기본 화면으로 유지하고 탐색 패널을 지도 하단 시트로 배치한다. 시트 상단에는 `지도`와 `목록` 전환 버튼을 제공한다. 핀을 누르면 시트가 선택 장소 요약을 표시할 만큼 올라오며, 상세 정보는 시트 내부에서 스크롤한다. 네이티브 드래그 제스처는 이번 범위에서 제외한다.

## 컴포넌트 경계

- `Home`: URL 검색 상태, 선택 장소 계산, 지도와 패널 배치
- `MapExplorerPanel`: 목록·상세 상태 전환과 검색·필터 UI
- `MapPlaceList`: 현재 결과 목록과 선택 요청
- `MapPlaceDetail`: 선택 장소 요약과 이동 링크
- `PlaceMap`: 지도 생성, 마커 렌더링, 선택·범위 이벤트 전달

패널 컴포넌트는 서버 요청을 직접 수행하지 않는다. `Home` loader가 제공하는 `PlaceSummary[]`와 URL 상태만 입력으로 받는다.

## 데이터와 표시 규칙

기존 `PlaceSummary`로 필요한 정보를 모두 표시한다. 추천 점수는 기존 `calculateRating`을 사용해 상세 페이지와 동일한 표기 규칙을 유지한다. 검수 승인되고 `PUBLISHED` 상태인 영업 장소만 기존 `listPlaces` 결과를 통해 노출한다.

이미지가 없을 때 외부 이미지를 임의로 가져오지 않는다. 주소, 동네 또는 평가 정보가 비어 있는 경우 각각 `주소 확인 중`, `지역 확인 중`, `평가 수 부족`으로 표시한다.

## 시각 기준

현재 Re:Taste의 흰색, 짙은 녹색, 연두 신호색과 각진 테두리 체계를 유지한다. 참고 화면의 정보 밀도와 좌우 분할은 따르되 혼잡도·차트 등 Re:Taste에 없는 데이터는 추가하지 않는다.

- 본문: 400
- 보조 정보와 링크: 500
- 상호명과 핵심 버튼: 600
- 700 이상 굵기 사용 금지
- 패널 전환은 160~200ms의 짧은 이동·투명도 효과만 사용
- 키보드 포커스, 명확한 버튼 이름, 이미지 대체 텍스트를 제공

## 오류와 빈 상태

- 검색 결과가 없으면 `이 범위에서 공개된 장소를 찾지 못했어요.`를 표시한다.
- 지도 SDK 오류는 기존 지도 오류 메시지를 유지하고 왼쪽 검색·목록은 계속 사용할 수 있게 한다.
- 선택 ID가 유효하지 않으면 오류 화면 대신 목록 상태를 표시한다.

## 테스트와 완료 기준

1. 핀 클릭 시 URL에 `selected`가 추가되고 왼쪽에 해당 장소명이 표시된다.
2. 목록 클릭도 같은 상세 상태를 만든다.
3. `목록으로` 클릭 시 선택만 제거되고 `bbox`, 검색어, 카테고리는 유지된다.
4. 선택된 장소가 필터 결과에서 사라지면 목록 상태로 복귀한다.
5. 연속 확대·이동 후에도 지도 상태와 왼쪽 목록이 함께 갱신된다.
6. 데스크톱과 모바일 Chromium에서 핵심 흐름을 검증한다.
7. 타입 검사, 단위 테스트, 통합 테스트와 프로덕션 빌드가 통과한다.

## 이번 범위에서 제외

- 혼잡도, 방문자 수, 시간대 차트
- 패널 드래그 제스처
- 지도 안에서 추천·비추천 또는 저장을 직접 처리하는 기능
- 신규 API나 데이터베이스 스키마 변경
