# 모바일 추천 지도 레이어링 A안 설계

**상태:** ACCEPTED
**작성일:** 2026-08-15
**연결 이슈:** #124
**결정:** 모바일 추천 지도는 `추천 우선 → 장소 확인` 흐름의 A안을 적용한다.

## 1. 문제와 목표

현재 모바일 추천 지도는 첫 진입 시 바텀시트가 화면의 약 절반만 차지해 추천 장소의 맥락과 첫 두 장소를 함께 읽기 어렵다. 장소를 선택한 뒤에도 지도에 집중할 여백이 충분하지 않다.

사용자가 해야 하는 일은 하나다. **지금 갈 만한 다섯 곳 중 한 곳을 고르고, 그 장소가 지도에서 어디인지 바로 확인하는 것**이다.

따라서 모바일에서는 첫 진입에 추천 내용을 넓게 보여주고, 장소를 선택하면 시트를 짧은 위치 확인 카드로 접어 지도를 우선한다. 데스크톱의 좌측 목록·우측 지도 분할 레이아웃은 바꾸지 않는다.

## 2. 확정 UX 흐름

### 2.1 첫 진입: 추천 우선

- 추천 지도 진입 시 시트는 `half` 스냅으로 연다.
- `half` 높이는 지도 컨테이너의 **70%**다. 추천 제목, 추천 방식 뱃지, 첫 두 장소와 핵심 이유가 한 화면 안에 읽히는 높이다.
- 지도는 시트 위쪽에 남아 현재 권역과 순위 마커를 계속 보여준다.
- 사용자는 손잡이를 위로 드래그하거나 탭해 전체 목록을 보고, 아래로 드래그하면 지도에 더 집중할 수 있다.

### 2.2 장소 선택: 지도 우선

- 추천 행을 탭하거나 키보드로 실행하면 즉시 `peek` 스냅으로 접는다.
- `peek`은 단순히 목록을 접은 상태가 아니라, 선택된 장소의 현재 순위와 이름을 계속 보여 주는 **위치 확인 상태**다.
- `peek` 높이는 **112px**이며, 위치 확인 정보와 시트 손잡이가 이 높이 안에서 항상 보여야 한다. 추천 목록 본문은 숨긴다.
- 기존 `selected` URL 검색 파라미터를 계속 사용한다. 선택된 장소 ID는 공유·뒤로가기에도 남는다.
- 기존 `PlaceMap`의 선택 장소 포커스 동작을 사용해 해당 좌표로 지도를 이동하고, 선택 마커를 강조한다.
- 추천 결과를 다시 조회하지 않는다. 선택은 UI 상태만 바꾸며 같은 후보 목록을 유지한다.
- 키보드나 포인터로 추천 행을 선택한 뒤에는 다음 애니메이션 프레임에 포커스를 시트 손잡이로 옮긴다. 접히면서 숨겨진 추천 행에 포커스가 남지 않아야 한다.

### 2.3 스냅과 조작

| 스냅 | 높이 | 목적 |
| --- | --- | --- |
| `peek` | 112px | 선택 장소를 지도에서 확인 |
| `half` | 지도 컨테이너의 70% | 추천을 비교하는 기본 상태 |
| `full` | 상단 16px을 남긴 최대 높이 | 다섯 장소와 이유를 모두 탐색 |

- 손잡이 드래그 임계값은 기존 36px을 유지한다.
- 손잡이는 버튼으로도 동작하며, `aria-label`은 현재 상태에 맞춰 `추천 목록 펼치기` 또는 `추천 목록 접기`를 제공한다.
- 모션 감소 설정(`prefers-reduced-motion`)에서는 높이 전환 애니메이션을 제거한다.
- 하단 안전 영역에는 `env(safe-area-inset-bottom)`을 반영해 iPhone 홈 인디케이터와 내용이 겹치지 않게 한다.

## 3. 컴포넌트와 상태 설계

### 3.1 `HomeCurationSheet`

- CSS의 `half` 높이는 70%로 변경한다.
- 시트는 스냅 상태를 자체 `useState`에 보관하지 않는다. `home.tsx`가 전달하는 `snap`과 `onSnapChange`를 사용하는 제어형(Controlled) 컴포넌트로 둔다.
- `HomeCurationCards`의 장소 선택 콜백을 시트 내부에서 감싼다.
  1. `onSnapChange("peek")`를 동기 실행한다.
  2. 기존 `onSelect(placeId)`를 호출해 URL의 `selected` 값을 바꾼다.
  3. `requestAnimationFrame`에서 시트 손잡이 버튼으로 포커스를 옮긴다.
- `peek` 상단은 `selectedPlaceId`로 현재 장소를 찾아 두 자리 순위와 상호명을 렌더하고, 긴 상호명은 한 줄 말줄임으로 112px 높이를 지킨다.
- 이 분리는 URL 검색 파라미터 이동으로 시트가 재마운트돼도 `peek` 상태가 초기화되지 않게 한다.
- 새로고침 직후 이미 `selected` 검색 파라미터가 있어도, 라우트 상태의 기본값은 `half`이므로 시트가 의도치 않게 접히지 않는다.

### 3.2 `home.tsx`와 `PlaceMap`

- `home.tsx`의 `selected` 검색 파라미터는 계속 유일한 선택 장소 단일 기준 원본(SSOT)이다.
- `home.tsx`는 모바일 시트의 일시적 표현 상태만 `useState<HomeSheetSnap>("half")`로 보관한다. 이는 선택 장소의 데이터 상태가 아니며 새로고침 시 `half`로 돌아간다.
- `home.tsx`는 이전 `view`를 추적하고 `browse → curated` 전환을 감지해 이 표현 상태를 `half`로 초기화한다. 따라서 추천 지도 버튼뿐 아니라 브라우저 history와 헤더 홈 링크로 복귀해도 같은 규칙을 적용한다.
- `PlaceMap`에 이미 있는 선택 장소 포커스/마커 강조를 회귀 테스트로 고정한다.
- 지도 마커를 직접 선택하는 흐름은 기존처럼 URL 선택만 갱신하며 현재 시트 스냅을 보존한다. 이번 변경은 **바텀시트 행 선택**만 명시적으로 `peek` 위치 확인 상태로 바꾸는 범위다.
- 추천 모드 변경, 내 위치 재탐색, 전체 지도↔추천 지도 전환은 기존 추천 응답 수명주기 규칙을 변경하지 않는다.

### 3.3 스타일과 레이어

- 모바일 시트는 기존 종이 카드(surface)·짙은 녹색 테두리·둥근 모서리·연한 그림자 방향을 유지한다.
- 시트는 지도 컨트롤보다 위, 전역 메뉴보다 아래에 위치한다. 메뉴가 열리면 기존 메뉴 레이어가 우선한다.
- `peek`에서는 목록 본문을 숨기되 선택 장소 위치 확인 정보, 시트 자체와 손잡이는 보여야 하고 조작 가능해야 한다.
- 데스크톱(`min-width: 761px`)의 `.home-curation-panel` 및 분할 그리드는 수정하지 않는다.

## 4. 실패·접근성·성능 기준

- 장소 선택 후 URL 업데이트나 지도 포커스가 지연돼도, 시트 축소는 즉시 반응한다.
- 추천 API 오류는 기존 오류 상태·재시도 동작을 유지한다.
- 추천 행은 계속 native `button`이므로 포커스·Enter/Space 실행이 가능해야 한다.
- 추천 행 실행 뒤에는 손잡이가 포커스를 받아 접힌 본문 안에 키보드 포커스가 고립되지 않아야 한다.
- 선택 행은 `aria-pressed="true"`를 유지한다.
- 새 네트워크 요청, 외부 API, 데이터베이스 변경, migration, 의존성 추가는 없다.

## 5. 검증 계획

### 단위 테스트

- 기본 `half`가 70%로 정의되는지 확인한다.
- 장소 행 선택 시 `peek`으로 전환하는 상태 전이 테스트를 추가한다.
- 드래그 36px 임계값, 모션 감소 CSS, `peek` 본문 비노출 계약을 유지한다.

### E2E

- 모바일 첫 진입에서 `data-snap="half"`와 추천 목록이 보이는지 확인한다.
- 두 번째 장소를 키보드로 선택하면 시트가 `peek`으로 바뀌고, 위치 확인 정보·URL `selected`·강조 마커가 같은 장소를 가리키며 손잡이가 포커스를 받는지 확인한다.
- 카드 선택 직후 `peek`을 확인하고 다시 펼친 뒤 손잡이 드래그/탭으로 목록 확장·축소가 가능한지 확인한다.
- `peek`에서 지도 마커를 선택해도 스냅이 바뀌지 않는지 확인한다.
- 전체 지도에서 브라우저 history 또는 헤더 홈 링크로 추천 지도에 복귀하면 `half`로 초기화되는지 확인한다.
- 데스크톱에서는 모바일 시트가 아닌 기존 좌측 추천 패널을 계속 사용하는지 확인한다.
- PR에는 데스크톱 및 모바일 스크린샷을 첨부한다.

## 6. 롤아웃과 롤백

- 기능 플래그·원격 데이터 작업 없이 UI 코드만 배포한다.
- 이상이 있으면 PR revert로 기존 52% 기본 시트와 선택 후 기존 상태 전이로 되돌릴 수 있다.
- 이 변경은 기존 추천 알고리즘·카테고리·지도 공급자·권한 체계에 영향을 주지 않는다.
