# 경양식 돈가스 분류·승인 불가 탭 분리·DB 감사 설계

## 목표

1. 공공데이터의 원천 세부업태가 `경양식`이면 돈가스를 기본 추천한다.
2. 기술적으로 승인할 수 없는 후보는 일반 검수 목록에 섞지 않고 `승인 불가·예외` 탭에서만 표시한다.
3. 운영 DB가 현재 스키마와 서비스 규칙에 맞게 구성됐는지 개인정보와 상호명을 출력하지 않는 집계로 점검한다.

## 분류 규칙

- `경양식`은 `donkatsu-detail`을 가리키는 별도 원천 업태 규칙으로 처리한다.
- 일반 `양식`은 기존 `pasta` 기본 추천을 유지한다.
- 상호명에서 파스타·스테이크·피자·버거·돈가스처럼 더 구체적인 음식 신호가 발견되면 상호명 규칙이 원천 업태 기본값보다 우선한다.
- 분류 신뢰도와 근거 계산 방식은 기존 점수 체계를 유지한다.
- 기존 후보는 다음 규칙 분류 또는 재분류 시 새 정책을 적용한다. 운영 DB의 AI 결과를 강제로 덮어쓰지 않는다.

## 관리자 검수 목록

- 일반 검수 집합은 `AUTO`와 `MANUAL` 후보만 포함한다.
- 기본 `전체` 건수와 목록에서도 `BLOCKED` 후보를 제외한다.
- `분류 완료`에는 `AUTO`, `수동 확인`에는 `MANUAL`만 표시한다.
- `승인 불가·예외`에는 다음을 합쳐 표시한다.
  - 좌표 누락, 동네 추출 실패, 기존 공개 장소 중복 등 계산된 `BLOCKED` 후보
  - 유흥업종 자동 제외와 관리자 수동 예외
- `체인점 제외` 탭은 기존처럼 체인점 자동 제외만 표시한다.
- 승인 불가 후보의 체크박스와 승인 작업은 계속 비활성화한다.

## 운영 DB 읽기 전용 감사

다음 항목을 건수로만 기록한다.

- 적용 migration과 미적용 migration
- `PRAGMA foreign_key_check` 위반
- 원천 종류·관리번호 중복
- 영업·검수 상태별 후보 분포
- 주소·좌표 누락 및 광주·전남 범위를 벗어난 좌표
- 승인 후보와 공개 장소 연결 누락 또는 중복
- 카테고리 연결의 고아 참조, 비활성·비말단 카테고리 연결
- 활성 제외와 승인 상태가 동시에 존재하는 충돌
- 체인·유흥·관리자 예외의 상태별 분포
- 분류 결과의 존재 여부와 활성 카테고리 연결 가능 여부

감사 SQL은 상호명, 주소, 전화번호, 이메일, 원본 payload를 반환하지 않는다. 이번 작업에서 운영 DB는 수정하지 않는다. 오류가 발견되면 유형과 건수만 보고하고, 데이터 변경은 별도 승인 후 수행한다.

## 테스트

- 단위 테스트: `경양식 → 돈가스`, `양식 → 파스타`, 구체 상호명 우선
- E2E 테스트: 기본 전체에서 승인 불가 행이 보이지 않고 `승인 불가·예외` 탭에서만 보임
- 기존 체인·관리자 예외 탭 회귀 테스트
- 데스크톱과 모바일 화면 증거
- 전체 단위·통합 테스트, 타입 검사, 프로덕션 빌드

## 범위 밖

- 카테고리 스키마 변경
- 운영 데이터 일괄 재분류 또는 자동 승인
- 좌표 보정과 중복 병합
- 승인 불가 후보를 영구 제외 행으로 변환
