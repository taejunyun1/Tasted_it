# 홈 큐레이션 지도 및 상황별 추천 5곳 설계

## 1. 목적

홈(`/`)을 모든 공개 장소를 한꺼번에 보여주는 지도에서, 사용자가 지금 갈 만한 장소를 빠르게 고를 수 있는 큐레이션 지도로 바꾼다. 기본 진입에서는 현재 위치 또는 광주 기본 중심, 현재 시간대, 사용자 취향, 평가 신뢰도, 새로운 발견을 결합한 5곳만 지도와 추천 시트에 표시한다.

홈의 핵심 질문은 `이 주변에 무엇이 있는가?`보다 `지금 어디를 가면 좋은가?`다. 전체 장소 검색과 지역 탐색은 제거하지 않고 사용자가 명시적으로 전환하는 `전체 탐색` 모드로 보존한다.

## 2. 선택한 방향

선택안은 `큐레이션 지도 + 스냅 시트`다.

- 지도에는 현재 추천 결과 5개의 번호 마커만 표시한다.
- 모바일에서는 지도 위 바텀시트가 접힘·중간·전체 높이로 이동한다.
- 데스크톱에서는 왼쪽 패널 상단에 같은 추천 5곳을 표시한다.
- 카드와 지도 마커는 같은 번호를 사용하며 양방향으로 초점을 동기화한다.
- 추천 모드 버튼은 장소를 강제로 걸러내는 검색 필터가 아니라 추천 점수와 슬롯 구성을 바꾸는 조정 장치다.
- `전체 장소 보기`는 추천 모드와 분리된 탐색 상태다.

## 3. 범위

### 포함

- 기본 `지금 추천` 5곳
- `나의 취향`, `시간대`, `Golden Pick`, `새로운 맛` 추천 모드
- 현재 위치 허용 시 위치 기반 재추천
- 위치 거부 또는 미지원 시 광주 기본 중심 추천
- 추천 카드와 번호 마커의 양방향 선택
- 지도 이동 후 명시적인 `이 지역 다시 추천` 동작
- 기존 검색·카테고리·행정구역 탐색을 보존한 `전체 탐색` 모드
- 데스크톱 왼쪽 패널과 모바일 바텀시트
- 추천 이유 최대 두 개
- 로딩, 빈 상태, 위치 거부, 추천 실패 상태

### 제외

- 외부 날씨·실시간 트렌드 API
- 실시간 LLM, 임베딩, 복잡한 기계학습 모델
- 운영 데이터 직접 수정
- 평가 신뢰도, Golden Pick 부여·만료 산식 변경
- 장소 영업시간 데이터가 없는 상태에서 `영업 중`이라고 단정하는 기능
- 신규 데이터베이스 테이블 또는 migration
- 운영 배포와 원격 D1 변경

## 4. 사용자 흐름

### 4.1 첫 진입

1. 홈 loader는 URL의 유효한 지도 범위가 있으면 그 중심을 사용한다.
2. 범위가 없으면 광주 기본 중심과 기본 반경을 사용한다.
3. 기본 모드는 `지금 추천`이다.
4. 추천 5곳과 번호 마커를 표시한다.
5. 위치 권한은 자동으로 요청하지 않고 사용자가 `내 위치`를 누를 때만 요청한다.
6. 위치 허용 시 기존 위치 정책으로 지도 범위를 계산하고 URL 상태를 갱신한 뒤 추천을 다시 계산한다.
7. 위치 좌표는 사용자 취향이나 제품 데이터로 저장하지 않는다.

### 4.2 추천 탐색

- 사용자가 추천 모드 버튼을 누르면 전체 페이지를 새로고침하지 않고 추천 리소스 요청으로 5곳만 다시 계산한다.
- 이전 결과는 새 응답이 도착할 때까지 유지한다.
- 카드 선택 시 해당 번호 마커를 강조하고 지도 중심을 이동한다.
- 마커 선택 시 대응 카드가 보이도록 시트를 이동하거나 패널을 스크롤한다.
- 장소 상세는 기존 상세 시트 계약을 재사용한다.

### 4.3 지도 이동

지도 pan·zoom마다 자동으로 추천을 다시 계산하지 않는다. 자동 재계산은 마커와 카드가 갑자기 바뀌는 문제와 불필요한 서버 요청을 만든다.

- 사용자가 현재 추천 범위를 벗어나 지도를 이동하면 `이 지역 다시 추천` 버튼을 표시한다.
- 버튼을 누를 때만 새 bbox와 중심 좌표로 현재 추천 모드를 다시 실행한다.
- 전체 탐색 모드에서는 기존 bbox 기반 지도 갱신 규칙을 유지한다.

### 4.4 전체 탐색

- `전체 장소 보기`를 누르면 `전체 탐색` 상태로 전환한다.
- 이 상태에서는 기존 전체 공개 장소 마커, 검색, 카테고리, 행정구역 그룹을 표시한다.
- `추천 지도로 돌아가기`를 누르면 마지막 추천 모드와 추천 결과로 돌아간다.
- 검색어 또는 카테고리를 직접 선택하면 전체 탐색 상태로 전환한다.

## 5. 추천 후보와 품질 하한

홈 추천은 `/places` 추천과 같은 공개 후보 및 계산 결과를 재사용한다.

- 공개 상태이며 유효한 좌표를 가진 장소만 사용한다.
- 체인점 제외, 운영 정책 제외, 승인 불가 장소는 후보에 포함하지 않는다.
- 최신 유효 평가 스냅샷과 이미 계산된 취향 신호를 사용한다.
- 요청마다 Wilson 점수, 평가 통계, Flavor Print를 다시 계산하지 않는다.
- 후보는 현재 bbox와 중심 좌표 기준 최대 500곳으로 제한한다.
- 기본 반경은 3km이며 후보가 부족할 때만 5km로 확장한다.
- 품질 하한은 `공개 승인 + 유효 좌표 + 활성 대표 카테고리 + 운영 정책 비제외`다. 표본이 8개 이상이면서 공개 추천 점수가 55점 미만인 장소도 홈 추천에서 제외한다.
- 평가 표본이 8개 미만인 승인 장소는 일반·취향·시간대·발견 슬롯에 들어갈 수 있지만 `평가 수집 중`으로 표시하고 신뢰 추천 슬롯에는 넣지 않는다.
- 활성 Golden Pick은 리뷰어의 명시적 선택이므로 표본 8개 미만이어도 Golden Pick 슬롯에 들어갈 수 있다. 다만 공개 추천 점수가 이미 보이고 55점 미만이면 제외한다.
- 계절·취향·시간대·거리 가중치는 위 품질 하한을 우회할 수 없다.
- 스냅샷이 없는 장소의 기존 투표 집계 대체 규칙은 `/places` 추천과 동일하게 유지한다.

추천 후보 조회와 평가·취향 결합은 공용 모듈로 분리한다. 홈과 `/places`가 후보 조회 코드를 각각 복사하지 않는다.

## 6. 기본 추천 5개 슬롯

단순 종합점수 상위 5곳을 그대로 사용하지 않는다. 각 자리에 역할을 부여한다.

1. **Best Now**: 취향, 거리, 시간대, 신뢰도를 가장 균형 있게 충족하는 곳
2. **Taste Match**: 사용자 상위 취향과 직접 일치하는 곳
3. **Time Match**: 현재 시간대의 식사 상황에 적합한 곳
4. **Trusted Pick**: 활성 Golden Pick 또는 Re:Taste 평가 신뢰도가 높은 곳
5. **Discovery**: 인접 취향 또는 아직 반응하지 않은 카테고리의 품질 좋은 곳

후보 부족 시 빈 자리를 남기지 않고 종합점수 차순위로 채우되, 카드의 추천 이유는 실제 선정 근거만 표시한다.

## 7. 점수 구성

모든 세부 점수는 `0..1`로 정규화한다. 기본 `지금 추천`은 다음 가중치를 사용한다.

| 신호 | 비중 | 의미 |
| --- | ---: | --- |
| 취향 적합도 | 30% | 사용자 취향 벡터와 장소 카테고리·검색 문구의 직접·인접 일치 |
| 거리 적합도 | 25% | 현재 중심에서 가까울수록 높은 점수, 과도한 원거리 급감 |
| 시간대 적합도 | 20% | 현재 시간대와 대표 음식·식사 유형의 적합성 |
| 평가 신뢰도 | 15% | 최신 평가 스냅샷, 표본 수, 회원·리뷰어 일치 |
| 새로운 발견 | 10% | 아직 반응하지 않은 품질 좋은 인접·신규 취향 |

최종 순서는 가중합만으로 확정하지 않고 슬롯 역할과 다양성 규칙을 함께 적용한다.

## 8. 시간대 정책

시간대는 한국 표준시(Asia/Seoul)를 사용한다.

| 시간대 | 시간 | 우선 식사 맥락 예시 |
| --- | --- | --- |
| 아침 | 05:00–10:30 | 백반, 국밥, 해장국, 베이커리, 커피 |
| 점심 | 10:30–14:30 | 한 끼 음식 전반, 회전이 빠른 식사, 혼밥 |
| 오후 | 14:30–17:30 | 카페, 디저트, 베이커리, 가벼운 식사 |
| 저녁 | 17:30–21:30 | 고기, 해산물, 전골, 식사와 술안주 |
| 늦은 시간 | 21:30–05:00 | 야식, 국물, 주점, 늦은 식사 |

시간대 점수는 카테고리와 취향 신호에 대한 적합도다. 신뢰할 수 있는 영업시간 데이터가 없으면 `지금 영업 중`을 추천 이유로 표시하지 않는다. 대신 `점심에 어울림`, `오후 방문 적합`처럼 시간대 맥락만 표현한다.

## 9. 추천 모드

### 9.1 지금 추천

- 다섯 슬롯을 모두 사용한다.
- 위치·시간대·취향·신뢰·발견의 균형을 우선한다.

### 9.2 나의 취향

- 직접 취향 일치 2곳
- 인접 취향 1곳
- 신뢰 추천 1곳
- 새로운 발견 1곳
- 개인화 기여도는 최종 점수의 35%를 넘지 않는다.

### 9.3 시간대

- 시간대 적합 2곳
- 가까운 장소 1곳
- 취향 일치 1곳
- 신뢰 추천 1곳
- 영업시간 부재 시 영업 여부를 추측하지 않는다.

### 9.4 Golden Pick

- 활성 Golden Pick 중 서로 다른 리뷰어, 대표 카테고리, 동네를 우선한다.
- 첫 장소의 개인화 가중치는 최대 25%로 제한한다.
- 활성 Golden Pick이 5곳보다 적으면 부족한 자리를 Re:Taste 신뢰 추천으로 채운다.
- 대체 장소에는 Golden Pick 배지를 붙이지 않는다.

### 9.5 새로운 맛

- 인접 취향 2곳
- 사용자가 아직 저장·평가하지 않은 카테고리 2곳
- 평가 신뢰도가 높은 안전한 발견 1곳
- 새로운 발견 후보도 동일한 품질 하한을 통과해야 한다.

## 10. 다양성 규칙

- 동일 대표 카테고리 최대 2곳
- 동일 동네 최대 2곳
- `지금 추천`, `나의 취향`, `시간대`에는 새로운 발견 최소 1곳
- 이미 선택된 장소와 같은 장소는 다음 슬롯에서 제외
- 다양성 조건 때문에 품질 하한 미달 장소를 올리지 않는다.
- 조건을 모두 만족하는 후보가 부족하면 카테고리 제한, 동네 제한 순서로 한 단계씩 완화하고 그 사실을 사용자에게 별도 노출하지 않는다.

## 11. 추천 이유

카드에는 점수 기여와 슬롯 선정 근거에서 최대 두 개만 표시한다. 실시간 생성형 문구를 사용하지 않는다.

- `국밥 취향과 가까움`
- `점심에 어울림`
- `현재 위치에서 가까움`
- `평가 신뢰도 상위`
- `리뷰어 Golden Pick`
- `평소 취향에서 한 발짝`
- `아직 평가하지 않은 메뉴`

근거가 없는 `인기 맛집`, `영업 중`, `현지인 추천` 같은 표현은 만들지 않는다.

## 12. URL 및 상태 계약

공개 URL 상태는 기존 지도 검색 상태와 충돌하지 않게 단일 값으로 제한한다.

- `view=curated|browse`, 기본값 `curated`
- `mode=now|taste|time|golden|discovery`, 기본값 `now`
- 기존 `bbox`, `selected`, `place`, `category`, `q`는 유지
- 알 수 없는 `view`와 `mode`는 기본값으로 정규화한다.
- 추천 모드 변경은 히스토리를 불필요하게 쌓지 않도록 replace navigation을 사용한다.
- 상세 장소 query와 기존 엄격한 상세 provenance 계약은 변경하지 않는다.

## 13. 서버와 데이터 흐름

### 13.1 공용 후보 서비스

홈과 `/places`가 함께 사용할 공용 후보 로더는 다음을 반환한다.

- 공개 장소 후보 최대 500곳
- 장소별 최신 유효 평가 스냅샷
- 사용자 또는 비회원 취향 신호
- 활성 Golden Pick과 리뷰어 식별자
- 계산 기준 시각과 중심 좌표

### 13.2 홈 큐레이션 순수 함수

입력:

- 후보 장소
- 중심 좌표
- 현재 시간대
- 사용자 취향 신호
- Golden Pick
- 추천 모드

출력:

- 5개 슬롯 결과
- 장소별 번호와 슬롯 종류
- 실제 추천 이유 최대 두 개
- 적용 반경과 기준 위치 설명

점수 계산과 슬롯 선택은 순수 타입스크립트 함수로 구현해 D1 없이 단위 테스트할 수 있게 한다.

### 13.3 리소스 갱신

추천 모드 또는 `이 지역 다시 추천`은 React Router fetcher를 통해 추천 결과만 요청한다. 응답 실패 시 기존 5곳을 유지하고 `추천을 새로 불러오지 못했어요. 다시 시도해 주세요.`를 표시한다.

## 14. UI 구조

### 14.1 모바일

- 지도는 화면 전체 배경을 유지한다.
- 바텀시트는 첫 진입에서 중간 높이로 열린다.
- 접힘 상태에는 `지금 갈 만한 5곳` 제목과 선택 장소 한 곳을 표시한다.
- 중간 상태에는 추천 모드와 카드 2곳을 표시한다.
- 전체 상태에는 5곳 전체와 추천 이유를 표시한다.
- 지도 drag 중에는 시트를 접을 수 있고, 추천 카드 선택 시 중간 상태 이상으로 이동한다.

### 14.2 데스크톱

- 기존 왼쪽 탐색 패널 자리에 추천 제목, 모드, 5개 카드가 먼저 나타난다.
- 지도는 오른쪽에 유지한다.
- `전체 장소 보기`를 누르면 기존 검색·카테고리·지역 탐색 패널로 전환한다.

### 14.3 마커

- 추천 마커는 `1..5` 번호를 사용한다.
- 선택 마커는 라임색, 나머지는 딥그린을 사용한다.
- Golden Pick 여부는 마커 색으로 표현하지 않고 카드 배지로만 표시해 번호 의미를 보존한다.
- 추천 결과가 바뀌면 번호와 카드 순서를 함께 갱신한다.

## 15. 접근성

- 추천 모드 버튼은 `aria-pressed`를 사용한다.
- 바텀시트는 제목과 상태를 제공하고 키보드로 접힘·확장이 가능해야 한다.
- 마커와 카드는 동일 장소 이름을 접근 가능한 레이블로 공유한다.
- 카드 선택과 fetcher 갱신 결과는 `aria-live`로 알린다.
- 포커스 이동 없이 결과가 교체되지 않도록 현재 선택 장소가 새 결과에 없을 때 첫 카드로 명시적으로 이동한다.
- 애니메이션 감소 설정에서는 시트와 지도 이동을 즉시 적용한다.

## 16. 오류 및 빈 상태

- 위치 거부: 광주 기본 중심 추천을 유지하고 `광주 중심 기준`을 표시한다.
- 추천 후보 5곳 미만: 반경을 5km까지 확장하고 가능한 수만 표시한다.
- Golden Pick 부족: Re:Taste 신뢰 추천으로 채우되 Golden Pick으로 위장하지 않는다.
- 취향 데이터 없음: 거리·시간대·신뢰도 중심으로 추천하고 발견 슬롯을 유지한다.
- 추천 리소스 실패: 기존 결과와 지도는 유지하고 재시도 버튼을 제공한다.
- 전체 추천 실패: 전체 탐색 전환 버튼을 제공해 기본 지도 기능을 계속 사용할 수 있게 한다.
- 지도 SDK 실패: 추천 카드 5곳은 계속 탐색할 수 있게 한다.

## 17. 성능

- 후보는 요청당 최대 500곳이다.
- 평가 점수와 취향 신호는 저장된 값을 사용한다.
- 지도 pan마다 자동 요청하지 않는다.
- 모드 변경 응답은 추천 5곳과 필요한 표시 데이터만 반환한다.
- 같은 bbox, 사용자, 모드, 시간대 구간의 결과는 짧은 요청 범위에서 재사용할 수 있지만 이번 작업에서 별도 캐시 저장소를 추가하지 않는다.

## 18. 검증

### 단위 테스트

- 기본 5개 슬롯 배정
- 모드별 슬롯 구성
- 가중치와 개인화 상한
- 동일 카테고리·동네 최대 2곳
- 새로운 발견 최소 1곳
- 시간대 경계와 Asia/Seoul 기준
- Golden Pick 부족 시 신뢰 추천 대체 및 배지 정확성
- 품질 하한과 3km→5km 확장
- URL `view`, `mode` 정규화

### 통합 테스트

- 공개 후보, 평가 스냅샷, 취향 신호, Golden Pick 결합
- 비회원과 로그인 사용자의 취향 입력 차이
- 추천 리소스 응답과 오류 시 기존 결과 유지 계약
- 전체 탐색의 기존 검색·카테고리 계약 보존

### 브라우저 테스트

- 첫 진입에서 큐레이션 5곳과 번호 마커 표시
- 위치 거부 후 광주 기본 중심 유지
- 추천 모드 변경 시 전체 페이지 새로고침 없이 카드·마커 동시 갱신
- 카드와 마커 양방향 선택
- 지도 이동 후 `이 지역 다시 추천`
- `추천 지도 ↔ 전체 탐색` 전환
- 모바일 바텀시트 접힘·중간·전체 상태
- 데스크톱과 모바일 시각 증거

## 19. 성공 기준

- 사용자가 홈 진입 후 검색 없이 추천 장소 상세를 열 수 있다.
- 기본 지도에는 추천 5곳만 나타나며 전체 장소는 명시적으로 요청할 때만 나타난다.
- 모든 추천 카드는 실제 데이터 기반 이유를 최대 두 개 제공한다.
- 사용자가 모드를 바꿔도 지도와 카드의 장소·번호가 항상 일치한다.
- 취향 데이터가 없어도 위치·시간대·신뢰도 중심 추천이 작동한다.
- 위치·추천·지도 실패 중 하나가 발생해도 전체 장소 탐색 경로가 남는다.

## 20. 운영 영향

- 신규 migration과 환경 변수는 없다.
- 외부 유료 API와 Workers AI를 추가 호출하지 않는다.
- 위치 정보는 기존 정책과 같이 현재 브라우저 요청과 URL 지도 범위에만 사용한다.
- 운영 배포 전 데스크톱·모바일 시각 검수와 기존 지도 회귀 테스트가 필요하다.
