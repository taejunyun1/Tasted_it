# `/places` 취향 탐색 추천·UI 개편 설계

## 목적

`/places`를 정적인 맛집 목록이 아니라 사용자가 최대 두 개의 취향 배지를 눌러 익숙한 취향과 새로운 발견을 함께 탐색하는 화면으로 개편한다. 기존의 개인 취향 추천, Re:Taste 추천, Golden Pick 추천 구조는 유지하되 세 영역의 추천 목적과 시각적 위계를 분명히 구분한다.

## 범위

- 음식·맛·스타일·계절·탐색 배지 최대 8개 노출
- 최대 2개 배지 동시 선택
- 개인 취향 추천을 익숙함 50%, 인접 취향 25%, 새로운 발견 25%로 구성
- Re:Taste 추천을 기존 평가 스냅샷 기반 신뢰 추천으로 구성
- Golden Pick을 서로 다른 리뷰어·카테고리·동네를 잇는 릴레이로 구성
- 배지 선택 시 전체 페이지 이동 없이 추천 결과만 갱신
- 코스 추천과 나의 취향 화면의 글꼴·색상·모서리·배지 체계 적용
- 데스크톱과 모바일 반응형 UI 및 접근성 제공

## 제외 범위

- 운영 DB 스키마 변경
- 날씨·트렌드 외부 API
- LLM, 임베딩, 실시간 ML 모델
- 추천 노출 이력 저장과 A/B 테스트
- 전체 장소 검색의 기존 검색 의미 변경

## 데이터 활용

- 사용자: `user_taste_badges`, 저장 장소, 긍정 평가 기록
- 장소: `places`, 대표 `categories`, `search_text`, 좌표와 동네
- 평가: 최신 비정상(stale) 상태가 아닌 `rating_snapshots`; 없으면 현재 투표 집계 기반 점수
- 리뷰어 선택: 활성 `golden_pick_events`
- 계절: 서버의 현재 월만 사용
- 취향 인접 관계: 코드 상수 `TASTE_ADJACENCY`

장소 취향 벡터는 별도 테이블을 만들지 않고 이미 조회한 대표 카테고리 슬러그·이름과 정규화한 상호명·검색 문구에 카탈로그 키워드를 적용해 요청 안에서 생성한다. 후보는 최대 500곳이며 복잡한 통계는 재계산하지 않는다.

## 추천 배지

노출 배지는 최대 8개다.

1. 사용자 상위 취향 3개
2. 현재 계절 후보 2개
3. 새로운 발견 2개
4. 일반 추천 1개

중복 라벨은 하나로 합치고 사용자 취향이 부족하면 일반·계절·탐색 배지로 채운다. 선택은 최대 2개이며 세 번째를 누르면 상태를 변경하지 않고 제한 안내를 표시한다.

계절 후보는 월 기준으로 결정한다.

- 봄: 봄나물, 쭈꾸미, 도다리, 딸기, 봄 제철
- 여름: 냉면, 막국수, 콩국수, 물회, 빙수, 삼계탕, 장어, 여름 별미
- 가을: 전어, 대하, 꽃게, 버섯, 가을 제철
- 겨울: 국밥, 해장국, 전골, 칼국수, 어묵, 굴, 대방어, 겨울 국물

## 개인 취향 추천

8곳을 기준으로 익숙한 취향 4곳, 인접 취향 2곳, 새로운 취향 2곳을 우선 배정한다. 선택 배지가 있으면 직접 일치 60%, 인접 취향 25%, 새로운 발견 15%의 관련도 점수를 사용하되 최종 결과에는 새로운 취향을 최소 2곳 유지한다.

실시간 점수는 다음 값만 결합한다.

- 기존 평가·신뢰 점수
- 사용자 취향 유사도(전체 점수의 최대 35%)
- 선택 배지 직접 일치
- `TASTE_ADJACENCY` 인접 관계
- 계절 가중치(최대 15%)
- 중심 좌표 거리
- 동일 카테고리·동네 다양성 감점

동일 대표 카테고리 최대 2곳, 동일 동네 최대 2곳을 강제한다. 품질 하한을 통과하지 못한 장소는 계절·탐색 가중치로 상위에 진입할 수 없다.

## Re:Taste 추천

개인 취향 영향 없이 최신 평가 스냅샷을 중심으로 정렬한다. `overallScore`, 전체 표본 수, 회원·리뷰어 점수 일치, 스냅샷 최신성을 사용한다. 스냅샷이 없는 장소만 기존 투표 집계 점수를 사용한다. 개인 추천 및 Golden Pick과 중복되는 장소는 차순위 후보로 교체한다.

## Golden Pick 취향 릴레이

활성 Golden Pick만 후보로 사용한다. 첫 장소에는 개인화 가중치를 최대 25% 적용한다. 이후 장소는 다른 리뷰어, 다른 대표 카테고리, 다른 동네, 적절한 이동 거리 순으로 선택한다. 동일 리뷰어와 동일 대표 카테고리가 연속되지 않게 한다.

## 제목과 추천 이유

제목은 실시간 LLM 없이 템플릿으로 생성한다.

- 냉면: 오늘은 시원하게
- 국밥: 오늘은 뜨끈하게
- 노포: 오래된 맛을 찾아서
- 새로운 맛: 평소와 다른 한 끼
- 계절: 지금 먹기 좋은 계절의 맛
- 냉면 + 노포: 오래된 여름의 맛
- 국밥 + 노포: 오래된 집에서 뜨끈하게

각 카드에는 실제 점수 기여가 큰 추천 이유를 최대 2개 표시한다. 임의 문장은 생성하지 않는다.

## 갱신 구조

최초 loader는 추천 결과와 추천 배지를 반환한다. 배지 선택은 React Router `fetcher`로 추천 전용 리소스 라우트를 호출한다. 응답은 제목과 세 추천 영역만 포함하며 페이지·스크롤·전체 loader를 다시 시작하지 않는다. 요청 실패 시 기존 결과를 유지하고 다시 시도할 수 있는 상태 문구를 노출한다.

## UI

- 큰 제목 `오늘 뭐 먹지?`와 짧은 안내 문구
- 추천 방향 배지는 2~3줄로 전체 노출하고 가로 스크롤에 의존하지 않음
- 활성 배지는 라임 배경과 진한 녹색 글자
- 개인 발견은 대표 카드 1개와 보조 카드 그리드
- Re:Taste는 평가 근거가 잘 읽히는 카드 그리드
- Golden Pick은 선택의 흐름이 보이는 릴레이형 카드
- SUIT/Pretendard 계열 글꼴, 짙은 녹색·오프화이트·라임 색상 사용
- 모바일은 한 열 카드와 충분한 터치 영역을 제공
- `aria-pressed`, `aria-live`, 키보드 포커스, reduced motion을 지원

## 검증

- 배지 조합과 최대 선택 수 단위 테스트
- 계절 후보와 제목 템플릿 단위 테스트
- 직접·인접·탐색 할당 및 다양성 제한 단위 테스트
- 평가 스냅샷·Golden Pick 후보 조회 통합 테스트
- loader와 리소스 라우트 계약 테스트
- 데스크톱·모바일 Playwright 검증 및 스크린샷
- 전체 unit, integration, typecheck, build 통과
