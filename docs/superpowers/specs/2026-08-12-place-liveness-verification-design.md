- **작성일:** 2026-08-12
- **상태:** 사용자 승인 완료
- **담당:** Codex / tj
- **추적:** GitHub Issue #89
- **선행 작업:** 비음식 유흥업소 필터 PR #88

## 1. 목적

공공데이터에는 `영업`으로 남아 있지만 실제로는 주소만 존재하거나 운영 여부가 불확실한 장소가 있다. Re:Taste는 공공데이터 영업 상태, Kakao Local 장소 검색, 내부 방문·평가 증거를 자동 교차검증해 다음 네 상태로 분류한다.

- `VERIFIED`: 실제 영업 증거가 충분함
- `MONITORING`: 정보가 일부 부족하지만 공개를 유지함
- `SUSPECTED`: 운영 의심. 지도 공개는 유지하되 추천에서 제외함
- `HIDDEN`: 공식 폐업 또는 다중 증거로 운영 중단 가능성이 매우 높아 임시 숨김

자동화의 목표는 무조건 삭제가 아니라, 명백한 폐업은 빠르게 숨기고 애매한 장소는 추천에서 먼저 제외한 뒤 관리자에게 근거를 제공하는 것이다.

## 2. 확정된 음식점 경계

기존 PR #88에 다음 정책을 추가한다.

- 제외: `라이브카페`, `7080라이브`, `라이브홀`, `뮤직홀`, `룸바`, `디스코텍`, `노래주점`
- 유지: `감성주점`, `소주방`, `포장마차`, `펍`, `와인바`, `이자카야`, `치킨호프`

이 정책은 영업 실재성 자동화와 별개다. 유흥 중심 업소는 장소 존재 여부와 관계없이 음식 추천에서 제외한다.

## 3. 검토한 접근

### A. 공공데이터 상태만 사용

비용과 구현이 가장 작지만, 갱신 지연과 주소만 등록된 영업 상태를 확인할 수 없다.

### B. 사용자 요청마다 Kakao Local을 실시간 호출

최신 결과를 얻지만 지도·추천 응답이 외부 API 장애와 지연에 종속되고 호출량도 커진다. 채택하지 않는다.

### C. 예약 교차검증 후 D1 스냅샷 사용 — 채택

외부 API는 백그라운드에서 제한적으로 호출하고, 공개 화면은 미리 저장한 판정만 읽는다. 사용자 요청 경로는 Kakao 응답과 무관하게 동작하며 비용과 장애 범위를 통제할 수 있다.

## 4. 공급자와 데이터 최소화

Kakao Local의 `키워드로 장소 검색` API를 서버에서 호출한다.

- 요청: `상호명 + 도로명 주소`, 기존 경도·위도, 제한 반경
- 응답 사용: Kakao 장소 ID, 장소명, 음식점·카페 분류, 주소, 좌표, 전화번호
- 전송하지 않음: 회원 위치, 이메일, 계정 정보, 리뷰 내용, 리뷰어 신원
- 저장하지 않음: 전체 원본 응답
- 저장: 일치 결과, 점수 구성, 공급자 오류 코드, 확인 시각과 연속 미검색 횟수만 저장

운영 비밀값은 이미 등록된 `KAKAO_REST_API_KEY`를 사용하며 코드·로그·D1·PR에 저장하지 않는다.

공식 문서:

- Kakao Local 장소 검색: https://developers.kakao.com/docs/en/local/dev-guide
- Kakao API 쿼터: https://developers.kakao.com/docs/en/getting-started/quota

## 5. 장소 일치 판정

후보는 음식점(`FD6`) 또는 카페(`CE7`) 분류를 우선한다. 기존 `kakaoPlaceId`가 있으면 같은 ID를 가장 강한 증거로 사용한다.

| 신호 | 점수 |
|---|---:|
| 기존 Kakao 장소 ID 일치 | 100점 즉시 일치 |
| 정규화 상호명 일치·높은 유사도 | 최대 40점 |
| 도로명 또는 지번 주소 일치 | 최대 30점 |
| 기존 좌표에서 150m 이내 | 최대 20점 |
| 전화번호 일치 | 최대 10점 |

- 70점 이상이고 음식점·카페 분류이면 `MATCHED`
- 50~69점 또는 후보가 둘 이상 비슷하면 `AMBIGUOUS`
- 결과가 없거나 모든 후보가 50점 미만이면 `NOT_FOUND`
- timeout, 429, 5xx, 인증·권한 오류는 `ERROR`이며 미검색 횟수에 포함하지 않는다.

상호명은 NFKC, 괄호·지점명·공백 정규화를 적용하되 의미가 다른 이름을 강제로 합치지 않는다.

## 6. 증거 우선순위

1. 공공데이터 `CLOSED`: 즉시 숨김. 기존 동작을 유지한다.
2. 공공데이터 `TEMPORARILY_CLOSED`: 임시 숨김 및 재검수 생성.
3. 관리자 수동 확인: 90일 보호 기간 동안 자동 숨김 금지.
4. 최근 90일 리뷰어 방문·사진: 강한 영업 증거.
5. 최근 90일 일반 사용자 평가·저장: 보조 영업 증거.
6. Kakao Local 일치: 영업 가능성 증거이지만 단독으로 폐업을 확정하지 않음.

사용자 활동은 장소 ID와 시각만 집계하며 회원별 상세 정보는 검증 증거에 저장하지 않는다.

## 7. 상태 전이와 자동 조치

### 일치

- `MATCHED`: `VERIFIED`, 연속 미검색 0, `lastVerifiedAt` 갱신
- 최근 방문 증거가 있으면 Kakao가 `AMBIGUOUS`여도 `MONITORING` 이상을 유지

### 미검색

동일 장소의 유효한 검사는 최소 7일 간격으로 누적한다.

- 1회 `NOT_FOUND`: `MONITORING`, 공개·추천 유지
- 2회 연속: `SUSPECTED`, 공개 지도 유지, 추천 후보에서 제외, 재검수 케이스 생성
- 3회 연속: 아래 조건을 모두 만족할 때만 임시 숨김
  - 첫 미검색부터 14일 이상 경과
  - 최근 90일 리뷰어 방문·사진 없음
  - 최근 90일 평가 없음
  - 연결된 공공데이터가 최근 120일 내 다시 관측되지 않았거나 상태가 `UNKNOWN`

공공데이터가 최근 120일 이내 `OPEN`으로 관측됐으면 3회 미검색이어도 `SUSPECTED`까지만 허용한다.

### 공급자 장애

- `ERROR`는 상태와 연속 횟수를 변경하지 않는다.
- 인증 오류가 연속 3회 또는 한 실행에서 오류율 50% 이상이면 실행을 중단한다.
- 공급자 장애 중에는 어떤 장소도 자동 숨김하지 않는다.

## 8. 데이터 구조

신규 파생 테이블 하나만 추가한다.

### `place_liveness_states`

- `place_id` 기본키 및 `places` 외래키
- `status`: `VERIFIED | MONITORING | SUSPECTED | HIDDEN`
- `kakao_status`: `MATCHED | AMBIGUOUS | NOT_FOUND | ERROR | SKIPPED`
- `matched_kakao_place_id`
- `match_score`
- `consecutive_not_found`
- `first_not_found_at`, `last_matched_at`, `last_checked_at`, `next_check_at`
- `recommendation_excluded`: 관찰 모드와 실제 추천 제외를 분리하는 파생 플래그
- `protected_until`: 관리자가 정상 영업으로 확인한 뒤 자동 숨김을 막는 시각
- `lease_token`, `lease_expires_at`: 중복 예약 실행을 막는 짧은 처리 임대
- `evidence_json`: 점수 구성과 비식별 집계만 저장
- `updated_at`

세부 검사 이력 전체를 새 테이블로 쌓지 않는다. 현재 상태는 재생성 가능한 파생 데이터이고, 자동 숨김·복구 같은 실제 상태 변경은 기존 `place_revisions`, `admin_audit_logs`, `place_revalidation_cases`에 기록한다.

새 migration은 기존 파일을 수정하지 않고 다음 순번으로 추가한다.

## 9. 조회 반영

- 일반 지도·장소 상세: `SUSPECTED`는 계속 표시
- 추천·홈 큐레이션·코스 추천: `SUSPECTED`, `HIDDEN` 제외
- `places.status = HIDDEN`: 모든 공개 조회에서 제외
- 상태 행이 없거나 기능이 꺼진 경우: 기존 동작을 그대로 유지

즉, 기능 실패나 롤백이 기존 공개 화면을 막지 않는다.

## 10. 예약 실행

새 cron trigger를 만들지 않고 기존 `runScheduledPlaceMaintenance` 안에서 순차 실행한다. 현재 `Promise.all`에 새 최상위 작업을 추가하지 않는다.

- 기본 비활성: `KAKAO_PLACE_VERIFICATION_ENABLED !== "true"`이면 즉시 건너뜀
- 집행 모드: `KAKAO_PLACE_VERIFICATION_MODE = OBSERVE | RECOMMEND | HIDE`
  - `OBSERVE`: 판정만 저장하고 추천·공개 상태를 변경하지 않음
  - `RECOMMEND`: 2회 미검색부터 추천 제외만 적용
  - `HIDE`: 추천 제외에 더해 3회 미검색과 보호 조건을 모두 만족할 때만 임시 숨김
- 하루 최대 25곳
- 우선순위: 공식 상태 충돌 → 열린 재검수 → 오래된 공개 장소
- 장소당 API 호출 최대 1회, 결과 최대 5개
- timeout 3초
- 429·5xx만 최대 1회 제한 재시도
- 한 실행의 최대 외부 호출 50회, 월 목표 1,500회 이하
- 동일 장소 중복 실행은 `next_check_at`과 만료 시간이 있는 처리 임대를 조건부 갱신해 방지

Kakao 공식 월 무료 쿼터는 변경될 수 있으므로 실제 앱 한도는 Kakao Developers의 `통계 > 쿼터`에서 운영자가 확인한다. 서비스 자체 호출 상한은 공급자 한도보다 훨씬 낮게 둔다.

## 11. 관리자 경험

기존 `장소 운영` 화면의 영업 재검증 섹션을 확장한다.

- 필터: 운영 의심, 임시 숨김, 공급자 오류
- 표시: 공공데이터 상태, Kakao 결과, 일치 점수 구성, 연속 미검색, 최근 내부 활동 시각
- 조치: 정상 영업, 임시 휴업, 폐업, 이전, 90일 자동 숨김 보호
- 모든 수동 조치에 근거 입력과 감사 로그 필수

UI는 기존 디자인 시스템을 유지하고 별도 UI 라이브러리를 추가하지 않는다.

## 12. 테스트

- 단위: 주소·상호·전화 정규화, 거리와 점수, 상태 전이, 보호 규칙
- 공급자 계약: mock 응답의 정상·빈 결과·모호한 결과·429·5xx·timeout·잘못된 JSON
- Workers/D1: 연속 검사, 7일 간격, 중복 실행, 추천 제외, 공식 폐업, 관리자 보호, 감사 로그
- 브라우저: 관리자 운영 의심 탭과 수동 판정 흐름
- 테스트는 실제 Kakao API와 운영 D1을 호출하지 않는다.

배포 뒤 실제 API contract smoke는 운영 담당자의 별도 승인으로 장소 1곳만 실행한다.

## 13. 보안·개인정보·비용

- REST API 키는 Worker secret으로만 사용
- 공급자 요청 URL과 헤더를 로그에 남기지 않음
- 오류 로그에 상호·주소·전화번호를 기록하지 않음
- Kakao 응답의 공개 사업장 정보만 처리
- 회원별 활동은 개수와 최신 시각만 파생
- 월 1,500회 자체 상한, 기능 kill switch, 429 즉시 중단

## 14. 롤아웃과 롤백

1. migration과 코드를 배포하되 기능 flag는 꺼둔다.
2. 관리자 수동 실행으로 mock이 아닌 1곳 contract smoke를 수행한다.
3. 첫 7일은 판정만 저장하고 추천·공개 상태를 바꾸지 않는 관찰 모드로 운영한다.
4. 오탐 검수 후 `SUSPECTED` 추천 제외를 활성화한다.
5. 자동 숨김은 별도 사람 승인 후 활성화한다.

롤백은 flag를 끄는 것으로 즉시 외부 호출과 신규 자동 조치를 중단한다. 추천 제외는 관리자 일괄 해제 동작으로 파생 플래그만 복구하고, 잘못 숨긴 장소는 기존 장소 revision으로 복구한다. 파생 상태 테이블은 남겨도 일반 지도·장소 상세는 정상 동작한다.
