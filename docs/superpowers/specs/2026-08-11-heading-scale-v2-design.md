# 제목 단계형 축소 설계

## 목적

직전 변경에서 H1만 원본의 70%로 축소하면서 화면별 제목 단계가 지나치게 작거나 H2와 가까워진 문제를 바로잡는다. Re:Taste의 강한 제목 인상은 유지하되 H1, H2, 본문이 자연스럽게 내려가는 위계를 만든다.

## 검토한 방식

1. H1과 H2를 모두 70%로 축소하면 일관성은 단순하지만 H2가 지나치게 작아진다.
2. H1과 H2 사이를 고정 비율로 강제하면 화면별 역할 차이를 잃고 기존 반응형 설계를 깨뜨릴 수 있다.
3. **선택안:** 각 화면의 원본 크기를 기준으로 H1은 75%, H2는 85%로 축소한다. 기존 화면별 비율과 반응형 동작을 보존하면서 제목 단계를 완만하게 정돈할 수 있다.

## 적용 규칙

- H1: H1 30% 축소 이전 원본 크기의 75%
- H2: 현재 원본 크기의 85%
- H3 이하와 본문: 변경하지 않음
- 굵기, 행간, 자간, 여백, 정렬: 변경하지 않음
- CSS `clamp()`의 최소값, 유동값, 최대값을 각각 같은 비율로 계산한다.
- 픽셀과 rem 값은 소수 첫째 또는 둘째 자리까지 명시해 브라우저 계산이 일관되게 유지되도록 한다.
- 데스크톱과 모바일 breakpoint에 동일 기준을 적용한다.
- CSS뿐 아니라 Tailwind 클래스와 이메일 인라인 제목 크기도 같은 기준으로 조정한다.

## 구현 범위

- 전역·화면별 H1/H2 CSS 선언
- 온보딩 디자인 시스템의 H1/H2 선언
- 인증, 리뷰어, 어드민 route의 직접 지정 H1/H2 클래스
- 이메일 템플릿의 H1 인라인 크기
- 제목 크기 계약 테스트
- 데스크톱 1440px, 모바일 390px 화면 증거

## 검증

- 계약 테스트를 먼저 실패시켜 기존 값과 목표 값 차이를 확인한다.
- 전체 단위 테스트, 타입 검사, 프로덕션 빌드를 실행한다.
- 데스크톱과 모바일에서 H1이 H2보다 크고 H2가 본문보다 큰지 실제 화면으로 확인한다.

## 운영 영향과 위험

- 데이터베이스, API, 인증, 추천 알고리즘에는 영향이 없다.
- 긴 제목의 줄바꿈 위치가 달라질 수 있으므로 대표 화면을 시각 검수한다.
- 기존 CSS에 중복 selector가 있으므로 최종 적용값을 계약 테스트로 고정한다.
