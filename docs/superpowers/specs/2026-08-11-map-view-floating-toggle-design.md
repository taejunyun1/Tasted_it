# 지도 보기 전환 플로팅 버튼 설계

## 목적

추천 지도와 전체 지도 사이의 전환 위치와 표현을 대칭적으로 통일한다. 사용자는 어느 지도에 있더라도 지도 중앙 상단의 같은 위치에서 다른 보기로 전환할 수 있어야 한다.

## 확정안

- 추천 지도에서는 지도 중앙 상단에 `전체 지도` 버튼을 표시한다.
- 전체 지도에서는 같은 위치와 스타일로 `추천 지도` 버튼을 표시한다.
- 추천 패널과 모바일 추천 시트 내부의 기존 `전체 지도` 버튼은 제거한다.
- 지도 위에는 보기 전환 버튼을 한 개만 표시한다.
- 기존 `home-curation-return` 플로팅 스타일을 공통 전환 스타일로 사용한다.

## 컴포넌트와 동작

- `home.tsx`가 현재 `view` 값에 따라 버튼 문구와 클릭 동작을 결정한다.
- 추천 지도의 `전체 지도` 클릭은 기존 `browseAll` 동작을 호출한다.
- 전체 지도의 `추천 지도` 클릭은 기존 `returnToCuration` 동작을 호출한다.
- 기존 URL 상태 보존 규칙은 변경하지 않는다. 추천 모드와 검색·지도 상태는 현재 전환 함수의 계약을 그대로 따른다.
- 지도 재추천 버튼이 필요한 경우 보기 전환 버튼과 겹치지 않도록 기존 위치 규칙을 유지한다.

## 반응형 디자인

- 데스크톱과 모바일 모두 지도 중앙 상단에 배치한다.
- 버튼의 테두리, 배경, 글자 굵기, 라운드 값, 그림자는 `추천 지도` 버튼의 현재 표현을 기준으로 동일하게 맞춘다.
- 모바일에서는 지도 조작과 추천 시트 핸들을 가리지 않는 기존 상단 여백을 유지한다.

## 접근성

- 네이티브 `button` 요소를 유지한다.
- 현재 화면에서 이동할 대상이 버튼의 접근 가능한 이름이 된다: `전체 지도` 또는 `추천 지도`.
- 키보드 포커스와 클릭 동작은 기존 전환 함수에 연결한다.

## 오류와 데이터 영향

- 전환 버튼은 클라이언트 URL 상태만 바꾸므로 별도의 오류 상태를 추가하지 않는다.
- 추천 알고리즘, 장소 데이터, D1 스키마, 환경 변수에는 변경이 없다.

## 검증

- 컴포넌트 계약 테스트로 패널·시트에서 `전체 지도` 버튼이 제거됐는지 확인한다.
- 라우트 계약 테스트로 추천·전체 보기 모두 공통 플로팅 버튼을 렌더링하는지 확인한다.
- 디자인 계약 테스트로 공통 버튼 스타일과 모바일 규칙을 확인한다.
- Playwright로 데스크톱과 모바일에서 `전체 지도 → 추천 지도 → 전체 지도` 양방향 전환을 검증한다.
