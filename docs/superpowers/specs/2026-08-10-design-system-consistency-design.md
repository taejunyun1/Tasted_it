# Re:Taste 디자인 시스템 정합성 설계

## 1. 목적

Re:Taste의 사용자 화면과 어드민 화면에서 컨테이너 폭, 페이지 시작 위치, 섹션 간격, 카드 내부 여백, 버튼과 배지 크기가 화면마다 달라지는 문제를 해결한다.

이번 작업은 현재의 크림색 배경, 딥그린 타이포그래피, 라임 강조색, 굵은 제목과 모노스페이스 보조 문구라는 시각적 정체성을 유지하면서 공간 규칙을 하나의 시스템으로 정리하는 작업이다. 기능, 데이터, 추천 알고리즘은 변경하지 않는다.

## 2. 현재 문제

스크린샷과 현재 CSS를 기준으로 다음 문제가 확인된다.

- `/courses`, `/places`, `/me`의 헤더 아래 첫 콘텐츠 시작 위치가 서로 다르다.
- 같은 위계의 대형 제목임에도 위·아래 간격과 구분선 위치가 다르다.
- 페이지별로 `30px`, `34px`, `36px`, `38px`, `42px`, `46px`, `52px`, `58px`, `62px`, `66px`, `82px`, `96px` 같은 개별 수치가 누적되어 리듬이 흔들린다.
- 카드 모서리와 내부 여백이 콘텐츠의 중요도보다 작성 시점에 따라 달라진다.
- 사용자 화면의 넉넉한 공간과 어드민 화면의 높은 정보 밀도를 구분하는 공통 원칙이 없다.
- 디자인 규칙이 코드와 문서에 함께 남지 않아 새 화면을 만들 때 기존 화면을 눈대중으로 복제하게 된다.

## 3. 디자인 방향

### 3.1 유지할 정체성

- 배경: 따뜻한 미색 계열
- 주요 글자: 검정에 가까운 딥그린
- 강조: 제한적으로 사용하는 라임
- 보조 영역: 옅은 그린·회색 미스트
- 제목: SUIT/Pretendard 계열의 굵고 응축된 한글
- 라벨과 데이터: IBM Plex Mono
- 구조 표현: 얇은 구분선, 큰 제목, 목적이 있는 둥근 카드

### 3.2 공간 원칙

모든 간격은 4px 기반의 제한된 토큰에서 선택한다. 인접 요소는 작은 토큰, 서로 다른 정보 덩어리는 큰 토큰을 사용한다. 페이지별 임의 수치 추가를 금지하지는 않지만, 예외는 디자인 가이드에 이유를 기록해야 한다.

## 4. 디자인 토큰

### 4.1 컨테이너

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `--layout-max` | `1280px` | 사용자·어드민 공통 최대 콘텐츠 폭 |
| `--layout-gutter` | `20px` | 데스크톱 좌우 안전 여백 |
| `--layout-gutter-mobile` | `14px` | 모바일 좌우 안전 여백 |
| `--layout-header-height` | `78px` | 데스크톱 공통 헤더 높이 |
| `--layout-header-height-mobile` | `64px` | 모바일 공통 헤더 높이 |

### 4.2 간격

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `--space-1` | `4px` | 아이콘과 짧은 라벨 사이 |
| `--space-2` | `8px` | 밀접한 텍스트와 상태 |
| `--space-3` | `12px` | 작은 컨트롤 내부·사이 |
| `--space-4` | `16px` | 기본 요소 간격 |
| `--space-6` | `24px` | 카드 내부 그룹 |
| `--space-8` | `32px` | 데스크톱 카드 내부 여백 |
| `--space-12` | `48px` | 페이지 내 중간 구획 |
| `--space-14` | `56px` | 모바일 대형 섹션 사이 |
| `--space-16` | `64px` | 페이지 시작·보조 섹션 |
| `--space-20` | `80px` | 데스크톱 대형 섹션 사이 |
| `--space-24` | `96px` | 의도적으로 크게 분리하는 장면 전환 |

### 4.3 모서리

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `--radius-control` | `12px` | 입력, 작은 선택 컨트롤 |
| `--radius-card` | `20px` | 일반 카드 |
| `--radius-feature` | `28px` | 핵심 추천·설정 카드 |
| `--radius-pill` | `999px` | 배지와 단일 행동 버튼 |

### 4.4 선과 그림자

- 기본 구분선: `1px solid` 미스트 그린
- 강한 구분선: `1px solid` 딥그린
- 강조 카드 그림자: 우측·하단으로 `6~8px`, 불투명도 10~12%
- 일반 카드에는 그림자를 사용하지 않는다.
- 그림자는 계층을 나타낼 때만 사용하며 장식용으로 반복하지 않는다.

## 5. 공통 레이아웃 규칙

### 5.1 페이지 시작

- 사용자 화면: 헤더 다음 콘텐츠는 데스크톱 `64px`, 모바일 `32px`에서 시작한다.
- 어드민 화면: 헤더 다음 콘텐츠는 데스크톱 `48px`, 모바일 `28px`에서 시작한다.
- 히어로 내부의 eyebrow, 제목, 설명 순서는 각각 `12px`, `24px` 간격을 기본으로 한다.
- 히어로와 다음 주요 영역 사이에는 구분선을 두고 `48px` 간격을 적용한다.

### 5.2 섹션

- 사용자 화면의 서로 다른 주요 섹션은 데스크톱 `80px`, 모바일 `56px`로 분리한다.
- 같은 섹션 안의 제목과 콘텐츠는 `24~32px`로 분리한다.
- 어드민의 주요 섹션은 `48px`, 같은 작업 그룹은 `24px`를 사용한다.
- 섹션 제목 구분선의 아래 여백은 모든 화면에서 동일한 위계 토큰을 사용한다.

### 5.3 카드

- 일반 사용자 카드: 데스크톱 `32px`, 모바일 `20px` 내부 여백
- 정보 밀도가 높은 사용자 카드: 데스크톱 `24px`, 모바일 `18px`
- 어드민 패널: 데스크톱 `24px`, 모바일 `16px`
- 카드 안에서 제목, 설명, 행동 영역을 각각 독립 그룹으로 묶고 그룹 사이는 `24px`를 사용한다.
- 카드 높이를 맞추기 위해 빈 공간을 임의로 늘리지 않는다. 동일 그리드에서 필요한 경우에만 `min-height`를 사용한다.

### 5.4 버튼과 배지

- 기본 버튼 높이: `44px`
- 작은 어드민 버튼 높이: `36px`
- 모바일 주요 버튼은 최소 `44px` 터치 영역을 보장한다.
- 배지 내부 여백은 기본 `8px 12px`, 강조 배지는 `10px 16px`를 사용한다.
- 같은 행의 버튼과 배지는 시각적 높이를 맞춘다.
- 라임은 선택 상태나 가장 중요한 한 가지 행동에만 사용한다.

## 6. 화면별 적용

### 6.1 코스 추천 `/courses`

- 히어로, 자동 문맥 카드, 조건 요약 카드가 동일한 기준선과 컨테이너에 맞는다.
- 히어로 아래 구분선부터 조건 요약까지 `32px`, 조건 요약부터 본문 그리드까지 `32px`를 사용한다.
- 좌측 조건 카드와 우측 결과 카드의 상단선, 모서리, 내부 여백을 맞춘다.
- 모바일 바텀시트 내부도 동일한 컨트롤·배지 토큰을 사용한다.

### 6.2 맛집 발견 `/places`

- 히어로, 추천 방향 카드, 추천 제목, 각 추천 레일의 세로 간격을 공통 섹션 토큰으로 재배치한다.
- 추천 방향 카드의 제목·설명·배지 영역을 `24px` 단위로 묶는다.
- 추천 카드의 이미지와 본문 간격은 유지하되 카드 외부 그리드 간격을 통일한다.
- 각 추천 방식의 개성은 배경과 카드 배치로 표현하고, 외부 여백 체계는 공유한다.

### 6.3 나의 취향 `/me`

- 프로필 사람 정보와 대표 취향 영역을 하나의 히어로 리듬으로 묶는다.
- 학습 상태, 설명, 통계, 행동 버튼이 동일한 콘텐츠 폭 안에서 정렬되도록 한다.
- `Taste Log`와 저장·평가 카드의 시작 위치를 다른 주요 섹션과 동일한 `80px` 리듬에 맞춘다.
- 빈 상태 카드의 콘텐츠는 세로 중앙 정렬하되 카드 내부 기본 여백을 유지한다.

### 6.4 공통 헤더·푸터

- 로고, 내비게이션, 메뉴 버튼의 좌우 정렬선을 `--layout-max` 컨테이너와 일치시킨다.
- 활성 내비게이션은 기존 테두리 표현을 유지하되 높이와 내부 여백을 고정한다.
- 푸터는 사용자 화면과 어드민에서 동일한 좌우 기준선을 사용한다.

### 6.5 어드민

- 사용자 화면과 색상·타이포·공간 토큰은 공유한다.
- 큰 마케팅형 히어로 대신 작업 제목과 상태 요약을 사용한다.
- 페이지 시작 `48px`, 섹션 간격 `48px`, 패널 내부 `24px`를 기본으로 한다.
- 필터, 테이블, 일괄 작업 바의 높이와 간격을 통일한다.
- 테이블 행은 데스크톱 최소 `52px`, 모바일 카드형 행은 내부 `16px`를 보장한다.
- 경고, 성공, 제외 상태는 의미색을 유지하되 패딩과 모서리는 공통 상태 컴포넌트 규칙을 따른다.

## 7. 구현 구조

### 7.1 CSS 토큰

전역 `:root`에 레이아웃, 간격, 모서리 토큰을 추가한다. 기존 `--s*` 변수는 새 토큰을 가리키는 호환 별칭으로 유지하여 한 번에 모든 화면을 재작성하지 않는다.

### 7.2 공통 클래스

다음 역할의 공통 클래스를 제공한다.

- 페이지 셸: 사용자형과 어드민형
- 히어로와 섹션 스택
- 일반 카드와 강조 카드
- 버튼 크기와 pill 형태
- 상태 배지

이미 의미가 명확한 컴포넌트를 억지로 하나로 합치지 않는다. 이번 범위에서는 CSS 토큰과 레이아웃 클래스가 우선이며, React 컴포넌트 공통화는 동일한 마크업이 세 곳 이상 반복되고 회귀 위험이 낮을 때만 수행한다.

### 7.3 디자인 가이드

`docs/design-system/retaste-design-guide.md`에 다음 내용을 남긴다.

- 브랜드 원칙과 색상
- 글꼴과 제목 위계
- 공간·컨테이너·반응형 규칙
- 카드, 버튼, 입력, 배지, 상태 표현
- 사용자 화면과 어드민 화면의 차이
- 새 화면 제작 체크리스트
- 권장 예시와 금지 예시

문서의 토큰명과 실제 CSS 변수명은 일치해야 한다.

## 8. 반응형 기준

- `1280px` 이상: 최대 폭 고정, 넉넉한 섹션 리듬
- `980px` 이하: 4열을 2열로, 보조 설명을 다음 행으로 이동
- `760px` 이하: 공통 모바일 거터와 헤더 적용, 어드민 표를 카드형으로 전환
- `620px` 이하: 추천 레일과 강조 카드 단일 열 전환
- `520px` 이하: 프로필, 계정, 통계 영역을 세로 스택으로 전환

브레이크포인트는 현재 화면과의 호환을 위해 유지하되, 각 구간의 거터와 섹션 토큰은 공통으로 사용한다.

## 9. 접근성

- 클릭 가능한 요소는 모바일에서 최소 `44px` 터치 영역을 확보한다.
- 키보드 포커스 표시를 유지한다.
- 색상만으로 선택·오류·성공 상태를 구분하지 않는다.
- `prefers-reduced-motion`에서 이동 효과를 제거한다.
- 큰 제목은 시각적 크기와 무관하게 문서의 올바른 heading 순서를 유지한다.

## 10. 검증

### 10.1 자동 검증

- CSS 토큰과 핵심 클래스 계약 테스트
- 기존 단위·통합 테스트
- 타입 검사
- 프로덕션 빌드

### 10.2 시각 검증

다음 화면을 데스크톱과 모바일에서 캡처한다.

- `/courses`
- `/places`
- `/me`
- 대표 어드민 목록 화면
- 대표 어드민 상세·작업 화면

확인 항목은 좌우 기준선, 페이지 시작 위치, 섹션 리듬, 카드 패딩, 버튼 높이, 모바일 터치 영역이다.

## 11. 완료 조건

- 사용자 핵심 화면과 어드민 화면이 동일한 공간 토큰을 사용한다.
- 스크린샷에서 콘텐츠 좌우 기준선과 주요 섹션 간격이 일관된다.
- 기능과 데이터 동작은 기존과 동일하다.
- 디자인 가이드의 토큰과 실제 CSS가 일치한다.
- 새 화면 제작자가 별도 질문 없이 컨테이너, 여백, 카드, 버튼 기준을 선택할 수 있다.

## 12. 제외 범위

- 추천·분류·주차 알고리즘 변경
- DB 스키마와 운영 데이터 변경
- 인증 흐름 변경
- 브랜드 로고 교체
- 전면적인 React 컴포넌트 재설계
- 새로운 애니메이션 시스템 도입
