# 베이커리 카테고리 분류 확장 설계

## 목표

기존 `카페·디저트 > 베이커리` 카테고리를 유지하면서 제과·제빵 관련 상호명과 공공데이터 업태를 안정적으로 `bakery-detail`로 분류한다.

## 분류 규칙

- 강한 상호명 신호: `제과점`, `제빵소`, `제빵`, `빵집`, `베이커리`, `제과제빵`.
- 상품 기반 상호명 신호: `식빵`, `케이크`, `도넛`, `도너츠`, `크루아상`, `쿠키`, `과자점`.
- 공공데이터 업태 신호: `제과점영업`, `제과`, `제빵`, `베이커리`, `과자점`.
- 공공데이터 출처가 `BAKERY`이면 기존처럼 `bakery-detail`을 기본값으로 사용한다.
- 상호명에 베이커리 신호와 `카페` 또는 `디저트`가 함께 있으면 구체 음식 신호인 베이커리를 우선한다.
- 단독 일반어 `빵`과 `과자`는 상호명 일부에서 오탐 가능성이 높으므로 규칙에 포함하지 않는다.
- `케이크`는 베이커리 신호로 변경한다. `디저트`만 있는 상호는 기존 `dessert`를 유지한다.

## 데이터와 UI

새 카테고리 행이나 마이그레이션은 추가하지 않는다. 현재 활성 카테고리 `bakery-detail`과 관리자 선택 목록, 지도·목록 필터를 그대로 사용하므로 분류 결과가 즉시 기존 UI에 노출된다.

## 신뢰도

- 상호명 베이커리 신호만 있으면 `MEDIUM`.
- 상호명 신호가 제과점 업태 또는 BAKERY 출처와 함께 확인되면 `HIGH`.
- 다른 구체 음식 신호가 동시에 있으면 기존 충돌 판정을 유지한다.

## 검증

- 각 신규 별칭이 `bakery-detail`로 분류되는 단위 테스트를 추가한다.
- `카페`, `디저트`와 함께 등장할 때 베이커리가 우선되는지 검증한다.
- 일반어 `빵`, `과자` 단독은 베이커리로 강제되지 않는지 검증한다.
- 기존 치킨·국밥·다른 음식 분류 회귀 테스트와 전체 타입 검사·통합 테스트·빌드를 실행한다.
