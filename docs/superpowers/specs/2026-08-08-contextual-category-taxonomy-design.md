# 문맥형 음식 카테고리 분류 사전 설계

## 1. 목표

광주·전남 공공데이터 후보의 상호명과 원천 업태를 함께 읽어 대표 음식 카테고리를 안정적으로 추천한다. 단순 키워드 추가 방식에서 벗어나 명확한 단어, 문맥 조합, 제외 표현, 우선순위를 분리하고, 규칙이 애매할 때만 Workers AI를 보조로 사용한다.

관리자 화면에서는 유효한 추천 카테고리가 있으면 드롭다운에 자동 선택하고, 체인점은 음식 분류보다 먼저 감지해 `체인점 제외` 탭으로 보낸다.

## 2. 적용 범위

- 전체 활성 음식 카테고리의 상호명·업태 키워드 사전 재정비
- 체인점 판정의 최우선 적용과 기존 검수 대기 데이터 재분류
- AI 근거 검증의 부분 유효 근거 허용
- 추천 카테고리와 관리자 선택값 연결 검증
- 운영 후보 전체 분류 감사

공개 카테고리 구조를 대규모로 새로 만들거나, 외부 상호 데이터베이스를 도입하거나, AI만으로 자동 공개하는 기능은 이번 범위에 포함하지 않는다.

## 3. 분류 순서

분류 파이프라인은 다음 순서를 지킨다.

1. 상호명을 정규화한다.
2. 체인점 사전을 먼저 검사한다.
3. 체인점이면 일반 검수 대상에서 제외하고 `체인점 제외` 탭으로 이동한다.
4. 비체인점이면 상호명의 구체 음식 신호를 수집한다.
5. 원천 업태와 공공데이터 종류로 신호를 보강한다.
6. 문맥 제외 규칙과 카테고리 우선순위를 적용한다.
7. 하나의 활성 최종 카테고리가 결정되면 관리자 선택값으로 자동 설정한다.
8. 규칙이 없거나 충돌하면 Workers AI로 제한된 후보 카테고리만 확인한다.
9. 규칙·AI 결과가 안전 기준을 통과하지 못하면 수동 확인으로 남긴다.

체인점 판정은 모든 음식 분류보다 우선한다. 관리자가 복원한 `OVERRIDDEN` 항목은 재수집이나 기존 데이터 재검사에서 다시 제외하지 않는다.

## 4. 문맥형 키워드 사전

### 4.1 규칙 구조

각 규칙은 다음 정보를 가진 독립 항목으로 관리한다.

- 대표 카테고리 slug
- 포함 키워드 또는 복합 표현
- 신호 종류: 구체 음식, 음식 문화권, 영업 형태, 원천 기본값
- 적용 위치: 상호명, 원천 업태
- 우선순위 가중치
- 선택적 제외 표현
- 관리자에게 표시할 한국어 근거

여러 카테고리의 신호가 잡히면 구체 메뉴를 넓은 업태보다 우선한다. 같은 점수의 구체 메뉴가 충돌하면 임의 확정하지 않고 `CONFLICT`로 남긴다.

### 4.2 주요 범위

- 한식: 국밥·해장국·설렁탕·곰탕, 찌개·전골·감자탕·육개장, 삼겹살·갈비·정육·구이, 족발·보쌈, 한정식
- 해산물: 회·사시미, 연어·장어, 대게·꽃게·홍게·크랩·랍스터, 전복·굴·꼬막·조개·가리비, 낙지·주꾸미·문어·오징어·아귀, 고등어·갈치·복어·물회·해물
- 일식: 스시·초밥, 라멘·멘야, 우동·소바, 돈가스·돈까스, 타코야끼, 이자카야
- 중식: 짜장·짬뽕, 마라·훠궈, 양꼬치와 명확한 중식 업태
- 양식: 파스타, 스테이크, 피자, 햄버거·버거, 브런치
- 분식: 떡볶이, 김밥, 순대, 튀김, 만두
- 치킨: 치킨, 통닭, 닭강정과 `호프/통닭` 같은 복합 업태
- 세계음식: 쌀국수·베트남, 태국·타이, 인도·인디아·커리, 멕시칸·타코
- 카페·베이커리·디저트: 카페·커피·다방, 베이킹·베이커리·제과·제빵·과자·과자점·꽈배기·브레드·브래드·빵집·바게트·식빵·케이크·도넛·크루아상·쿠키, 아이스크림·빙수, 디저트
- 주점: 라이브카페·라이브바·음악주점, 포차·소주, 호프·펍·맥주, 와인, 칵테일
- 건강식: 샐러드, 비건, 채식

사용자가 요청한 `과자`는 베이커리 신호로 사용한다. 과일 이름은 단독 음식점 신호로 사용하지 않는다. `회`, `탕`, `구이`, `커리`, `타코`처럼 다른 단어 일부가 될 수 있는 표현은 정규화 후 명시적 예외 또는 주변 문맥을 적용한다.

## 5. AI 보조 분류

규칙이 활성 최종 카테고리를 확정하지 못하거나 구체 음식 신호가 충돌할 때만 AI를 사용한다. AI에는 전체 카테고리가 아니라 규칙이 만든 후보 목록을 제공한다.

AI가 반환한 근거 중 정규화한 상호명 또는 업태 원문에 실제 포함된 표현이 하나 이상 있으면 결과를 검증할 수 있다. 원문과 일치하지 않는 근거는 저장 대상에서 제거한다. 모든 근거가 원문과 불일치하거나 카테고리가 허용 후보 밖이면 계속 실패 처리한다.

이 정책은 `다시마 꽈배기`에서 `꽈배기`처럼 실제 근거는 인정하면서, AI가 덧붙인 `베이커리` 같은 원문 밖 표현 때문에 전체 결과가 실패하지 않도록 한다.

## 6. 체인점 기존 데이터 재분류

신규 수집 데이터는 현재의 수집 시점 체인점 판정을 유지한다. 이미 `PENDING` 상태로 저장된 체인점은 새 순번의 마이그레이션 또는 명시적 재조정 작업으로 `business_license_exclusions`에 등록한다.

- 대상은 `OPEN`이면서 `PENDING`인 명시적 체인점만 포함한다.
- 기존 `OVERRIDDEN` 기록은 변경하지 않는다.
- `뚜레쥬르 여수무선점`처럼 지역명과 지점명이 뒤에 붙어도 체인 본문을 인식한다.
- 체인명 표기 변형은 명시적 사전과 회귀 테스트로만 확장한다.

## 7. 관리자 화면 동작

추천 결과가 활성 최종 카테고리와 연결되면 `chosenCategories[candidateId]` 초기값에 해당 ID를 넣는다. 따라서 수동 확인 상태라도 추천값이 있으면 드롭다운에 자동 선택되어야 한다.

추천 slug가 존재하지만 카테고리 ID를 찾지 못한 경우, `추천 · 분류 없음`으로 조용히 숨기지 않고 분류 감사에서 오류로 집계한다. 체인점은 일반 검수 행에 표시하지 않고 제외 탭에서 체인명과 일치 규칙을 보여준다.

## 8. 오류 처리와 안전 기준

- AI 호출 실패는 규칙 결과와 수동 선택을 지우지 않는다.
- AI 결과는 자동 공개가 아니라 대표 카테고리 추천에만 사용한다.
- 주소·좌표 누락, 중복, 규칙 충돌은 기존 승인 차단 정책을 유지한다.
- 넓어진 키워드 때문에 서로 다른 구체 메뉴가 잡히면 높은 신뢰도로 강제하지 않는다.
- 실제 운영 데이터를 감사할 때 상호명 전체 목록이나 개인정보를 문서에 남기지 않는다.

## 9. 테스트와 감사

테스트 우선 방식으로 다음 사례를 고정한다.

- 각 카테고리의 대표 상호명 표 기반 테스트
- 베이킹·베이커리·과자·제과·제빵·꽈배기 베이커리 자동 선택
- 과일 단독 표현과 알려진 부분 문자열 오탐 방지
- 구체 음식과 넓은 업태가 함께 있을 때 구체 음식 우선
- 유효 AI 근거 일부와 무효 근거가 섞인 응답의 성공
- 모든 AI 근거가 무효인 응답의 실패
- 기존 `PENDING` 체인점 제외 등록과 `OVERRIDDEN` 보존
- 추천 category ID가 관리자 선택 초기값으로 연결됨

운영 후보 감사에서는 전체 건수, 카테고리별 건수, `LOW`, `CONFLICT`, 분류 slug와 활성 카테고리 불일치, 체인점 잔존 건수를 확인한다. 대표 오분류만 익명화해 검토하고 규칙에 반영한다.

## 10. 완료 기준

- 명확한 음식 상호의 추천 카테고리가 자동 선택된다.
- `다시마 꽈배기`와 같은 정상 AI 보조 분류가 근거 일부 불일치 때문에 실패하지 않는다.
- `뚜레쥬르 여수무선점` 같은 기존 체인점이 제외 탭에 나타난다.
- 전체 단위·통합·브라우저 테스트와 타입 검사, 프로덕션 빌드가 통과한다.
- 운영 후보 감사 결과에 설명되지 않은 대규모 분류 이동이 없다.
