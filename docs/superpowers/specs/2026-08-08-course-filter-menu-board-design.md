# 코스 추천 필터 메뉴 보드형 디자인

## 1. 목적

코스 추천 화면의 드롭다운 필터를 키워드 배지 선택 방식으로 바꾼다. 사용자는 열고 닫는 과정 없이 전체 선택지를 한눈에 보고, 먹고 싶은 한 끼 메뉴를 최대 2개까지 고를 수 있어야 한다.

이번 변경은 A형 `메뉴 보드형`만 대상으로 한다. 기존 코스·주차 추천 알고리즘과 결과 카드의 정보 구조는 유지하고, 필터의 선택 경험과 화면 완성도를 개선한다.

## 2. 디자인 방향

### 2.1 데스크톱

- 왼쪽에는 메뉴 보드형 필터를 고정하고, 오른쪽에는 코스 결과를 배치한다.
- 필터 보드는 한 번에 전체 조건을 확인할 수 있는 독립 카드로 구성한다.
- 각 조건은 드롭다운이 아닌 둥근 키워드 배지로 표시한다.
- 한 끼 메뉴는 줄바꿈되는 배지 목록으로 전체 노출한다.
- 결과 카드의 이동 순서, 핵심 가치 배지, 주차 비교 영역은 현재 구조를 유지한다.

```text
┌────────────────────────────────────────────────────────────┐
│ 오늘의 두 곳, 주차까지 이어봤어요.      자동 상황 정보     │
├───────────────────┬────────────────────────────────────────┤
│ 선택 조건          │ COURSE 01                              │
│ [자동] [점심] ...  │ 핵심 가치 배지 · 코스 점수             │
│                    │                                        │
│ 한 끼 전체 메뉴    │ 01 한 끼                               │
│ [라멘] [돈가스]    │          예상 이동거리                  │
│ [한식] [국밥] ...  │ 02 카페·디저트                         │
│                    │                                        │
│ 반경·주차·추가조건 │ 한 곳 주차 / 장소별 주차 비교          │
└───────────────────┴────────────────────────────────────────┘
```

### 2.2 모바일

- 첫 진입에서 메뉴 보드가 바텀시트로 자동 열린다.
- 결과 진입 후에는 `조건 변경` 버튼으로 같은 바텀시트를 다시 연다.
- 모든 배지는 가로 스크롤 없이 여러 줄로 배치한다.
- 바텀시트 하단의 `이 조건으로 코스 만들기` 버튼은 화면 하단에 안정적으로 노출한다.

## 3. 필터 선택 규칙

### 3.1 한 끼 메뉴

- 활성화된 한 끼 하위 카테고리를 모두 표시한다.
- 각 배지에는 이모지, 메뉴명, 등록 장소 수를 표시한다.
- 최대 2개까지 동시에 선택할 수 있다.
- 두 개를 선택하면 두 카테고리 중 하나에 해당하는 맛집을 모두 추천 후보에 포함한다.
- 아무 메뉴도 선택하지 않은 상태는 `전체 한 끼`와 동일하게 처리한다.
- 두 개가 선택된 상태에서 세 번째 메뉴를 누르면 선택을 변경하지 않고 `최대 2개까지 선택할 수 있어요` 안내를 보여준다.
- 선택된 메뉴 배지는 연두색 강조 배경과 진한 글자로 표시한다.

### 3.2 단일 선택 조건

다음 조건은 그룹마다 하나만 선택한다.

- 시간대: 자동, 점심, 오후, 저녁, 늦은 시간
- 두 번째 장소: 카페, 디저트·베이커리
- 검색 반경: 1km, 3km, 5km, 8km
- 주차 방식: 자동 추천, 한 곳 주차, 장소별 주차
- 전기차 조건: 상관없음, 있으면 우선, 설치 확인 필수

선택된 단일 조건은 진한 녹색 배경과 흰색 글자로 표시한다. 같은 배지를 다시 눌러도 필수 단일 선택은 해제하지 않는다.

### 3.3 켜기·끄기 조건

다음 조건은 독립적으로 켜고 끌 수 있다.

- 비 오는 날
- 아이 동반

선택 상태는 `aria-pressed`와 시각적 강조를 함께 제공한다.

## 4. 상태와 URL

- 필터는 React Router의 GET Form 방식을 유지한다.
- 메뉴 카테고리는 반복 파라미터를 사용한다.

```text
mealCategory=ramen-detail&mealCategory=western-detail
```

- 기존 단일 `mealCategory` URL도 그대로 해석해 하위 호환성을 유지한다.
- URL에는 최대 2개의 유효한 메뉴 카테고리만 직렬화한다.
- 잘못된 값, 중복 값, 세 번째 이후 값은 서버에서 제거한다.
- 필터 적용 후 새로고침하거나 URL을 공유해도 동일한 선택 상태와 추천 결과가 복원되어야 한다.

## 5. 컴포넌트 구성

### `ChoiceChipGroup`

- 단일 선택 조건을 렌더링한다.
- 라디오 입력과 라벨을 사용해 키보드 및 보조기기 선택을 지원한다.

### `MealCategoryChipGroup`

- 전체 한 끼 메뉴를 렌더링한다.
- 체크박스 입력을 사용한다.
- 최대 2개 선택과 제한 안내를 담당한다.

### `ToggleChipGroup`

- 비 오는 날과 아이 동반 조건을 독립 토글로 렌더링한다.

### `Conditions`

- 세 배지 그룹을 조합한다.
- 위치 사용과 코스 생성 버튼을 유지한다.
- 데스크톱에서는 고정 메뉴 보드, 모바일에서는 바텀시트 내부 콘텐츠로 사용한다.

## 6. 시각 체계

- 배경: 따뜻한 미색
- 기본 글자와 선택 배지: 짙은 녹색
- 한 끼 메뉴 선택: 연두색
- 코스 점수와 제한 안내: 주황색
- 카드와 비선택 배지: 흰색 또는 옅은 회색
- 배지는 충분한 둥근값을 적용하되 결과 카드보다 작고 가볍게 표현한다.
- 폰트는 SUIT 또는 Pretendard 계열을 우선 적용한다.
- 기존 화면보다 구분선 사용을 줄이고 배지·간격·면 색으로 정보 위계를 만든다.

## 7. 오류 및 빈 상태

- 활성화된 한 끼 카테고리가 없으면 `선택 가능한 한 끼 메뉴가 아직 없어요`를 표시한다.
- 최대 선택 수 초과는 폼 제출 오류가 아니라 즉시 안내로 처리한다.
- 서버는 클라이언트 검증을 신뢰하지 않고 최대 2개 제한을 다시 적용한다.
- 선택한 두 카테고리에서 코스가 없으면 검색 반경을 넓히거나 메뉴 선택을 줄이도록 안내한다.

## 8. 테스트 기준

### 단위 테스트

- 단일 및 복수 `mealCategory` 파라미터 해석
- 중복 제거와 최대 2개 제한
- 기존 단일 카테고리 URL 하위 호환
- 두 선택 카테고리 중 하나에 속하는 한 끼 후보 포함

### 화면 정책 테스트

- `Conditions`에서 `select` 요소 제거
- 전체 메뉴 배지 렌더링
- 라디오·체크박스 기반 선택
- 최대 2개 제한 안내 문구
- 모바일 첫 진입 바텀시트 자동 열림 유지

### 브라우저 검증

- 데스크톱에서 모든 필터가 메뉴 보드 안에 표시됨
- 모바일 390px에서 가로 넘침 없음
- 세 번째 한 끼 메뉴 선택이 차단됨
- 필터 적용, 새로고침, 공유 URL에서 상태 유지
- 키보드 탭 이동과 선택 가능

## 9. 완료 조건

- 모든 드롭다운이 키워드 배지 선택 방식으로 교체된다.
- 한 끼 전체 메뉴가 항상 노출된다.
- 한 끼 메뉴를 최대 2개까지 선택할 수 있다.
- 선택한 두 메뉴가 추천 후보에 함께 반영된다.
- 기존 코스·주차 추천 기능과 모바일 바텀시트가 정상 동작한다.
- 데스크톱과 모바일에서 A형 메뉴 보드 디자인이 일관되게 표현된다.
