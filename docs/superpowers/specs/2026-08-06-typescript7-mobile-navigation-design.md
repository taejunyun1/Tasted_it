# TypeScript 7 및 모바일 탐색 UX 설계

## 목표

- TypeScript를 안정 버전 `7.0.2`로 전환하고 현재 React Router·Vite·Cloudflare Workers 도구 체인과의 호환성을 검증한다.
- 상단 내비게이션의 고정 항목을 `맛집 리스트`, `내 상태`로 제한하고 나머지 기능은 햄버거 메뉴에 모은다.
- 모바일에서 장소 빠른 정보 바텀시트가 열리면 뒤쪽 검색·목록 패널을 자동으로 접어 지도 탐색을 방해하지 않게 한다.

## 상단 내비게이션

- 브랜드 오른쪽 고정 링크는 `맛집 리스트`, `내 상태` 두 개다.
- `내 상태`는 `/me`로 연결한다. 비로그인 사용자는 기존 보호 라우트 정책에 따라 로그인 화면을 거친다.
- 햄버거 메뉴는 접근 가능한 `details/summary` 구조를 사용한다.
- 로그인 사용자의 메뉴에는 장소 제안, 역할별 리뷰어·어드민 기능, 로그인된 이름, 로그아웃을 배치한다.
- 비로그인 사용자의 메뉴에는 로그인·회원가입을 배치한다.
- 메뉴의 목적이 불분명해지지 않도록 텍스트 레이블을 유지하고 아이콘만으로 기능을 표현하지 않는다.

## 모바일 지도와 바텀시트

- `Home`의 선택 장소 여부를 `MapExplorerPanel`에 전달한다.
- 모바일에서 장소가 선택되면 패널 보기를 `map`으로 전환해 지도/목록 탭 높이만 남긴다.
- 장소 정보 바텀시트는 지도 위 하단에 유지한다.
- 바텀시트를 닫아도 탐색 패널은 접힌 상태를 유지한다.
- 사용자가 `목록` 탭을 누르면 검색·카테고리·장소 목록을 다시 펼친다.
- 데스크톱의 좌측 탐색 목록 동작은 변경하지 않는다.
- `prefers-reduced-motion` 사용자는 기존과 같이 시트 애니메이션을 생략한다.

## TypeScript 7 전환

- `typescript` 의존성을 정확히 `7.0.2`로 고정한다.
- 기존 `wrangler types`, `react-router typegen`, `tsc -b` 순서를 유지해 실제 프로젝트 참조 빌드를 TypeScript 7로 검사한다.
- TypeScript 7에서 제거된 설정이나 새 기본값 충돌이 발생할 때만 `tsconfig`를 최소 수정한다.
- TypeScript 6 호환 패키지는 현재 도구가 TypeScript 컴파일러 API를 직접 요구하지 않으므로 추가하지 않는다.
- 락파일에는 TypeScript 7을 사용하는 React Router 및 관련 peer dependency 해석 결과를 보존한다.

## 장소 분류 알고리즘

### 1단계: 상호명 다중 신호

- 상호명은 공백·기호를 제거하고 음식명 오탈자·이형 표기를 정규화한다.
- `육계장`은 `육개장`과 같은 신호로 취급한다.
- 현재처럼 첫 번째 일치 규칙에서 종료하지 않고 상호명에 포함된 모든 음식 신호를 수집한다.
- 하나의 구체적인 신호와 원천 업태가 일치하면 높은 규칙 신뢰도를 부여한다.
- 서로 다른 대표 카테고리 신호가 둘 이상이면 한쪽을 임의 선택하지 않고 충돌 후보로 남긴다.
- 규칙 근거에는 일치한 실제 상호명 토큰과 정규화 내역을 저장한다.

### 2단계: Workers AI 교차검증

- AI에는 전체 카테고리를 자유 선택하게 하지 않고 규칙이 만든 상위 후보와 `기타/판단 불가` 선택지만 전달한다.
- 응답은 카테고리, 신뢰도, 상호명에서 인용한 근거 토큰, 판단 사유를 구조화해 받는다.
- 근거 토큰이 정규화된 상호명·원천 업태에 실제로 존재하지 않으면 응답을 실패 처리한다.
- 규칙과 AI가 같은 카테고리를 선택하고 근거 검증까지 통과할 때만 최종 신뢰도를 높인다.
- AI 자체 확률만으로 자동 승인하지 않는다. 복합 상호, 규칙 충돌, 근거 부재는 수동 확인에 남긴다.
- 프롬프트 버전을 올려 기존 잘못된 캐시와 분리하고 근거 검증 실패를 운영 알림에 기록한다.

### 3단계: 선택적 웹 보강

- 외부 검색은 규칙과 AI로 판단하지 못한 후보만 처리하는 별도 인터페이스로 설계한다.
- 검색 결과의 상호명 일치, 주소 근접도, 업종·메뉴 근거를 각각 저장할 수 있게 한다.
- 이번 릴리스에는 외부 검색 API 호출을 넣지 않는다. 네이버 지역검색 등 공급자 자격 증명과 이용약관을 확정한 뒤 연결한다.
- 웹 검색 결과 하나만으로 자동 공개하지 않으며 규칙·AI·운영 검수와 함께 사용한다.

### 오류 재현 기준

- `콩물동부육계장`은 `김밥`으로 분류되지 않아야 하며 육개장·탕 계열 후보와 정규화 근거를 반환해야 한다.
- `다마수제타코야끼앤버거`는 타코야끼와 버거의 복수 신호를 보여 주고 자동 승인 대상이 되지 않아야 한다.
- `gimbap`처럼 상호명과 업태에 없는 AI 근거는 검증 단계에서 거부해야 한다.

## 테스트와 배포 기준

- 헤더의 고정 링크와 햄버거 메뉴 노출을 역할별 E2E로 확인한다.
- 모바일에서 목록을 연 뒤 장소를 선택하면 목록이 접히고 바텀시트가 표시되는 흐름을 E2E로 확인한다.
- 바텀시트 닫기와 목록 재열기를 확인한다.
- 실제 오분류 사례와 근거 없는 AI 출력에 대한 단위·통합 회귀 테스트를 추가한다.
- 단위 테스트, Workers 통합 테스트, 전체 Playwright E2E, TypeScript 7 타입 검사, 프로덕션 빌드를 모두 실행한다.
- Cloudflare 배포 전 dry-run과 Worker 시작 검사를 수행한다.
- PR 병합 후 `main`에서 운영 배포하고 공개 페이지, 로그인 리다이렉트, 새 정적 자산을 스모크 검증한다.

## 실패 처리

- TypeScript 7 진단이 실제 소스 오류를 발견하면 소스를 수정하고 회귀 테스트를 추가한다.
- 도구 체인이 TypeScript 7 API를 요구해 실패하면 원인을 기록하고 6/7 병행 구성을 검토하되, 검증 없이 운영 배포하지 않는다.
- 모바일 상태 전환 실패 시 URL의 선택 상태와 패널 UI 상태를 분리해 디버깅하며 장소 선택 URL은 유지한다.
