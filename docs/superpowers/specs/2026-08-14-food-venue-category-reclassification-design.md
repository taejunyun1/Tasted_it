# 음식점 판별 및 전체 카테고리 재분류 설계

- **상태:** GO
- **작성일:** 2026-08-14
- **결정:** 사용자 요청으로 대기 후보와 공공데이터 원천이 연결된 공개 장소를 새 규칙으로 일괄 재분류한다.
- **소유:** Codex (`codex/tj-category-reclassification-v3`)

## 문제

`신 돼지세끼`의 원천 업태는 `식육(숯불구이)`지만, 현재 분류표에는 이 업태를 `고기·구이`로 연결하는 규칙이 없다. 상호에서 특정 메뉴를 찾지 못하면 `GENERAL_RESTAURANT` 기본값인 `백반·가정식`이 선택된다.

동시에 일반음식점 데이터에는 PC방, 공예·도예 작업실, 편의점처럼 식사를 부수적으로 판매하거나 음식점으로 잘못 등록된 장소가 섞인다. 이들은 지도·검색·추천 후보가 되어서는 안 된다.

## 목표와 비목표

### 목표

1. `식육(숯불구이)`, `석쇠구이`, `불고기`, `갈비`, `정육식당`을 `고기·구이`로 일관되게 분류한다.
2. 장어·해산물처럼 더 구체적인 메뉴 신호는 일반 `구이` 업태보다 우선한다.
3. PC방·고신뢰 공예 시설·편의점 체인은 자동 제외하고 근거와 복원 경로를 남긴다.
4. 모든 `PENDING` 후보와 원천이 연결된 `PUBLISHED` 장소의 대표 카테고리를 새 규칙으로 다시 계산한다.
5. 자동 제외나 재분류의 원인과 전후 값은 관리자 감사 로그에서 확인할 수 있게 한다.

### 비목표

- LLM 호출이나 새 외부 API를 추가하지 않는다.
- 장소·리뷰·사진을 삭제하지 않는다.
- 공개 장소를 규칙 하나만으로 `HIDDEN`으로 바꾸지 않는다. 비음식 시설은 공개 조회에서 제외하되, 관리자가 예외 복원할 수 있다.
- 사람의 개별 카테고리 선택을 새 UI로 수집하지 않는다.

## 결정: 두 단계 판별

### 1. 음식점 적합성 게이트

카테고리 계산보다 먼저 실행한다. 결과는 `ALLOW`, `EXCLUDE`, `MANUAL_REVIEW` 중 하나다.

| 결과 | 조건 | 예시 | 처리 |
| --- | --- | --- | --- |
| `EXCLUDE` | 편의점 체인 명칭이 상호 처음에 일치 | CU, GS25, 세븐일레븐, 이마트24, 미니스톱 | `NOT_RESTAURANT` 자동 제외 |
| `EXCLUDE` | 고신뢰 비음식 시설 표현 | PC방·피시방, 노래방, 스크린골프, 도예·목공·가죽·캔들 공방 | `NOT_RESTAURANT` 자동 제외 |
| `EXCLUDE` | 기존 유흥·성인 업종 표현 | 룸살롱, 카바레, 라이브바, 단란주점 | 기존 `ADULT_ENTERTAINMENT` 자동 제외 |
| `ALLOW` | 명시적인 음식 메뉴 신호가 있음 | 마라공방, 떡볶이공방, 장어구이 | 음식 분류로 진행 |
| `MANUAL_REVIEW` | `공방` 단독처럼 비음식 여부가 확실하지 않음 | 동네공방 | 낮은 신뢰도로 수동 확인 |

`공방` 하나만으로 자동 제외하지 않는다. `마라공방` 같은 실제 음식점을 잘못 숨기지 않기 위해 공예 종류 또는 비음식 시설 표현과 함께 확인한다.

자동 비음식 제외를 성인 유흥 제외로 기록하지 않는다. `business_license_exclusions.reason`에 `NOT_RESTAURANT`를 추가하고, `exclusion_category`도 같은 값으로 기록한다. 기존 체인점·유흥·관리자 예외 이력은 보존한다.

### 2. 카테고리 근거 우선순위

후보 카테고리는 점수 합계가 아니라 근거 등급을 먼저 비교한다. 같은 등급일 때만 점수를 비교한다.

| 등급 | 근거 | 예시 | 결과 |
| --- | --- | --- | --- |
| A | 상호의 구체 음식·재료 | 풍천장어구이, 순대국, 라멘 | 해당 음식 카테고리 |
| B | 원천의 구체 업태 | 식육(숯불구이), 석쇠구이, 제과점영업 | 해당 업태 카테고리 |
| C | 상호의 일반 음식 표현 | 고기, 구이, 카페, 포차 | 해당 카테고리 |
| D | 넓은 원천 업태 | 한식, 일식, 경양식, 분식 | 보조 카테고리 |
| E | 데이터 원천 기본값 | GENERAL_RESTAURANT | 최후 기본값 |

따라서 `신 돼지세끼 / 식육(숯불구이)`는 B 등급의 `grill`이 되고, `풍천장어구이 / 식육(숯불구이)`는 A 등급 해산물 신호가 승리한다. A·B 등급에서 서로 다른 카테고리가 가까운 점수로 경쟁하면 `CONFLICT`로 수동 검수한다. E 등급만 있으면 `LOW`다.

분류 근거에는 등급과 사람이 읽을 수 있는 문구를 함께 남긴다. 예: `원천 업태 식육(숯불구이) → 고기·구이 (B, 90점)`.

## 일괄 재분류 범위와 안전장치

1. 대상은 `OPEN`인 `PENDING` 후보와, 그 후보 원천이 `place_source_links`로 연결된 `PUBLISHED` 장소다.
2. 자동 제외 대상 후보는 활성 제외 이력을 만든다. 이미 `OVERRIDDEN`인 이력은 다시 자동 제외하지 않는다.
3. 공개 장소는 삭제·숨김 없이 대표 카테고리만 바꾼다. 공개 목록·지도·추천은 원천의 비음식 판별과 활성 예외 상태를 함께 보아 제외한다.
4. 재분류는 미리보기와 적용을 분리한다. 미리보기는 기존·신규 카테고리, 제외 여부, 근거, 충돌 수를 반환한다. 적용은 한 요청당 100곳 이하로 처리하고 다음 커서를 반환한다.
5. 대표 카테고리가 달라질 때만 `place_categories`의 primary 표시를 원자적으로 변경하고, `admin_audit_logs`에 전후 카테고리·규칙 버전을 기록한다.
6. `OVERRIDDEN` 자동 제외는 공개 필터에서도 존중한다. 거짓 양성은 관리자 복원 뒤 즉시 다시 보인다.

## 관리자 경험

- 제외 목록에는 `편의점 자동 제외`, `비음식 시설 자동 제외`, `유흥업종 자동 제외`, `체인점 자동 제외`를 구분해 표시한다.
- 재분류 화면은 먼저 `변경 예정`, `충돌`, `낮은 신뢰도`, `자동 제외` 수를 보여준다.
- 적용 완료 후 `처리됨 / 변경됨 / 제외됨 / 보류됨` 수와 다음 처리 버튼을 보여준다.
- 개별 행에는 현재 카테고리, 새 카테고리, 가장 강한 근거 하나만 우선 노출하고 상세 근거는 펼쳐서 본다.

## 운영·롤백

- 새 패키지, 외부 API, Cloudflare binding, cron은 추가하지 않는다.
- D1 migration은 새 순번으로만 추가하고, 기존 제외 이력 전체를 원문 그대로 복사하는 통합 테스트를 둔다.
- 원격 일괄 적용은 PR 본문에 대상 `PENDING`·`PUBLISHED`, 요청당 100개 제한, 영향 수 확인, rollback 절차를 명시한 뒤 PR 병합 후 관리자 경로에서 실행한다.
- 잘못된 재분류는 감사 로그의 전 카테고리로 관리자 복원 경로를 통해 forward-fix 한다. 이미 반영된 migration은 되돌려 수정하지 않는다.

## 완료 기준

1. `식육(숯불구이)`가 `grill`로 분류되고 `신뢰도 높음`으로 표시된다.
2. `풍천장어구이 / 식육(숯불구이)`는 해산물로 유지된다.
3. CU·GS25·세븐일레븐·이마트24·미니스톱, PC방, 구체 공예 시설은 자동 제외되며 `마라공방`은 제외되지 않는다.
4. 공개 목록·지도·추천·코스에서 활성 비음식 장소를 볼 수 없고, 관리자 복원 뒤에는 다시 보인다.
5. 재분류 미리보기와 적용이 동일 규칙 버전을 사용하며, 두 번째 적용은 카테고리 중복이나 감사 로그 중복을 만들지 않는다.
