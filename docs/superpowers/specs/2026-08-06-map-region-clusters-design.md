# 지도 행정구역 클러스터 설계

**작성일:** 2026-08-06  
**상태:** 구현 전 확정안  
**대상:** 회원 메인 지도와 지도 왼쪽 장소 목록

## 1. 목표

넓은 지도에서 개별 음식점 마커가 겹치는 문제를 줄이고 사용자가 광주·전남의 지역 구조를 바로 이해하도록 한다. 지도 확대 수준에 따라 `구·시·군 → 동·읍·면 → 개별 장소` 순서로 전환하고, 같은 기준으로 왼쪽 목록도 묶는다.

이번 변경은 행정구역을 지도에 표시하는 탐색 UI다. 장소 공개 상태, 검색, 카테고리 필터, 추천 점수와 평가 계산 규칙은 바꾸지 않는다.

## 2. 채택 방식

`행정구역 우선 + 좌표 보완` 방식을 사용한다.

- 주소에서 광주는 자치구, 전남은 시·군을 추출한다.
- 세부 지역은 기존 `neighborhood`를 우선 사용하고 없으면 주소의 동·읍·면·리를 추출한다.
- 행정구역을 추출할 수 없는 장소는 같은 확대 단계에서 좌표 기반 근접 그룹으로 묶고 `주변 N곳`으로 표시한다.
- 단순 픽셀 격자 클러스터를 기본으로 사용하지 않는다. 화면을 조금 이동할 때 지역 이름과 묶음이 불안정하게 바뀌기 때문이다.
- 별도 행정경계 폴리곤이나 외부 지오코딩 API는 이번 범위에 추가하지 않는다.

## 3. 확대 단계와 전환 규칙

Naver Maps의 현재 zoom 값을 단일 기준으로 사용한다.

| zoom | 지도 표현 | 목록 표현 |
|---|---|---|
| `0~12` | 구·시·군 클러스터 | 구·시·군별 섹션 |
| `13~14` | 동·읍·면 클러스터 | 동·읍·면별 섹션 |
| `15 이상` | 개별 장소 마커 | 개별 장소 목록 |

- 초기 zoom `12`에서는 `북구 12`, `동구 8`, `담양군 5`처럼 표시한다.
- 구·시·군 클러스터를 누르면 해당 장소들의 좌표 경계를 화면에 맞추되 최소 zoom `13`까지 확대한다.
- 동·읍·면 클러스터를 누르면 해당 장소들의 좌표 경계를 화면에 맞추되 최소 zoom `15`까지 확대한다.
- 장소를 목록에서 직접 선택하면 기존 동작처럼 zoom `16`으로 이동하고 빠른 정보 바텀시트를 연다.
- 사용자가 다시 축소하면 선택된 장소의 빠른 정보는 유지하되 지도 마커는 현재 확대 단계의 표현을 따른다.

임계값은 순수 함수와 테스트 상수로 관리한다. 실제 기기 QA에서 지나치게 빠르거나 늦게 전환되면 숫자만 조정할 수 있게 한다.

## 4. 지역명 추출

### 4.1 광주

주소에서 `동구`, `서구`, `남구`, `북구`, `광산구`를 구 단위 키로 사용한다. `전남광주통합특별시`처럼 현재 원천 데이터에 존재하는 광주 호환 주소도 같은 규칙을 적용한다.

### 4.2 전남

주소에서 광주 5개 구가 아닌 첫 번째 `시` 또는 `군` 토큰을 상위 지역 키로 사용한다. 예시는 `목포시`, `여수시`, `담양군`, `화순군`이다.

### 4.3 세부 지역

1. `place.neighborhood`의 동·읍·면 값을 사용한다.
2. 값이 비어 있거나 형식이 잘못되면 주소의 괄호 안 법정동을 우선 추출한다.
3. 이후 주소 본문의 마지막 동·읍·면·리 토큰을 사용한다.
4. 추출 실패 시 좌표 보완 그룹으로 보낸다.

장소 등록 화면에 별도 동네 입력을 다시 추가하지 않는다. 주소와 기존 자동 추출 결과가 유일한 기준이다.

## 5. 클러스터 계산

클러스터 계산은 지도 SDK와 분리된 순수 TypeScript 모듈이 담당한다.

각 클러스터는 다음 정보를 가진다.

```ts
type RegionClusterLevel = "DISTRICT" | "NEIGHBORHOOD" | "PLACE";

interface RegionCluster {
  id: string;
  level: Exclude<RegionClusterLevel, "PLACE">;
  label: string;
  count: number;
  latitude: number;
  longitude: number;
  bounds: [west: number, south: number, east: number, north: number];
  placeIds: string[];
  fallback: boolean;
}
```

- 중심 좌표는 포함 장소 좌표의 산술 평균을 사용한다.
- 이동 범위는 포함 장소 좌표의 최소·최대값으로 만든다.
- `id`는 확대 단계와 정규화 지역 키를 조합해 안정적으로 생성한다.
- 장소 수가 한 곳이어도 zoom `14` 이하에서는 지역 클러스터로 표시해 확대 단계가 일관되게 유지되도록 한다.
- 현재 검색·카테고리·bbox 결과에 포함된 공개 장소만 계산한다. 숨김·폐업 장소는 서버 조회 단계에서 이미 제외된다.

## 6. 좌표 보완 그룹

주소 지역명이 없는 장소는 유실시키지 않고 현재 지도 결과 안에서 좌표를 일정 단위로 양자화해 묶는다.

- 구·시·군 단계: 약 8km 단위 셀
- 동·읍·면 단계: 약 1.5km 단위 셀
- 표시는 `주변 3곳`처럼 중립적인 문구를 사용한다.
- 정상 행정구역 그룹과 좌표 보완 그룹을 합치지 않는다.
- 보완 그룹을 클릭하면 동일하게 bounds 이동을 수행한다.

이 보완은 표시 안정성을 위한 최후 수단이며 잘못된 행정구역명을 추측하지 않는다.

## 7. 지도 UI

### 7.1 지역 클러스터 마커

- 흰색 바탕, 진한 녹색 테두리의 납작한 캡슐형 버튼을 사용한다.
- 지역명은 `500`, 장소 수는 `600` 이하 굵기로 구분하고 전체를 `700`으로 만들지 않는다.
- 예: `북구 12`, `용봉동 5`.
- 장소 수가 많아져도 그림자 크기를 키우지 않는다. 장소 영향력 시각화는 개별 장소 단계에서만 유지한다.
- hover·focus에서는 배경색만 옅은 녹색으로 바꾸고 위치나 크기를 튀기지 않는다.

### 7.2 전환 애니메이션

- 클러스터 클릭은 Naver Maps `morph` 또는 `fitBounds`로 420~520ms 이동한다.
- `prefers-reduced-motion: reduce`에서는 즉시 중심과 zoom을 변경한다.
- 애니메이션 중 발생하는 `idle` 이벤트가 bbox를 연속 갱신하지 않도록 기존 bounds 억제 시간을 재사용한다.
- zoom 단계가 바뀔 때 기존 마커를 먼저 제거한 뒤 새 단계 마커를 한 번만 생성한다.

### 7.3 접근성

- 구 클러스터: `aria-label="북구 음식점 12곳, 확대해서 보기"`.
- 동 클러스터: `aria-label="용봉동 음식점 5곳, 확대해서 보기"`.
- 키보드 Enter와 Space로 클릭할 수 있는 실제 `button` 요소를 사용한다.
- 개별 마커의 기존 장소명 접근성 이름은 유지한다.

## 8. 목록 UI

- zoom `12` 이하에서는 `북구 12곳` 같은 구·시·군 제목 아래 장소를 표시한다.
- zoom `13~14`에서는 `용봉동 5곳` 같은 동·읍·면 제목 아래 장소를 표시한다.
- zoom `15` 이상에서는 현재처럼 번호가 있는 단일 목록을 표시한다.
- 섹션 순서는 장소 수가 아니라 지역명 가나다순으로 고정해 지도 이동 시 목록 순서가 불필요하게 흔들리지 않게 한다.
- 섹션 내부 장소는 현재 서버 결과 순서를 유지한다.
- 지역 제목을 누르면 대응하는 지도 클러스터와 동일하게 이동·확대한다.
- 검색과 카테고리 필터를 변경하면 현재 결과로 즉시 다시 그룹화한다.

모바일에서 빠른 정보 바텀시트가 열리면 목록 패널을 접는 기존 동작을 유지한다.

## 9. 구성 경계

- `region-cluster-policy.ts`: zoom 단계, 주소 지역 추출, 좌표 보완, 클러스터 계산을 소유한다.
- `home.tsx`: 현재 zoom과 선택할 지역 클러스터를 일시 상태로 소유하고 동일한 클러스터 뷰 모델을 지도와 목록에 전달한다. URL 검색 상태와 공개 장소 조회는 기존대로 유지하며 행정구역별 별도 API를 만들지 않는다.
- `PlaceMap.tsx`: Naver Maps 인스턴스, zoom 변경 통지, 마커 생명주기와 선택된 지역 클러스터로의 이동만 소유한다.
- `MapPlaceList.tsx`: 전달받은 목록 그룹 렌더링과 지역 제목 선택을 담당한다.
- `MapExplorerPanel.tsx`: 지역 제목 선택을 상위 `home.tsx`에 전달하고 현재 확대 단계에 맞는 목록을 표시한다.

DB 마이그레이션과 외부 API 추가는 없다. 모든 계산은 서버가 반환한 최대 100개 공개 장소를 대상으로 클라이언트에서 수행한다.

## 10. 오류와 경계 조건

- 장소가 0개면 현재 빈 상태 문구를 유지한다.
- 좌표가 없는 공개 장소는 기존 서버 승인 규칙상 없어야 하지만 입력되면 지도 마커에서 제외하고 목록에는 `위치 확인 필요`로 남긴다.
- 동일 지역명이 광주·전남에 중복되면 상위 지역 키를 포함한 ID로 충돌을 막는다.
- 선택한 장소가 필터 또는 bbox 결과에서 사라지면 기존 동작대로 선택 상태를 제거한다.
- Naver Maps SDK 로드 실패 시 기존 오류 메시지와 목록 탐색을 유지한다.
- zoom 이벤트가 매우 빠르게 연속 발생해도 마지막 단계의 마커 집합만 남아야 한다.

## 11. 테스트와 완료 기준

### 단위 테스트

- zoom `12/13/14/15` 경계가 각각 구·동·동·개별 단계가 된다.
- 광주 5개 구와 전남 시·군을 올바르게 추출한다.
- 기존 neighborhood, 괄호 법정동, 주소 토큰 우선순위를 검증한다.
- 지역 추출 실패 장소가 좌표 보완 그룹에 포함된다.
- 중심, bounds, 장소 수, 안정 ID가 같은 입력에서 동일하게 계산된다.

### 브라우저 테스트

- 초기 지도에서 개별 마커 대신 구·시·군 클러스터가 표시된다.
- 구 클러스터 클릭 후 동 클러스터로 전환되고 URL bbox가 갱신된다.
- 동 클러스터 클릭 후 개별 장소 마커로 전환된다.
- 개별 마커 클릭 시 기존 zoom 이동과 빠른 정보 바텀시트가 유지된다.
- 목록의 구·동 그룹 제목이 지도 단계와 일치한다.
- 검색·카테고리 필터 후 클러스터 수와 목록 장소 수가 일치한다.
- 데스크톱과 모바일에서 키보드 조작 및 접근성 이름을 확인한다.

### 출시 게이트

- 단위·통합·전체 E2E·TypeScript 7 typecheck·빌드가 모두 통과한다.
- 운영 지도에서 광주 5개 구, 전남 시·군, 동·읍·면 전환을 표본 확인한다.
- 지도 이동 중 bbox 재조회 루프나 마커 잔상이 없다.
- 기능 브랜치 PR을 squash merge한 뒤 최신 `main`에서 Cloudflare Worker를 배포한다.

## 12. 이번 범위에서 제외

- 행정동 경계 폴리곤 색칠.
- 실시간 상권·인구·교통 데이터 레이어.
- 서버 저장형 클러스터 테이블과 사전 집계.
- 전국 행정구역 코드 데이터셋 도입.
- 사용자가 직접 지역명을 수정하는 입력 UI.
- 개별 장소 영향력 점수 계산 방식 변경.
