# 카테고리 근거 우선·공개 회수 설계

## 목표

공공데이터의 포괄 업태를 대표 카테고리로 자동 확정하지 않고, NAVER 지역검색의 상호·위치·구체 카테고리 근거 또는 관리자 수동 승인을 통과한 장소만 공개한다. 현재 공개 중인 장소는 삭제하지 않고 전부 회수한다.

## 현재 문제와 근거

- `GENERAL_RESTAURANT` 후보의 기본 규칙이 `home-meal(백반·가정식)`이다.
- 운영 공개 장소 643곳 중, 대표 카테고리가 백반·가정식인 장소는 222곳이며 모두 일반음식점 원천이다.
- 그 222곳 중 원천 업태는 `기타` 135곳, `한식` 71곳이 대부분이다. 두 업태는 대표 메뉴를 특정하지 못한다.
- 관리자 화면의 `RULE_ONLY · 40점 · 일치 없음`은 NAVER 근거가 없는 제안임에도 승인 가능한 카테고리 값으로 표현된다.

## 결정

### 자동 분류

1. 일반음식점의 포괄 업태(`기타`, `한식`, 그 밖의 구체 음식 신호가 없는 값)는 카테고리를 자동 확정하지 않는다.
2. 자동 확정은 다음 세 가지 NAVER 근거가 한 번의 검증 결과에서 모두 충족될 때만 가능하다.
   - 상호: 정확 일치 또는 정규화한 지점명 일치
   - 위치: 정확 주소 일치 또는 100m 이내 좌표 일치
   - 카테고리: 내부 최종 카테고리로 매핑되는 구체 NAVER 카테고리
3. 상호명·원천 업태 규칙은 후보 우선순위를 정하는 보조 근거로만 사용한다. NAVER 근거가 없으면 `분류 확인 필요`가 된다.
4. 원천 업태와 구체 NAVER 카테고리가 충돌하면 자동 확정하지 않고 수동 확인으로 보낸다.

### 관리자 검수 UI

- 대표 카테고리는 다중 태그가 아닌 단일 선택 값이다.
- 각 후보에 `NAVER 확정`, `수동 선택 필요`, `근거 충돌`, `검증 실패` 상태를 눈에 보이는 근거 칩으로 표시한다.
- 카테고리 선택기는 검색 가능한 단일 선택 태그 목록으로 제공한다. 현재 선택·NAVER 추천·원천 업태를 함께 보여 주되, 추천이 저장값처럼 보이지 않게 분리한다.
- `NAVER 확정`이나 수동 선택이 없는 후보는 승인·공개 일괄 작업 대상에서 제외한다.

### 공개 회수와 재공개

- 작업 시점의 `places.status = PUBLISHED` 643곳을 `HIDDEN`으로 일괄 전환한다.
- 장소는 삭제하지 않는다. 각 대상에 `RECALL_PUBLISHED_PLACES_FOR_CATEGORY_AUDIT` 감사 로그를 남긴다.
- 이 회수 작업의 복구는 해당 감사 로그의 대상만 `PUBLISHED`로 되돌리는 전용 운영 작업으로 제한한다.
- 회수 후 재공개는 NAVER 3종 근거가 충족된 경우 또는 관리자 수동 승인이 있는 경우에만 허용한다.

### 기존 백반·가정식 재검증

- 기존 222곳은 현재 카테고리를 일괄 덮어쓰지 않는다.
- 기존 NAVER 지역검색 adapter와 일일 200회 한도를 사용한다.
- NAVER 3종 근거가 충족되면 내부 최종 카테고리로 재분류 후보를 만들고 감사 로그를 남긴다.
- 근거 부족·충돌·실패는 숨김 상태를 유지하며 수동 검수 목록으로 보낸다.

## 데이터 경계와 안전성

- 새 외부 공급자·패키지·Cloudflare binding을 추가하지 않는다.
- NAVER 원문 상호·장소 ID·사진은 저장하지 않는다. 내부 카테고리, 점수, 허용된 근거 코드, 실패 코드만 저장한다.
- NAVER 기능 플래그와 일일 한도는 유지한다. 한도 도달·공급자 오류 때는 자동 재공개하지 않는다.
- 운영 D1 변경은 병합된 PR에 명시된 대상·검증·복구 절차로만 실행한다.

## 검증

- 단위 테스트: 포괄 업태가 자동 확정되지 않는지, 세 NAVER 근거가 모두 있어야 자동 확정되는지, 충돌이 수동 확인이 되는지 검증한다.
- 통합 테스트: 승인 전제조건, 공개 회수와 감사 로그, 감사 대상만 복구되는지 검증한다.
- E2E: 데스크톱·모바일에서 추천 근거와 단일 선택 태그를 구분하고, 미확정 후보를 승인할 수 없는지 검증한다.
- 운영 전: 대상 수 643과 감사 로그 수가 같은지 확인하고, 공개 지도·목록 결과가 0개인지 확인한다.

## 롤아웃과 롤백

1. 코드 PR을 병합·배포한다.
2. 공개 회수 작업을 실행하고 대상·감사 로그·공개 조회 결과를 기록한다.
3. 기존 백반·가정식 재검증을 일일 한도 안에서 실행한다.
4. 이상 시 자동 재공개를 중지하고, 회수 감사 작업의 대상만 전용 복구 작업으로 되돌린다.
