# 장소 운영 중복 상호·NAVER 상태 검수 설계

## 목표

관리자가 같은 상호를 묶어 한 번에 찾고 선택해 NAVER 근거를 재검수할 수 있게 하며, 기존 Kakao 영업 상태 판정을 NAVER 지역검색 근거로 교체한다.

## 현재 문제

- 장소 운영 화면은 장소별 단일 처리만 가능하며, 같은 상호가 여러 개 있는 경우를 찾아보거나 함께 선택할 수 없다.
- 같은 상호가 여러 주소에 존재할 수 있다. 프랜차이즈 지점은 상호가 같아도 자동 병합하면 안 된다.
- 영업 상태 재검증과 화면 표기가 `kakaoStatus`와 Kakao 검색 결과에 의존한다.

## 결정

### 동일 상호 필터와 선택

1. 상호를 NFKC 정규화하고 공백·기호를 제거한 정확 동일 상호 키로 그룹화한다.
2. `동일 상호 2곳 이상` 필터는 두 곳 이상인 그룹의 장소만 보인다.
3. 그룹 헤더의 선택 상자는 그 그룹의 현재 표시 장소를 최대 25곳까지 한 번에 선택한다.
4. 선택 결과의 일괄 작업은 `NAVER 근거 확인`과 `숨김 유지`만 제공한다. 병합은 대상·흡수 주소를 관리자가 개별로 명시하는 기존 흐름을 유지한다.
5. 화면은 상호와 함께 주소·거리·NAVER 근거 상태를 보여 같은 상호의 다른 지점을 혼동하지 않게 한다.

### NAVER 상태 판정

1. 기존 NAVER 지역검색 adapter를 상태 확인에도 사용한다.
2. NAVER 결과의 상호 일치와 주소/100m 좌표 일치를 만족하면 `MATCHED`, 복수 후보면 `AMBIGUOUS`, 결과가 없으면 `NOT_FOUND`, 공급자 오류·한도면 `ERROR` 또는 `SKIPPED`로 기록한다.
3. 상태 확인은 원문 NAVER 결과를 저장하지 않고, 공급자 이름, 상태, 점수, 허용 근거 코드, 확인 시각만 저장한다.
4. 기존 Kakao 상태 컬럼은 과거 이력으로 보존하고, 새 NAVER 상태 컬럼을 추가한다. 관리자 UI와 새 자동 처리에는 NAVER 상태만 사용한다.
5. 일일 NAVER 한도 200회는 카테고리 검증과 공유한다. 한도 도달 시 새 상태 확인은 중단하고 자동 숨김·자동 공개를 수행하지 않는다.

## 데이터와 운영

- 새 D1 migration은 `place_liveness_states`에 NAVER 상태·매칭 식별자·확인 시각을 추가한다. 적용된 Kakao 컬럼은 수정·삭제하지 않는다.
- 기존 Kakao 정기 작업은 NAVER 작업으로 교체한다. 별도 cron·Queue·Cloudflare binding은 추가하지 않는다.
- 사용자에게 공개되는 지도·목록은 이미 `PUBLISHED` 상태만 조회한다. 카테고리 감사 회수 이후에는 숨김 상태가 즉시 지도에서 제외된다.

## 검증

- 단위 테스트: 동일 상호 정규화, 25곳 선택 제한, NAVER 일치·모호·미검색·오류 상태를 검증한다.
- 통합 테스트: NAVER 상태 저장, 한도 도달 시 안전 정지, Kakao 이력 보존, 일괄 숨김 감사 로그를 검증한다.
- E2E: 동일 상호 2곳 이상 필터, 그룹 전체 선택, NAVER 근거 확인, 주소가 다른 동일 상호가 자동 병합되지 않는지 검증한다.

## 롤백

- NAVER 상태 확인 기능 플래그를 끄면 자동 상태 변경을 중단한다.
- 과거 Kakao 상태 데이터는 그대로 남아 조사 용도로만 사용한다.
- 공개 회수·재공개는 별도의 장소 상태 감사 로그를 사용하므로 NAVER 상태 migration 롤백과 독립적이다.
