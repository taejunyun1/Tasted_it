# NAVER 근거 워크벤치와 Workers AI 제거 설계

**상태:** ACCEPTED — 2026-08-15 사용자 요청 및 #123 범위 확정

## 1. 목적

관리자 `/admin/candidates`를 AI 사용량과 복수의 재분류 패널을 나열하는 화면에서, 장소 분류의 근거를 판단하고 적용하는 단일 작업대로 바꾼다.

Workers AI 후보 분류는 동작 신뢰도와 운영 비용 대비 가치가 낮으므로 완전히 제거한다. NAVER API HUB 지역검색의 상호·주소·좌표·구체 카테고리를 공공데이터 원천 업태와 교차 검증해, 설명 가능한 신뢰도로 후보를 분류한다.

## 2. 범위와 비범위

### 포함

- Workers AI binding, 실행 코드, 스케줄, UI, 사용량·운영 지표, AI 실행 이력 테이블 제거
- NAVER API HUB 지역검색 URL·인증 헤더 계약으로 전환
- 동기화 후 신규 후보의 자동 NAVER 검증과, 관리자의 선택/필터 범위 수동 재검증
- API 실패 원인별 중단·재시도 안내와 근거 중심 검수 UI
- 기존 공개 장소 규칙 재분류 작업대 제거. 규칙은 NAVER 근거가 부족할 때 후보의 보조 제안으로만 유지

### 제외

- 사용자 지도·목록·상세 요청에서 NAVER 지역검색 호출
- NAVER 응답의 장소 ID, 링크, 이미지, 리뷰, 설명 원문 저장
- 신규 Queue, Durable Object, 외부 데이터베이스, UI kit 도입
- NAVER 근거만으로 관리자 승인·공개를 자동 실행

## 3. 대안과 결정

| 대안 | 장점 | 단점 | 결정 |
| --- | --- | --- | --- |
| 수동 재검증만 제공 | 호출량 제어가 단순 | 동기화 후 102개 수동 확인이 누적 | 기각 |
| 동기화 때 전수 자동 검증 | 빠른 근거 확보 | Worker 외부 subrequest·API 오류가 동기화를 망칠 수 있음 | 기각 |
| 자동 소량 검증 + 수동 범위 재검증 | 새 후보를 빠르게 정리하면서 운영자가 범위를 통제 | 커서·상태 안내가 필요 | 채택 |

자동 검증은 동기화 완료 뒤 신규 후보 중 최대 25곳만 별도 요청으로 수행한다. 관리자는 현재 필터 또는 선택한 후보를 최대 25곳씩 재검증한다. 한 HTTP 요청에서 외부 NAVER 호출을 50회 미만으로 제한해 Cloudflare Free의 50개 외부 subrequest 한도 안에 둔다.

## 4. NAVER 검증 계약

### API 경계

`NaverLocalSearchAdapter`는 NAVER API HUB의 다음 계약만 사용한다.

- URL: `https://naverapihub.apigw.ntruss.com/search/v1/local`
- 헤더: `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY`
- 요청: 상호명과 주소 앞 4개 토큰, 결과 최대 5개
- timeout: 4초
- 응답: 이름, 카테고리, 도로명/지번 주소, WGS84 `mapx`/`mapy`만 메모리에서 투영

기존 secret 이름은 유지하되 값은 API HUB에서 발급된 Client ID·Secret이어야 한다. secret 값은 로그·D1·클라이언트에 노출하지 않는다.

### 검증 및 점수

한 결과가 아래 조건을 충족할 때만 `VERIFIED`다.

1. 정규화 상호가 정확히 일치하거나 허용된 지점명 차이만 존재한다.
2. 정규화 주소가 일치하거나, 기존 공공데이터 좌표와 NAVER WGS84 좌표의 거리가 100m 이하이다.
3. NAVER 카테고리가 내부 최종 카테고리에 하나로 매핑되는 구체 카테고리다.

자동 제안은 NAVER 일치 40점, 구체 카테고리 20점, 원천 세부업태 일치 20점, 상호 음식 신호 일치 10점으로 계산한다. 원천 세부업태가 NAVER와 충돌하거나 NAVER 카테고리가 넓으면 자동 적용하지 않고 `확인 필요`로 남긴다. AI 점수와 AI 근거는 사용하지 않는다.

### 오류 처리

| 상태 | 처리 | 화면 문구 |
| --- | --- | --- |
| 401/403/404 등 4xx | 현재 배치 즉시 중단, 오류 코드를 실행 이력에 기록 | “NAVER API 인증 또는 호출 주소를 확인하세요.” |
| 429 | 현재 배치 즉시 중단 | “NAVER 일일 호출 한도에 도달했습니다.” |
| timeout/5xx/network | 해당 항목 실패, 남은 25개 이내 항목은 계속 시도 | “일시적으로 NAVER에 연결하지 못했습니다.” |
| 결과 없음/동명이인/근거 부족 | 실패가 아닌 확인 필요 | “NAVER 근거가 충분하지 않아 직접 확인이 필요합니다.” |

오류 원문·응답 본문은 저장하지 않는다. UI에는 안전한 내부 오류 코드와 다음 행동만 노출한다.

## 5. 데이터와 제거

### 유지·확장

`naver_local_category_verifications`와 `naver_local_category_runs`는 검증 결과와 실행 이력을 유지한다. 실행 scope는 `PENDING`과 `PUBLISHED`를 모두 표현하며, 화면은 후보 검수의 `PENDING`을 우선 사용한다.

입력 fingerprint는 상호·주소·좌표가 바뀔 때만 캐시를 무효화한다. `VERIFIED` 결과는 90일 동안 재사용하고, 수동 재검증은 명시적 갱신으로 새 호출을 허용한다.

### 제거

새 순번 D1 migration에서 아래를 제거한다.

- `ai_classification_runs` 테이블과 인덱스, 기존 AI 이력
- `AI_CLASSIFICATION` 운영 알림 enum 값과 AI 전용 집계 경로

적용된 기존 migration은 수정하지 않는다. 제거 migration의 rollback은 drop한 AI 이력을 복구하지 않는 forward-only 전략이며, 배포 전 원격 D1 export를 운영 절차로 남긴다.

## 6. 관리자 UX/UI

### 정보 구조

1. **검수 헤더** — “장소 검수”와 현재 필터의 대상 수, 전체/근거 확보/확인 필요/예외 카운트
2. **NAVER 근거 상태 레일** — 검증됨, 재검증 필요, API 문제 수와 마지막 실행 시간. 이 화면의 유일한 외부 검증 진입점이다.
3. **필터** — 기본 검색과 지역만 먼저 보이고, 공공데이터·원천 업태·제안 카테고리·신뢰도·페이지 크기는 “상세 필터” disclosure로 접는다.
4. **근거 목록** — 한 행에서 `상호 일치 → 주소/42m → NAVER 구체 카테고리 → 원천 업태 → 최종 신뢰도`를 읽는다. 넓은 카테고리·충돌·오류는 이유와 다음 행동을 텍스트로 함께 표시한다.
5. **선택 작업대** — 선택했을 때만 고정 영역을 보이며 “NAVER 근거 확인”, “카테고리 적용”, “승인·공개”, “예외 처리”를 제공한다.

### 시각 방향

Re:Taste의 크림 배경, 깊은 녹색, 라임 신호색, IBM Plex Mono 보조 데이터, 공통 간격 토큰을 유지한다. 화면의 고유 요소는 `근거 체인`이다. 작은 사각 증거 토큰과 가는 연결선으로 근거 순서를 보여 주되, 모든 정보를 pill badge로 만들지 않는다.

라임은 검증 완료와 최우선 “카테고리 적용”에만 쓴다. 오류에는 기존 rose, 확인 필요에는 amber, 예외에는 violet을 쓴다. 데스크톱에서는 표형 5열, 760px 이하에서는 장소 카드의 세로 근거 체인으로 전환한다. 키보드 포커스와 44px 모바일 조작 영역을 보장한다.

### 제거하는 화면 요소

- Workers AI 오늘 사용량·뉴런 progress
- AI 자동 분류 실행 버튼과 결과 배너
- 별도 “NAVER 100곳 재분류” 카드
- 별도 “규칙 기반 공개 장소 보조 재분류” 카드

## 7. 실행 흐름

```text
공공데이터 동기화 완료
  → 신규 PENDING 후보 최대 25곳 NAVER 검증 요청
  → 검증 결과·근거 코드 저장
  → 후보 목록을 근거 상태로 재검증

관리자 선택/현재 필터
  → NAVER 근거 확인 (최대 25곳)
  → VERIFIED + 구체 업태 일치: 카테고리 적용 가능
  → 그 외: 확인 필요 또는 오류 안내
```

동기화 성공 자체는 NAVER 실패와 분리한다. NAVER 자동 검증이 실패해도 공공데이터 후보는 정상적으로 수동 확인 큐에 남는다.

## 8. 테스트와 검증

- 단위: API HUB URL·헤더·응답 좌표 투영, 100m 경계, 4xx/429 즉시 중단, 구체·넓은 카테고리 점수
- 통합: 자동 25건·수동 선택 25건, cached verified 재사용, AI 테이블/코드 제거 뒤 후보 상태 계산
- E2E: 데스크톱·390px 모바일에서 근거 레일, 상세 필터, 선택 작업대, 명확한 오류 문구, 승인 흐름
- 회귀: 유형·빌드·기존 후보/장소 검수 범위

실제 NAVER 호출은 local/CI 테스트에서 금지하고 fake adapter를 사용한다. 운영 계약 확인은 배포 후 관리자 한 건 미리보기로만 수행한다.

## 9. 운영·개인정보·비용·복구

- 전송 데이터: 상호명, 주소, 서비스 지역 코드. 저장 데이터: 내부 카테고리·점수·허용 근거 코드·시간·안전한 오류 코드.
- NAVER API HUB의 일일 한도는 25,000건이지만 앱의 기본 실행 단위는 25건이다. quota 또는 인증 오류는 즉시 batch stop으로 비용을 차단한다.
- kill switch `NAVER_LOCAL_SEARCH_ENABLED=false`는 유지한다.
- 장애 시 자동 검증을 끄고 기존 규칙 제안과 수동 검수를 유지한다.
- 잘못 적용된 카테고리는 `NAVER_CATEGORY_REVERIFICATION` 감사 로그를 근거로 forward-fix 한다.
- Workers AI 제거는 Cloudflare binding 삭제와 Worker 재배포로 완료한다. D1 AI 이력 제거는 migration 전 export 후 수행하며 복구는 export를 이용한 별도 운영 절차만 허용한다.
