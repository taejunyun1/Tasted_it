# 체인점 수집 제외 및 어드민 복원 설계

## 목표

공공데이터에서 음식점 후보를 가져올 때 알려진 체인점을 일반 검수 목록에서 자동 제외한다. 제외된 후보는 삭제하지 않고 어드민의 `체인점 제외` 탭에서 사유를 확인할 수 있어야 하며, 오탐은 일반 검수 대상으로 복원할 수 있어야 한다.

## 범위

- 체인점 상호 판정 정책
- 수집 후보 저장 시 자동 제외
- 제외 이력과 복원 예외 보존
- 어드민 `체인점 제외` 탭, 제외 사유 표시, 복원 동작
- 비체인 베이커리 상호 분류 보강

운영 데이터 일괄 변경, 운영 migration 적용, 배포는 이 설계 범위에 포함하지 않는다.

## 체인점 판정

체인점 판정은 정규화된 상호명과 코드에 관리되는 명시적 체인 목록을 비교한다. 최초 목록은 다음 표현을 포함한다.

- 파리바게뜨
- 파리바게트
- 파리베게뜨
- 파리베게트
- 뚜레쥬르
- 뜌레쥬르

공백, 가운데점, 괄호, 영문 대소문자처럼 상호 판정에 의미가 없는 문자는 제거한 뒤 비교한다. 유사도나 단일 `빵` 같은 넓은 단어로 체인점을 추측하지 않는다. 새로운 체인은 상호 목록과 회귀 테스트를 함께 추가한다.

판정 함수는 다음 결과를 반환한다.

```ts
type ChainStoreMatch = {
  chainId: string;
  chainName: string;
  matchedTerm: string;
} | null;
```

## 제외 데이터 구조

기존 `business_licenses.review_status`의 승인·반려 의미를 유지하기 위해 제외 이력은 별도 `business_license_exclusions` 테이블에 저장한다. 활성 제외 행이 있으면 화면과 도메인에서는 후보 상태를 `EXCLUDED`로 취급한다.

필드:

- `business_license_id`: 후보 식별자, 고유값
- `reason`: 최초 값 `CHAIN_STORE`
- `matched_rule`: 판정된 체인 식별자
- `status`: `ACTIVE`, `OVERRIDDEN`, `CLEARED`
- `excluded_at`: 자동 제외 시각
- `overridden_by`, `overridden_at`: 어드민 복원 기록
- `created_at`, `updated_at`

이 구조는 기존 CHECK 제약을 재작성하지 않으며 승인·반려 기록과 자동 제외 기록을 섞지 않는다.

## 수집 흐름

1. 공공데이터 항목을 정규화한다.
2. 사업자 후보를 기존 방식으로 추가 또는 갱신한다.
3. 상호명에 체인 규칙이 일치하면 제외 행을 확인한다.
4. 제외 이력이 없으면 `ACTIVE / CHAIN_STORE`로 저장한다.
5. 기존 제외가 `ACTIVE`이면 최신 판정 정보를 유지한다.
6. 어드민이 복원한 `OVERRIDDEN` 행은 다음 동기화에서도 다시 활성화하지 않는다.
7. 체인명이 더 이상 일치하지 않으면 기존 `ACTIVE` 제외를 `CLEARED`로 바꾼다.

동기화 결과의 `skipped`는 원천 데이터 파싱 실패 건수 의미를 유지한다. 자동 제외 건수는 별도 `excluded` 값으로 반환해 운영 화면에서 구분한다.

## 어드민 화면

후보 검수 화면 상단에 `체인점 제외` 탭을 추가한다.

- 기존 `전체`, `분류 완료`, `수동 확인`, `승인 불가` 탭은 일반 `PENDING` 후보만 표시한다.
- `체인점 제외` 탭은 활성 제외 후보만 표시한다.
- 각 행에 상호명, 원천 업태, 주소, 판정 체인명, `체인점 자동 제외` 사유를 표시한다.
- 제외 행에는 승인 선택·AI 분류·카테고리 선택을 노출하지 않는다.
- `검수 대기로 복원` 버튼은 제외 상태를 `OVERRIDDEN`으로 바꾸고 관리자 감사 로그를 남긴다.
- 복원 후 후보는 일반 검수 탭에 다시 나타난다.

## 베이커리 분류

체인점으로 판정되지 않은 상호에 다음 표현이 있으면 `베이커리`로 추천한다.

- 꽈배기
- 베이커리
- 브레드
- 브래드
- 빵집

파리바게뜨·뚜레쥬르 계열은 베이커리 추천보다 수집 제외 정책이 먼저 적용되므로 일반 검수 목록에 나타나지 않는다. 단일 `빵`은 오탐 가능성이 있어 자동 분류 근거로 사용하지 않는다.

## 오류와 안전 기준

- 체인 판정 실패가 전체 동기화를 중단시키지 않도록 판정 함수는 순수 함수로 유지한다.
- 제외된 데이터는 삭제하지 않는다.
- 복원은 관리자만 수행할 수 있다.
- 복원과 자동 해제는 감사 로그에 이전·이후 상태를 기록한다.
- 이미 승인된 후보는 자동 제외로 되돌리지 않는다.
- 운영 migration과 기존 후보 일괄 재판정은 별도 승인 후 수행한다.

## 테스트

- 체인명 표기 변형과 비체인 유사 상호 단위 테스트
- 꽈배기·브레드·브래드·빵집 베이커리 분류 테스트
- 신규 체인 후보가 활성 제외로 저장되는 통합 테스트
- 복원된 후보가 재동기화되어도 제외되지 않는 통합 테스트
- 상호가 체인명에서 벗어나면 자동 해제되는 통합 테스트
- 어드민 제외 탭 목록, 건수, 복원 액션 통합·브라우저 테스트
- 전체 단위 테스트, 통합 테스트, 타입 검사, 프로덕션 빌드
