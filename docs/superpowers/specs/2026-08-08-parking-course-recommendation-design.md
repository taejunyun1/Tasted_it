# 주차장 데이터 동기화와 코스 추천 알고리즘 설계

## 목적

`한 끼 + 카페 또는 디저트`로 이미 선택된 두 장소에 대해 `한 곳 주차`와 `장소별 주차` 대안을 각각 계산한다. 가장 중요한 기준은 첫 번째 장소와 두 번째 장소에 대한 접근 거리다. 공영 여부, 주차 면수, 전기차 충전기, 예상 요금은 거리가 충분히 비슷한 후보 안에서만 순위를 바꾼다.

사용자 요청 중에는 외부 주차장·전기차 API를 호출하지 않는다. 광주·전남 데이터는 Cloudflare D1의 활성 스냅샷에서 읽고, 기존 일일 예약 작업이 마지막 정상 갱신 후 90일이 지났을 때만 새 스냅샷을 수집한다.

이번 작업 단위에는 주차장·전기차 데이터 기반, 주차 추천 도메인 서비스, 음식점 쌍 선별과 `/courses` 결과 화면을 포함한다. 코스 추천은 검수 승인된 공개 장소만 사용하고, 요청 시 외부 API를 호출하지 않는다. 회원 차량 영구 프로필은 포함하지 않으며 전기차 조건은 요청별 필터로 받는다.

## 코스 추천 화면과 흐름

### 첫 진입

- `/courses`에 추천 조건이 없으면 코스 결과를 임의로 만들지 않는다.
- 모바일에서는 첫 진입 즉시 조건 바텀시트를 연다. 데스크톱에서는 왼쪽 조건 패널을 항상 보인다.
- 조건을 적용하면 검색 매개변수에 상태를 기록하고 서버 로더가 코스와 주차 추천을 함께 계산한다.
- 공유 가능한 검색 매개변수는 `time`, `mealCategory`, `second`, `radiusKm`, `parkingMode`, `ev`, `weather`, `child`, `lat`, `lng`다.

### 조건

- 시간대: `auto`, `lunch`, `afternoon`, `dinner`, `late`
- 한 끼: 전체 또는 활성 세부 음식 카테고리. 카페·디저트 하위 카테고리는 한 끼 후보에서 제외한다.
- 두 번째 장소: `cafe` 또는 `dessert`. `dessert`는 디저트·베이커리·아이스크림·빙수를 포함한다.
- 반경: 1km, 3km, 5km, 8km
- 주차 방식: `auto`, `shared`, `separate`
- 전기차: `none`, `preferred`, `required`
- 날씨·동반 조건: 보통·비, 아이 동반 여부

위치 권한을 허용하면 브라우저 좌표를 검색 매개변수에 반영한다. 허용하지 않으면 서비스 기본 중심점인 광주광역시청 좌표를 사용하고 화면에 `기본 위치 기준`을 표시한다.

### 음식점 쌍 선별

1. `PUBLISHED` 장소와 활성 대표 카테고리만 조회한다.
2. 첫 장소는 선택 반경과 한 끼 카테고리를 만족해야 한다.
3. 두 번째 장소는 카페 또는 디저트 조건을 만족하고 첫 장소에서 1.5km 이내여야 한다. 후보가 없으면 3km까지 확장하고 `이동거리 확장`을 표시한다.
4. 장소별 평가는 표본이 8개 이상일 때만 추천률 점수에 반영한다. 표본이 부족하면 중립값으로 두고 `평가 더 필요`를 표시한다.
5. 코스 기본 점수는 첫 장소 품질 30%, 두 번째 장소 품질 25%, 사용자 위치에서 첫 장소까지 거리 20%, 두 장소 사이 거리 20%, 카테고리 조합 다양성 5%다.
6. 주차 추천이 있으면 방식 비교 점수를 코스 결과에 별도 표시하되, 먼 음식점 쌍을 주차장 사양으로 역전시키지 않는다.
7. 같은 입력은 장소 ID 순서를 최종 타이브레이커로 사용해 항상 같은 결과를 반환한다.

영업시간 정보가 없는 장소에는 시간대 적합을 추측하지 않는다. 시간대는 코스 시작 시각과 주차장 운영시간 검증에만 사용하고, 음식점 카드에는 `영업시간 확인 필요`를 표시한다.

### 결과 화면

- 상단에는 선택 조건 요약과 코스 적합도를 표시한다.
- 결과는 `한 끼 → 예상 이동 → 카페·디저트` 순서의 경로 리본으로 연결한다.
- 각 장소 카드에는 카테고리, 예상 거리, 평가 표본, 핵심 가치 배지를 최대 3개까지 표시한다.
- 주차 영역은 `한 곳 주차`와 `장소별 주차`를 함께 비교하고 추천 방식, 예상 도보거리, 예상 요금, 공영 여부, 면수, 충전기 설치 확인, 데이터 기준일을 보여준다.
- 주차 활성 스냅샷이 없거나 자격 후보가 없으면 음식 코스는 유지하고 `주차 정보 준비 중` 또는 `조건에 맞는 주차장 없음`을 표시한다.
- 모든 거리 문구는 `예상 거리` 또는 `예상 도보거리`로 표시한다.

## 확정한 원칙

1. 데이터 신뢰도는 낮은 가산점이 아니라 추천 자격을 결정하는 선행 게이트다.
2. 거리 차이가 큰 후보는 공영·면수·요금 때문에 역전할 수 없다.
3. 한 곳 주차와 장소별 주차를 각각 최적화한 뒤 두 방식의 전체 부담을 비교한다.
4. 3개월 스냅샷으로는 주차 빈자리나 충전기 실시간 사용 가능 상태를 표시하지 않는다.
5. 요금이나 면수 누락은 무료·0면으로 해석하지 않는다.
6. 부분 수집이나 공급자 장애가 기존 정상 데이터를 지우지 않는다.
7. 추천 결과는 알고리즘 버전과 사용한 데이터 스냅샷을 함께 반환한다.

## 외부 데이터

### 전국주차장정보표준데이터

- 요청 주소: `https://api.data.go.kr/openapi/tn_pubr_prkplce_info_api`
- 인증: 기존 Cloudflare 비밀값 `DATA_GO_KR_SERVICE_KEY`
- 사용 필드: 관리번호, 명칭, 공영·민영 구분, 유형, 주소, 총 주차면, 운영요일과 요일별 시간, 요금 구분, 기본·추가·일일 요금, 결제수단, 특기사항, 관리기관, 좌표, 장애인 주차구역 여부, 데이터 기준일
- 광주·전남 외 행은 저장하지 않는다.
- 원천 갱신일이 반기이고 전국 병합 데이터에 시차가 있으므로 서비스에는 반드시 데이터 기준일을 노출한다.

### 한국환경공단 전기자동차 충전소 정보

- 인증: 같은 `DATA_GO_KR_SERVICE_KEY`를 사용하되 해당 API 활용 권한을 별도로 검증한다.
- 사용 범위: 충전소 설치 위치, 충전기 종류와 수, 이용 가능시간, 이용자 제한, 주차료 무료 여부, 삭제 여부
- 실시간 충전 상태 응답은 수집·저장·표시하지 않는다.
- 90일 스냅샷에서는 `충전기 설치 확인`만 표현한다.
- 공공저작물 출처표시 조건에 따라 후속 화면에서 출처를 표시한다.

### 요청 시 외부 API 금지

추천 요청은 D1만 조회한다. 카카오 `PK6` 검색과 실제 보행 경로 API는 이번 작업에 포함하지 않는다. 따라서 초기 거리값은 WGS84 좌표 기반 예상 거리이며 UI 소비자는 이를 `예상 도보거리`로 표시해야 한다.

## 데이터 모델

신규 migration은 기존 migration을 수정하지 않고 `0014_parking_foundation.sql`로 추가한다.

### `parking_sync_runs`

- `id`, `source` (`PARKING`, `EV`)
- `status` (`RUNNING`, `COMPLETED`, `FAILED`)
- `snapshot_id`, `next_page`, `total_count`
- `fetched_count`, `accepted_count`, `skipped_count`
- `started_at`, `finished_at`, `error_summary`
- 생성·수정 시각

같은 소스에는 동시에 하나의 `RUNNING` 작업만 허용한다. 예약 작업은 완료된 최신 실행의 `finished_at + 90일` 전에는 외부 요청을 하지 않는다.

### `parking_data_snapshots`

- `id`, `source`, `status` (`STAGING`, `ACTIVE`, `RETIRED`, `FAILED`)
- `source_reference_date_min`, `source_reference_date_max`
- `row_count`, `activated_at`
- 생성·수정 시각

새 데이터는 `STAGING`에 적재한다. 전체 페이지 수집과 품질 검사를 통과한 뒤에만 한 트랜잭션에서 기존 `ACTIVE`를 `RETIRED`, 새 스냅샷을 `ACTIVE`로 바꾼다.

### `parking_facilities`

- 스냅샷 ID와 원천 관리번호의 복합 고유키
- 명칭, 공영·민영, 노상·노외·부설 유형
- 도로명·지번 주소, 광주·전남 지역 코드
- 위도·경도
- 총 주차면, 장애인 주차구역 여부
- 운영요일과 평일·토요일·공휴일 시작·종료시각
- 무료·유료·혼합·미확인 요금 상태
- 기본시간·기본요금·추가시간·추가요금·일일 최대요금
- 일반인 이용 상태 (`PUBLIC`, `RESTRICTED`, `UNKNOWN`)
- 데이터 기준일과 원천 payload

활성 스냅샷, 지역, 위도·경도 범위 조회 인덱스를 둔다.

### `ev_charging_stations`

- 스냅샷 ID와 원천 충전소 ID의 복합 고유키
- 명칭, 주소, 위도·경도
- 급속·완속 충전기 수와 지원 형식 요약
- 이용 가능시간, 이용자 제한, 주차료 무료 여부, 삭제 여부
- 데이터 기준일과 원천 payload

### `parking_ev_links`

- 주차장 스냅샷·관리번호와 전기차 스냅샷·충전소 ID
- 관계 (`ONSITE_CONFIRMED`, `NEARBY_ONLY`)
- 연결 방식과 연결 신뢰도

`ONSITE_CONFIRMED`는 주소 정규화가 일치하고 명칭 또는 시설 관계가 확인된 경우만 부여한다. 좌표만 가까우면 `NEARBY_ONLY`이며 `주차장 내 충전기`로 표시하거나 전기차 필수 조건을 만족시키지 않는다.

## 데이터 신뢰도 게이트

신뢰도는 필드별로 판단한다.

### 대표 추천 필수 조건

- 좌표가 광주·전남 유효 범위 안에 있다.
- 주소 지역과 좌표 지역이 크게 어긋나지 않는다.
- 일반인이 이용 가능한 주차장이며 전용·폐쇄·삭제 상태가 아니다.
- 예상 입차부터 마지막 장소 이용 후 30분까지 운영시간 안에 있다.
- 원천 데이터 기준일을 파싱할 수 있다.

위 조건을 통과하지 못하면 대표 추천에서 제외한다.

### 정보 등급

- `A`: 필수 조건을 통과하고 운영시간·주차면·요금 정보가 모두 있다.
- `B`: 필수 조건을 통과하지만 주차면 또는 요금 정보가 일부 없다. 대표 추천은 가능하되 `면수 확인 필요` 또는 `요금 확인 필요`를 반환한다.
- `C`: 필수 조건 중 하나가 불확실하다. 참고 후보로만 보존하고 대표 추천에는 사용하지 않는다.

수집일이 아니라 원천 `데이터 기준일`로 신선도를 판단한다. 기준일이 18개월을 넘으면 `C`로 내린다. 12~18개월은 `B`로 제한한다.

## 거리 계산

초기 구현은 하버사인(Haversine) 직선거리에 보행 보정계수 `1.25`를 곱해 예상 도보거리로 사용한다. 결과는 10m 단위로 반올림한다. 강·철도·진입 불가 도로를 반영하지 못하므로 `실제 도보거리`라는 표현은 금지한다.

### 한 곳 주차

- `d1`: 주차장부터 첫 번째 장소까지 예상 도보거리
- `d2`: 두 번째 장소부터 같은 주차장까지 예상 도보거리

두 장소 사이 거리는 모든 동일 음식 코스 후보에 공통이므로 주차장 간 순위 계산에서는 제외하고, 전체 코스 시간에는 포함한다.

```text
거리 부담 = 0.65 × max(d1, d2) + 0.35 × mean(d1, d2)
```

가장 긴 구간을 강하게 반영해 `50m / 850m`보다 `430m / 450m`를 우선한다.

기본 추천 자격은 `max(d1, d2) <= 800m`다. 광주·전남 저밀도 지역에서 후보가 없을 때만 1,200m까지 확장하고 `도보거리 김` 경고를 붙인다. 비 오는 날 또는 아이 동반 조건은 최대 구간을 500m로 낮춘다.

### 근거리 후보군

거리 부담이 가장 낮은 후보를 기준으로 다음 조건을 모두 만족하는 주차장만 같은 거리권으로 묶는다.

- 최장 구간이 최적 후보보다 150m 이내
- 두 구간 합이 최적 후보보다 250m 이내

공영 여부, 주차 면수, 전기차, 요금은 이 후보군 안에서만 순위를 바꿀 수 있다. 따라서 먼 공영주차장이나 대형 주차장이 가까운 주차장을 역전하지 않는다.

### 근거리 후보군 안의 비교 순서

1. 공영 또는 검수된 매장 무료 주차
2. 주차 면수
3. 요청된 전기차 조건
4. 예상 체류시간 기준 주차비
5. 운영 종료 여유시간
6. 원천 데이터 기준일

주차 면수는 `log1p(min(totalSpaces, 300))`로 포화시킨다. 300면 이상은 같은 수준으로 취급한다. 누락 면수는 0면으로 보지 않고 비교에서 불리한 `미확인`으로 둔다.

전기차가 `REQUIRED`이면 `ONSITE_CONFIRMED` 충전기가 있는 후보만 남긴다. `PREFERRED`이면 같은 거리권에서 우선하고, `NONE`이면 순위에 영향을 주지 않는다.

### 요금 계산

예상 체류시간에 기본요금과 올림 처리한 추가 단위요금을 적용한다. 일일 최대요금이 있으면 더 작은 값을 사용한다. 무료로 명시된 경우만 0원이다. 필드 누락이나 파싱 실패는 `null`이며 무료로 취급하지 않는다. 자정 통과, 공휴일, 일일 최대요금 경계를 테스트한다.

## 장소별 주차

- 첫 주차장에 주차하고 첫 장소 이용 후 같은 주차장으로 복귀한다.
- 차량으로 둘째 주차장까지 이동해 주차하고 둘째 장소 이용 후 같은 주차장으로 복귀한다.

```text
총 예상 도보거리 = 2 × distance(첫 주차장, 첫 장소)
                  + 2 × distance(둘째 주차장, 둘째 장소)
```

입차·출차·주차 탐색을 두 번 수행하므로 한 곳 주차보다 7분의 고정 처리비용을 더한다. 두 주차장 후보를 각각 상위 10개로 제한한 뒤 최대 100개 조합만 비교한다.

각 주차장은 한 곳 주차와 같은 신뢰도·운영시간·전기차·요금 규칙을 적용한다. 전기차 필수 조건은 두 주차장 중 적어도 한 곳에서 `ONSITE_CONFIRMED`를 만족하고, 그 주차장에서의 예상 체류시간이 사용자가 지정한 최소 충전시간 이상이어야 한다.

## 두 방식 비교

한 곳 주차 최적안과 장소별 주차 최적안을 독립적으로 만든 뒤 다음 정규화 점수로 비교한다.

- 주차장과 장소 간 총 접근거리: 45%
- 예상 전체 소요시간: 25%
- 예상 주차비: 15%
- 추가 입출차·주차 탐색 부담: 15%

비 오는 날·아이 동반은 접근거리 비중을 60%로 올리고 시간 20%, 요금 10%, 처리 부담 10%로 조정한다. 예상 주차시간이 3시간 이상이면 요금 비중을 25%로 올리고 접근거리 40%, 시간 20%, 처리 부담 15%로 조정한다.

두 방식의 정규화 점수 차이가 5점 미만이면 하나를 임의로 확정하지 않고 `BOTH_SIMILAR`를 반환한다. 그 외에는 높은 방식을 `RECOMMENDED`, 다른 방식을 `ALTERNATIVE`로 반환한다.

## 서비스 경계

`recommendParkingForCourse`는 다음을 입력받는다.

- 첫 장소 ID·좌표
- 두 번째 장소 ID·좌표
- 코스 시작시각과 장소별 예상 체류시간
- 조건 (`weather`, `childAccompanied`, `evRequirement`, `minimumChargeMinutes`)

서비스는 두 장소를 둘러싼 제한된 경계상자에서 활성 스냅샷의 `A`·`B` 주차장만 일괄 조회한다. 결과에는 다음을 반환한다.

- 한 곳 주차 추천안과 장소별 주차 추천안
- 추천 방식과 대안 또는 `BOTH_SIMILAR`
- 거리·시간·예상 요금·주차면·공영·전기차·운영시간 근거
- 누락 정보 경고
- `algorithmVersion: parking-course-v1`
- 사용한 주차장·전기차 스냅샷 ID와 기준일

알고리즘은 외부 의존성이 없는 순수 함수와 D1 조회·운영시간 해석·요금 계산 경계를 분리한다.

## 90일 동기화

기존 일일 Cron에 `runScheduledParkingSync`를 추가한다.

1. 각 소스의 최신 정상 완료시각을 조회한다.
2. 90일이 지나지 않았고 실행 중 작업이 없으면 외부 API 호출 없이 종료한다.
3. 실행 중 작업이 있으면 저장된 다음 페이지부터 제한된 페이지를 처리한다.
4. 새 실행이 필요하면 `STAGING` 스냅샷과 실행 기록을 만든다.
5. 한 번의 예약 실행에서 소스별 최대 3페이지만 처리한다.
6. 전체 수집 후 광주·전남 행 수, 유효 좌표율, 중복률, 이전 활성 스냅샷 대비 행 수를 검사한다.
7. 행 수가 이전의 70% 미만이거나 유효 좌표율이 90% 미만이면 활성화하지 않고 실패 처리한다.
8. 검사를 통과하면 새 스냅샷을 원자 활성화한다.
9. 한 번 누락된 원천 ID는 바로 삭제하지 않는다. 다음 두 번의 정상 스냅샷에서도 연속 누락됐을 때만 서비스 후보에서 제외한다.

API 실패 시 기존 활성 스냅샷을 계속 사용한다. 실패 원인은 `parking_sync_runs.error_summary`에 보존한다. 추천 요청에는 외부 장애가 전파되지 않는다.

## 검증 기준

### 단위 테스트

- 200m 민영주차장이 900m 공영주차장보다 우선한다.
- `430m / 450m`가 `50m / 850m`보다 우선한다.
- 같은 거리권에서 공영·무료, 면수, 전기차, 요금 순으로 비교한다.
- 500면이 100면을 압도하지 않고 300면에서 포화된다.
- 요금 누락을 무료로 계산하지 않는다.
- 장소별 주차에서 각 장소 이용 후 주차장 복귀 거리를 포함한다.
- 장소별 주차에 7분의 추가 처리비용이 적용된다.
- 자정 통과, 토요일, 공휴일, 출차 30분 여유를 검증한다.
- 전기차 `REQUIRED`와 `PREFERRED`를 구분한다.
- `NEARBY_ONLY`가 주차장 내 충전기로 오인되지 않는다.
- 두 방식 점수 차가 5점 미만이면 `BOTH_SIMILAR`다.
- 같은 입력과 같은 버전은 항상 같은 결과를 반환한다.

### 통합 테스트

- 정상 스냅샷만 추천 조회에 사용한다.
- 90일 이전 예약 실행은 외부 fetcher를 호출하지 않는다.
- 90일 이후 실행은 저장된 페이지부터 재개한다.
- 부분 API 실패가 기존 활성 스냅샷을 유지한다.
- 행 수 급감과 낮은 좌표율이 새 스냅샷 활성화를 막는다.
- 광주·전남 외 데이터가 저장되지 않는다.
- API 키가 URL에 이중 인코딩되지 않는다.
- 원천 기준일로 정보 등급을 산정한다.
- 조건이 없는 `/courses` 로더는 결과를 계산하지 않는다.
- 코스 추천은 공개 장소와 활성 세부 카테고리만 사용한다.
- 카페·디저트 후보가 1.5km 안에 없으면 3km까지 확장한다.
- 주차 스냅샷이 없어도 음식 코스를 반환한다.

### 화면 검증

- 모바일 첫 진입에서 조건 바텀시트가 자동으로 열린다.
- 조건 적용 후 URL과 결과 요약이 일치한다.

- 키보드 포커스가 보이고 모션 감소 설정에서 전환 효과가 제거된다.

### 회귀 검증
