# 분류 신뢰도 점수 고도화 설계

## 목적

공공데이터 후보의 상호명, 원천 세부업태, 넓은 음식 계열, 공공데이터 종류를 서로 다른 강도의 근거로 평가한다. 현재처럼 넓은 업태가 다르다는 이유만으로 즉시 `CONFLICT`를 만들지 않고, 가장 구체적인 근거의 강도와 경쟁 후보와의 점수 차이를 함께 사용한다.

이번 변경은 분류 신뢰도 알고리즘에만 한정한다. 관리자 화면, 데이터베이스 구조와 데이터, 카테고리 키워드 목록, 배포 설정은 변경하지 않는다.

## 현재 문제와 원인

현재 규칙은 상호의 음식 표현 100점, 원천 세부업태 음식 표현 70점, 넓은 업태 30점, 공공데이터 기본값 5점으로 점프한다. 이후 구체 음식의 그룹과 `한식·일식·양식·분식` 그룹이 다르면 근거의 구체성을 비교하지 않고 `CONFLICT`를 반환한다.

따라서 `사계순대 + 한식`이나 `스시하루 + 한식`처럼 상호의 구체 음식명이 명확한 경우에도 충돌이 발생한다. 또한 AI 결과가 없거나 실패하면 규칙 근거가 충분해도 신뢰도를 `MEDIUM`으로 낮춰, 분류 정확도와 외부 확인 수단의 가용성을 한 값에 섞고 있다.

## 선택한 접근

가중 근거 점수와 1·2위 후보 간 점수 차이를 사용한다. 학습 모델은 승인·오분류 표본이 충분히 쌓이기 전까지 도입하지 않는다. 단순 예외 추가 방식도 카테고리 증가에 따라 조건문이 계속 늘어나므로 사용하지 않는다.

## 규칙 점수

각 근거의 기본 강도는 다음과 같다.

| 근거 | 기본 점수 |
| --- | ---: |
| 상호의 구체 음식 표현 (`NAME` + `FOOD`) | 80 |
| 상호의 영업 형태 표현 (`NAME` + `VENUE`) | 74 |
| 원천 세부업태의 구체 음식 표현 (`SUBTYPE` + `FOOD`) | 65 |
| 원천 세부업태의 영업 형태 (`SUBTYPE` + `VENUE`) | 45 |
| 원천의 넓은 음식 계열 (`SUBTYPE` + `CUISINE`) | 35 |
| 공공데이터 종류의 기본값 (`SOURCE`) | 15 |

규칙에 기존 `priority`가 있으면 최대 10점의 작은 보너스로 환산한다. 같은 slug의 두 번째 이후 근거는 기본 점수의 30%만 더하고, 같은 그룹의 넓은 업태는 최대 6점의 보조 근거로 더한다. 최종 규칙 점수는 0~100으로 제한한다.

후보 순서는 최종 점수가 높은 순서다. 구체 음식 신호는 넓은 업태와 공공데이터 기본값보다 항상 우선한다.

## 충돌 판정

충돌은 다음 조건을 모두 만족할 때만 발생한다.

1. 서로 다른 slug를 가리키는 구체 근거가 2개 이상이다.
2. 두 근거가 각각 65점 이상이다.
3. 두 구체 근거의 점수 차이가 20점 이하이다.

`한식·일식·양식·분식` 같은 `CUISINE` 신호와 공공데이터 기본값은 충돌 후보에서 제외한다. 따라서 넓은 업태가 상호의 구체 음식 계열과 다르다는 사실만으로 감점하거나 충돌시키지 않는다.

## 신뢰도 등급

충돌이 없을 때 최종 규칙 점수를 다음 등급으로 변환한다.

| 점수 | 등급 |
| --- | --- |
| 78~100 | `HIGH` |
| 50~77 | `MEDIUM` |
| 0~49 | `LOW` |

내부 분류 결과에 `confidenceScore`를 추가해 0~100 점수를 보존한다. 기존 소비자는 `HIGH·MEDIUM·LOW·CONFLICT` 등급을 계속 사용하므로 UI나 DB 변경이 필요하지 않다.

## AI 보정

AI는 규칙 신뢰도를 대신하지 않고 보조 검증만 한다.

- AI가 없거나 실패하면 규칙의 `confidenceScore`와 등급을 그대로 유지한다. 자동 승인 가능 여부는 계속 `false`다.
- 검증된 AI가 규칙과 일치하면 AI confidence에 따라 최대 10점을 더한다. AI confidence 0.85 이상이고 보정 후 `HIGH`일 때만 기존 자동 승인 조건을 만족한다.
- AI가 다르고 confidence가 0.85 미만이면 규칙 카테고리를 유지하며 점수만 10점 낮추고 수동 확인한다.
- AI가 다르고 confidence가 0.85 이상이면 `CONFLICT`로 보내되 규칙 카테고리를 임의로 AI 결과로 교체하지 않는다.
- AI evidence 검증과 허용 slug 검사는 기존 정책을 유지한다.

AI 장애 여부는 기존 `AI_FAILED` 상태로 별도 표시한다. 장애가 분류 근거의 품질을 낮추지는 않는다.

## 대표 사례

| 입력 | 예상 결과 |
| --- | --- |
| `사계순대` + `한식` | 구체 음식명 우선, `HIGH` |
| `전주해장국` + `한식` | 이름과 같은 그룹의 업태가 보조, `HIGH` |
| `스시하루` + `한식` | 스시 우선, `HIGH`; 넓은 한식 업태는 충돌 아님 |
| `타코야끼앤버거` + `한식` | 두 구체 음식 신호가 동급이라 `CONFLICT` |
| `맛있는집` + `한식` | 넓은 업태와 기본값뿐이라 `LOW` |
| 규칙 `HIGH` + AI 실패 | 규칙 `HIGH` 유지, 자동 승인 불가 |
| 규칙 `HIGH` + 낮은 확률 AI 불일치 | 규칙 유지, 점수 하락, 수동 확인 |
| 규칙 `HIGH` + 높은 확률 AI 불일치 | 규칙 카테고리 유지, `CONFLICT` |

## 코드 경계

- `category-suggestion.ts`: 근거 수집, 후보별 점수 집계, 충돌과 등급 계산
- `ai-classification-policy.ts`: 규칙 점수와 AI 결과의 보정
- `candidate-auto-classification.test.ts`: 대표 상호·업태 조합과 점수 경계 검증
- `ai-classification-policy.test.ts`: AI 없음·일치·약한 불일치·강한 불일치 검증

키워드 정규식과 카테고리 정의는 `category-taxonomy.ts`에 그대로 둔다.

## 검증 기준

1. 구체 상호명과 넓은 업태 불일치가 `CONFLICT`를 만들지 않는다.
2. 서로 다른 구체 음식 근거가 비슷할 때는 기존처럼 `CONFLICT`다.
3. 넓은 업태나 공공데이터 기본값만 있으면 `HIGH`가 되지 않는다.
4. AI 실패가 규칙 점수와 등급을 낮추지 않는다.
5. 높은 신뢰도의 AI·규칙 일치만 자동 승인 가능하다.
6. 기존 분류·AI 정책·통합 테스트가 모두 통과한다.

## 운영 영향

마이그레이션, 환경 변수, 운영 DB 변경은 없다. 현재 검수 대기 데이터는 화면을 다시 조회할 때 새 알고리즘으로 계산되며, 이미 승인된 장소는 변경되지 않는다.
