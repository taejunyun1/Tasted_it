# Re:Taste 개인정보 처리방침 제작 가이드

## 기준 자료

- 기준 저장소: <https://github.com/kimlawtech/korean-privacy-terms>
- 적용 흐름: 한국 사용자 대상 `privacy-kr`
- 현재 확인 버전: 저장소 README 기준 v4.1.0 (확인일 2026-08-05)
- 라이선스: Apache-2.0

실제 문서를 생성할 때에는 최신 배포본을 다시 확인하고 사용한 태그 또는 커밋 SHA를 이 문서에 기록한다. 저장소가 제공하는 결과는 법률 자문이 아닌 초안이므로 실서비스 및 결제 출시 전에 법률 전문가 검토를 받는다.

## Re:Taste 적용 원칙

1. 템플릿보다 실제 시스템 동작이 먼저다. 코드, D1 스키마, Cloudflare 설정, 분석·이메일·결제 공급자를 조사한 데이터 인벤토리를 기준으로 문구를 채운다.
2. 수집하지 않는 항목은 관행적으로 기재하지 않는다. 새 수집 항목이나 외부 처리자가 생기면 코드 배포와 방침 개정을 같은 릴리스에서 처리한다.
3. 위치 권한은 `내 주변`을 누른 뒤에만 요청한다. 위치의 서버 전송·저장 여부와 사용 목적을 정확히 명시한다.
4. 개인정보 처리방침과 이용약관은 `/privacy`, `/terms`에서 비로그인 사용자도 열람할 수 있게 하고 전역 푸터, 로그인, 앱 스토어 메타데이터에서 연결한다.
5. 변경일, 시행일, 이전 버전 보관 위치를 표시하고 중요 변경은 시행 전에 공지한다.

## 출시 전 데이터 인벤토리

| 영역 | 확인할 데이터 | 현재 베타 기준 |
|---|---|---|
| 계정 | 이메일, 표시 이름, 역할 | D1 저장 |
| 인증 | 불투명 세션 ID, 생성·만료 시각 | 쿠키 + D1, 7일 |
| 활동 | 추천·비추천 이벤트와 현재 투표 | D1 저장 |
| 개인화 | 저장 장소 | D1 저장 |
| 위치 | 브라우저 현재 위치 | 명시적 요청 후 사용, 저장 여부 검증 필요 |
| 운영 | 접속·오류·보안 로그 | Cloudflare 실제 보존 설정 확인 필요 |
| 결제 | 주문자, 견적, 결제·환불 기록 | 결제 도입 시 추가 |

## 배포 게이트

- 사업자/운영자 명칭, 주소, 개인정보 보호책임자, 이메일 등 실제 연락처 확정
- 수집 항목·목적·법적 근거·보유기간·파기 절차 확정
- 처리위탁 및 국외 이전 대상과 Cloudflare 리전·정책 확인
- 이용자 열람·정정·삭제·처리정지 및 계정 삭제 요청 절차 확인
- 만 14세 미만 정책, 쿠키·분석, 마케팅 동의의 해당 여부 확인
- 앱 권한 설명과 Apple/Google 개인정보 표시의 문서 일치 확인
- 결제사 도입 시 전자상거래 보존기간, 환불, 영수증 관련 항목 추가
- 템플릿 자리표시자 전수 검색 및 제거
- 법률 전문가 최종 검토 기록 보관
