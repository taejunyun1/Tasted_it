# 통합 기록 감사 운영 문서

작성일: 2026-08-14  
적용 범위: 평가·리뷰 사진·Golden Pick·보존기간·추천 적격성의 읽기 전용 기준선 감사

## 운영 경계

- 감사는 문제를 **찾고 기록**하는 절차이며, 어떤 데이터도 자동으로 수정·삭제·복원하지 않는다.
- 운영 환경 실행은 승인된 Pull Request가 `main`에 병합된 뒤, 권한 있는 운영자가 수행한다.
- 감사 화면 `/admin/audit`은 ADMIN 역할만 접근할 수 있으며, 이메일·사진 object key·원문 메타데이터·주소·토큰은 표시하지 않는다.
- 감사 결과는 비식별 표본 ID와 집계만 포함한다. 결과 파일을 외부에 공유할 때도 원문 로그나 화면 캡처를 덧붙이지 않는다.

## 사전 확인

1. 실행 대상이 production인지 preview인지, 실행자와 변경 티켓/PR 번호를 기록한다.
2. 배포된 커밋을 확인한다.

   ```bash
   git rev-parse --short HEAD
   ```

3. 운영 DB에 대해 쓰기·migration·seed 명령을 실행하지 않는다. 이 기준선에는 D1 변경, R2 조회, 외부 API 호출이 없다.
4. ADMIN 계정으로 `/admin/audit`을 열어 생성 시각, 커밋 식별자, 결과 상한 도달 여부를 확인한다.

## 결과 판독과 조치

| 영역 | 예시 발견 | 기본 조치 |
| --- | --- | --- |
| 평가 | 현재 평가와 마지막 유효 이벤트 불일치 | 해당 place/user 표본을 별도 복구 작업으로 격리하고 원인을 조사한다. |
| 리뷰 사진 | 사진 수·순번 불일치 | 공개 경로를 확인하고 사진 메타데이터 복구 PR을 만든다. R2 객체 키는 감사 결과에 포함하지 않는다. |
| Golden Pick | 만료된 grant가 종료 이벤트 없이 남음 | 기간 만료·철회 이력을 확인하고 전용 정합성 복구 절차를 승인받는다. |
| 보존기간 | 만료 guest session 또는 product event 잔존 | 보존 작업의 실행 상태를 조사하고 전용 cleanup 작업으로 처리한다. |
| 추천 적격성 | HIDDEN인데 추천 제외가 아님 | 일반 공개 상태를 바꾸지 말고 liveness 운영 절차의 복구 흐름을 따른다. |

`결과 상한 도달`은 정상 판정이 아니다. 쿼리 상한을 늘리거나 안전한 분할 감사 계획을 먼저 PR로 승인받는다. 기준선 화면의 결과만으로 대량 수정·삭제를 실행하지 않는다.

## 감사 기록

실제 감사가 끝난 뒤에만 아래 파일을 새로 만든다.

```text
docs/audits/YYYY-MM-DD-record-audit-baseline.md
```

기록에는 아래 정보만 남긴다.

```text
실행 시각 (KST):
실행 환경:
실행자:
배포 커밋:
PR/Issue:
감사 버전:
각 심각도 건수:
쿼리 상한 도달 여부:
발견별 후속 PR 또는 incident:
개인정보·원문 응답 미포함 확인:
```

ID 표본은 화면에 이미 마스킹된 값만 기록한다. 이메일, 사용자 ID 전체값, 사진 URL/object key, 주소, 원문 JSON, 외부 API 응답, 세션·토큰은 절대 기록하지 않는다.

## 실패와 중단

- 권한 없음·서버 오류·상한 도달이면 결과를 정상으로 해석하지 않고 실행을 중단한다.
- 감사 코드나 배포 자체가 의심되면 사용자 데이터 복구를 시도하지 말고, 배포를 이전의 정상 `main` 커밋으로 되돌릴 승인 절차를 시작한다.
- 발견된 정합성 문제의 수정은 별도 feature branch·PR·테스트를 통해서만 수행한다. 감사 실행과 수정 작업을 한 번의 운영 명령에 섞지 않는다.

## 금지 사항

- 감사 중 production D1 migration, seed, UPDATE/DELETE/INSERT 실행
- R2 사진 객체를 표본 확인 목적으로 직접 열람·다운로드
- 실제 사용자 이메일·원문 메타데이터·토큰을 감사 문서나 GitHub Issue에 복사
- 감사 발견을 근거로 승인 없이 장소 공개 상태·평가·리뷰·추천 상태를 즉시 변경
