## 변경 계약

한 번에 최대25개를 미리보기하고 처리 예정/사전 제외 사유를 구분한다. 확정은 현재 ADMIN·최근10분 재인증·같은 세션, 대상/version과 원천 근거를 다시 검사한다. 처리 예정 대상 하나가 달라지면 해당 D1 배치 전체를 롤백하고 적용0/충돌로 표시한다. 성공은 실제 commit/audit가 연결된 영수증으로 재조회하며, 제외 항목을 성공으로 합산하지 않는다.

리뷰어는 신청 당시 제안 수와 현재 승인 제안 수를 분리한다. 기존 신청 당시10개/명시적 예외 승인 기준을 유지하고, 상태 변경은 ADMIN 역할과 명시적 콘텐츠 회수 상태를 보존한다. 기존 승인 자료의 노출 적격성이 활동 상태에 따라 바뀔 수 있음을 미리보기에서 설명한다.

학생은 좌석 소유자·활성·기한·capability와 작업 version을 보존·검사한다. 초대 원문은 최초 성공 응답의 메모리에서만 제공하며 payload/result/audit·새로고침·중복 확정에서는 재표시하지 않는다. 발급은 실제 전달 완료가 아니다. 배정 취소는 원문·revision·담당 이력을 삭제하지 않는다.

## migration과 배포

1. 두 기능 PR의 필수4CI·독립 리뷰를 확인하고 순서대로 squash merge한다. 마지막 병합 main만 primary checkout에서 빌드한다. 새 dependency/provider/cron0, production 의존성 audit와 `wrangler deploy --config build/server/wrangler.json --dry-run`을 확인한다.
2. 운영 version·대기 migration과 파일 hash를 확인한다. 대기는 `0048_admin_people_contract.sql` 한 개다. 사전 기록은0700 private 디렉터리/0600 파일에 보관한다. SQL 조회는 실제 행 반환을 확인하고 Wrangler 실행 요약을 데이터로 비교하지 않는다.
3. 같은 빌드 설정을 같은 디렉터리의 점검 설정으로 복사해 `CST_MAINTENANCE=true`, `assets.run_worker_first=true` 두 필드만 바꾼다. 배포 후 공개·로그인·관리자·정적자산·RSI의503/no-store를 확인하고 최소60초 drain한다. 저장 로그의 이전 호출/예약 실행 종료를 대조하며 미확인 실행이 있으면 migration을 적용하지 않는다.
4. fence에서 D1 Time Travel bookmark와 export1개를 비공개 보관한다. 기존 사용자/장소/평가·학생·리뷰어 집계와 행 digest, operations/commits/checks/audit 전체 정렬 digest를 수집한다. 0048은 작업 이력3테이블을 보존해 kind2개를 추가하고 신청/프로필/좌석 version을0으로 추가한다. 기존 데이터 내용은 바꾸지 않는다. local migration 이력/rowid/FK/기존 trigger 보존 증거를 먼저 확인한다.
5. `pnpm exec wrangler d1 migrations apply DB --remote`로0048을1회 적용한다. 실패 시 fence를 유지하고 실제 적용 상태부터 확인한다. pending0·FK위반0, 작업/감사 이력 digest 동일, 기존 필드 digest 동일과 새 version0을 확인한다. 새 version 컬럼을 빼고 기존 필드를 비교한다.
6. 같은 빌드의 정상 설정으로 배포하고 새 version100%·공개 응답을 확인한다. 이력/권한 불일치 시 정상 공개로 전환하지 않는다. 두 도메인이 모두 병합되기 전에 개별 기능을 운영에 배포하지 않는다.

## 필요한 live와 한도

- 기존 `OPERATOR_ADMIN_PROVISIONED` 감사가 유일하게 지정한 비탈퇴·미제한·인증 ADMIN에 임시30분 세션1개만 만든다. 최근 인증 보증은 만들지 않으며 실제 계정의 비밀번호/역할/학생 좌석/리뷰어 자격을 바꾸지 않는다.
- 두 관리자 화면의 목록·상태·version·개별/일괄 미리보기, 잘못된 입력/익명/교차 출처 거절, 재인증 없는 확정 거절과 연결된 B06 kind 필터를 확인한다. 기존 적격 대상이 있으면 단일 읽기/미확정 preview만 사용한다. 대상이 없으면 빈 상태를 확인하며 운영용 신청/프로필/좌석/업무를 만들어 양성 사례를 만들지 않는다.
- 초대 발급/재발급·배정/취소·리뷰어 승인/휴면/정지는 로컬 D1/합성 UI에서 양성·경합을 검증한다. 운영에서는 실제 발급·메일·실제 학생/리뷰어 변경0이다. 원문 토큰이 목록/영수증/감사에 없음을 확인하고, 현재 로그인 사용자 ID와 도메인 상세의 정상 정보까지 누출로 오인하지 않는다.
- 실제 Worker RSI ADMIN POST1회(재시도0), 고정6경로·감사1행·같은 Worker 로그 종료를 확인한다. 점검 중 skip은 성공으로 세지 않는다. 정상 공개/상세/TEMP 대표사진은 읽기 smoke만 한다.
- finally에서 이번 임시 세션과 이번 미확정 preview의 정확 ID만 삭제하고 잔존0을 확인한다. 기존 만료 preview의 B02 정상 정리가 발생하면 별도로 기록한다. 공용 감사/rate-limit 이력은 삭제하지 않는다.
- 누적 수동HTTP70회, D1 데이터/관리 조회70회, export1·migration1·임시ADMIN세션1·RSI1회가 상한이다. 클라이언트 판정 오류 교정은 같은 세션/원래 만료·남은 한도에서만 하며 최초 실패를 보존한다. 한도나 임시 객체를 임의로 늘리지 않는다.

## 복구와 기록

이전 Worker는 새 version을 인식하지 못하고 위험 작업을 바로 실행할 수 있으므로 장애 시 동일 schema의 점검 fence로 닫고 전진 수정한다. 전체 DB복원·이력 삭제·기존 초대 재발급은 이번 범위가 아니다. 백업 사본 확보를 실제 복원 성공으로 표현하지 않는다.

병합·운영 배포·로컬 양성 검증·한정 live 결과를 각각 기록해 CST SSOT와 위키에 반영한다. B08 완료를 전체 ADMIN·전체T01–T08·현장실증 완료로 확대하지 않는다. 문서만 갱신한 최종 PR은 다시 운영 배포하지 않는다.
