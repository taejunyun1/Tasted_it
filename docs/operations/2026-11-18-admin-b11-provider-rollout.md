# B11.1 공급자 사용량 원장 전환

상태: 구현·로컬 검증 / 운영 HOLD. 아래 0053 단독 절차는 당시 검토 기록이다. 전환은 [B17 부분 적용 기준](2026-11-18-admin-b17-rollout.md)을 반영한 별도 운영 PR의 승인을 따른다. NAVER quota는 독립 종료 근거와 아래 전환 조건을 충족할 때까지 HOLD다. #397은 계속 보류한다.

## 변경 범위

- 기존 NAVER 서버 지역검색 전송 전에 D1에서 전역·지역 사용량을 함께 예약한다. 전역 상한은 설정값과 20,000 중 작은 값이며, 지역별 상한은 기존 10,000을 유지한다. 숫자가 잘못된 설정은 호출을 차단한다.
- 최초 전송과 재시도는 각기 예약을 소비한다. 전송 표식, 응답 성공·실패·불명, 예약 뒤 중단을 분리한다. 이미 소비한 예약은 반환하지 않는다.
- `provider_daily_quotas`, `provider_call_attempts` 2개 테이블을 추가한다. 기존 `naver_local_category_runs`는 삭제·재작성하지 않는다. 호출 요약은 새 dispatch 표식의 합계이며, 공급자 수신·청구의 증거로 표현하지 않는다.
- `/admin/providers`는 관리자만 읽을 수 있으며 외부 요청이나 설정 변경이 없다. 과거 실행이력 추정·새 예약·전송 표식·응답 결과를 구분하고, 계약상 무료 잔여·금액은 미확인으로 표시한다.
- 공공 인허가 `request_count`는 B10 이후 기록된 전송 시도만 보여 준다. 이전 수집 레코드 수를 호출 수로 환산하지 않는다. 주차·EV에는 저장된 전송 카운터가 없어 미측정으로 표시한다.

## 운영 적용 전제와 순서

대상은 기존 `wrangler.jsonc`가 가리키는 Worker와 D1 `DB` 바인딩이다. 신규 서비스·자격정보·요금제·cron·binding을 만들지 않는다. B10 변경과 0050~0052가 운영에 적용된 상태에서 **0053_provider_usage.sql 하나**를 적용한다.

1. 최신 병합된 main을 사용하고 Worker의 이전 버전과 D1 migration 목록을 확인한다. 0050~0052가 미적용이면 이 절차를 시작하지 않고 B10 절차를 먼저 완료한다.
2. 기존 NAVER 검색을 중지한 전환 상태와 구 Worker 실행 종료의 근거를 보존한다. 이전 실행이 끝났다는 근거 없이 새 원장을 READY로 만들지 않는다.
3. 로컬 비공개 운영 기록에 기존 NAVER run의 행 수·원본 필드 대조 결과, UTC 날짜·지역별 합계, invalid timestamp/음수 count/알 수 없는 지역이 없는지 기록한다. 개인·장소·원문 query·키는 PR과 위키에 복사하지 않는다.
4. `pnpm exec wrangler d1 migrations list DB --remote`에서 추가 미적용 migration이 0053 하나인지 확인한 후 `pnpm exec wrangler d1 migrations apply DB --remote`를 실행한다. migration은 기존 run을 UTC 날짜로 한 번만 집계하고, NULL 지역은 각 지역에 보수적으로 귀속한다. 오류 자료를 임의 보정하지 않는다.
5. 이전 run의 행 수와 원본 필드가 그대로인지, 새 원장 기준선이 일치하는지, FK 오류가 0인지 확인한다. 전환일 anchor는 `CLOSED_LEGACY_UNCERTAIN`, 검증 시각·허용일·근거는 NULL이어야 한다.
6. 병합된 main에서 기존 빌드·배포 절차를 실행한다. 운영자는 Worker 버전/commit을 기록하고 인증 차단, 관리자 읽기, 개인정보 미노출, 외부 전송 0을 확인한다. 기존 RSI 점검 경로를 한 번 확인한다.

이번 배포와 live 검증에서는 **실제 NAVER 호출·유료 API·메일 발송을 하지 않는다.** 전환일을 자동 허용하거나 날짜 변경을 검증의 대체로 삼지 않는다.

## HOLD 해제는 별도 운영 증거

migration만으로 구 Worker의 실행 종료를 증명할 수 없다. 새 날짜에도 anchor가 검증되지 않았으면 예약은 계속 차단된다. 해제에는 구 실행 종료와 최종 기준선 대조를 기록한 별도 승인 운영 절차가 필요하다. `cutover_verified_at`, `cutover_receipt_ref`, `ready_after_utc_day`를 함께 한정 갱신하며, 허용일은 **검증한 날 다음의 완전한 UTC 날짜 이후**다. NULL·빈 근거와 불완전 anchor는 허용하지 않는다. 이 PR은 근거 없는 해제 SQL을 실행하도록 승인하지 않는다.

## 검증과 복구

필수 검증은 마지막 슬롯 병렬 경합, 실패·UNKNOWN 보존, 중복 정산, UTC 자정 경계, 전환 HOLD, 기존 기준선 보존·NULL 지역 귀속, 모든 서버 검색 소비자 연결, TEMP 예약 거절 복귀, 관리자 읽기 권한과 반응형 화면이다. 독립 리뷰와 필수 CI 통과 뒤 병합한다.

복구 시 원장·영수증을 삭제하거나 이미 소비한 횟수를 되돌리지 않는다. 구 버전으로 되돌리면 원자 예약이 사라지므로 **먼저 `NAVER_LOCAL_SEARCH_ENABLED=false`인 복구 설정을 확인한 뒤** 이전 Worker 버전을 적용한다. 공개 조회 서비스는 유지하고, 새 원장과 HOLD는 보존한다. 금액·계약상 잔여량은 계속 미확인이다.
