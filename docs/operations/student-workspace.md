# 학생 작업공간 운영과 인수

관련: [결정 기록](../decisions/2026-10-15-student-workspace.md), #295. 운영 승인의 원본은 이 계획을 명시한 병합 PR이며, 로컬 시험이나 화면 캡처는 배포 완료 증거가 아니다.

## 2026-10-15 초기 운영 인수

관련 운영 범위와 최종 실행 기록: [Issue #297](https://github.com/taejunyun1/Tasted_it/issues/297).

- [PR #296](https://github.com/taejunyun1/Tasted_it/pull/296)을 `0cf49ef`로 병합하고 지정 운영 계정에 D1 `0037`·`0038`을 적용했다. 최초 false 배포는 `02540a1c-4810-4939-b825-0e4bca6d7aac`, 초기 true 활성화는 `34d297d6-1ea5-4bbd-91ef-da37fa9ca6b7`이다. 활성화 단계의 rollback은 직전 false 버전이다.
- 사용자 요청으로 Cloudflare 운영 권한을 이용해 **별도 운영 ADMIN 1개**를 준비했다. 기존 해시 함수를 사용하는 강한 무작위 비밀번호와 운영자 초기 인증 상태로 생성하고 `OPERATOR_ADMIN_PROVISIONED` 감사 이력을 남겼다. 개인 서비스 계정의 역할은 유지했다. 이 운영 ID는 수신 메일함이 없는 로컬 로그인 전용이며 일반 학생의 이메일 인증 절차를 대신하지 않는다. 자격증명은 사용자 비공개 로컬 전달 파일에만 보관한다.
- 실제 관리 화면에서 A~D 초대를 각각 한 번, 총 4개 발급했다. 원문과 DB SHA-256 digest가 각각 일치하고, digest 4개가 서로 다르며, 모두 미사용·미취소·미만료다. 개인 계정과 연결된 좌석은 0개다. 초대 원문은 소스·위키·이슈·PR·화면 증거에 넣지 않는다.
- 일반 회원의 학생·관리자·미배정 작업 차단 화면, 별도 ADMIN의 실제 로그인과 초대 발급, 더미 토큰을 이용한 ADMIN의 학생 참여 거부와 fragment 제거를 확인했다. 실제 A~D 링크는 시험 수락에 쓰지 않았다. 학생의 실제 가입·수락·제출·교차 확인은 추후 실제 학생 참여 때 확인할 **PENDING** 항목이다.
- 초기 활성화 HTTP 상태 10건은 기대값과 일치했으나 미인증 학생 세 경로의 302에서 캐시 금지 헤더가 없었다. 이 변경은 Worker 최종 응답에서 학생 경로와 single-fetch `.data` 요청에 `no-store, private`와 `same-origin`을 강제한다. 회귀 24개, 전체 unit 937개, integration 393개, typecheck·build를 통과했다. 이 수정의 실제 배포 버전과 최종 HTTP 결과는 병합 후 #297과 위키 실행 기록에 남긴다.
- 새 배포의 `RSI_SELF_CHECK` 경로별 결과는 아직 **PENDING**이다. 기존 cron의 2026-10-15 00:47:43 UTC 호출 성공은 새 배포 이전이다. 다음 기존 RSI 예정은 2026-10-15 06:47 UTC(15:47 KST)이며, 예정만으로 성공을 주장하지 않는다. 새 토큰·스케줄·AI·사진 업로드 설정은 추가하지 않았다.

현재 저장소 학생 스위치는 true다. 공개 베타·개인정보 잔여 게이트 및 업로드 AI 검사 도입안은 별도 상태를 유지한다.

## 화면과 일상 운영

- 운영 ADMIN: `/admin/students`에서 A~D 개별 초대 발급. 새 링크는 해당 action 응답에서만 원문을 볼 수 있으므로 해당 학생에게만 전달한다. 일반 문서·소스·위키·PR·이슈·화면 증거에 붙이지 않는다.
- 학생: 전달된 `/student/join#<개별토큰>`을 열고 개인 가입·이메일 인증·로그인을 새 창에서 마친다. 원래 초대 화면의 로그인 상태 확인 → 본인 계정 확인 → 수락 → `/student` 순서다. 일반 회원 가입 약관과 개인정보 안내를 그대로 따른다.
- 운영자: 점포는 단계·검색·페이지로 찾고 한 건 또는 현재 목록 최대 25건 배정. 리뷰는 아직 배정하지 않은 최근 50건씩 제공되며, 배정 후 다음 자료를 고를 수 있다. QA는 공개 경로를 지정한다. 1차와 교차 확인 학생은 다르게 선택한다.
- 학생: 배정 자료 확인 → 분류와 근거 제출 → 지정 학생의 교차 확인/보완 요청. 최종 검수 조건을 갖춘 신규 점포는 A·B가 서로의 자료에 등록 인가 기록을 남길 수 있다.
- 운영자: 등록 인가를 확인해 기존 `/admin/place-operations?step=5`에서 최신 원천·업종·중복과 수동 근거를 다시 검토하여 공개한다. 학생 기록만으로 공개하지 않는다.
- 참여 중단: 좌석 접근 중지. 미사용 초대는 함께 취소되고 기존 로그인도 학생 경로를 사용할 수 없다. 좌석을 다른 학생에게 넘기는 재연결 기능은 제공하지 않는다. 잘못 연결한 계정은 운영자가 본인 확인 후 별도 변경을 검토한다.

## 배포 전 조건

1. 권한 있는 유지보수 담당자가 PR 코드·새 테이블·권한·아래 운영 범위를 확인하고 병합한다. CI 네 잡, 학생의 데스크톱·모바일 시험과 실제 diff를 확인한다.
2. 지정 운영자가 올바른 Cloudflare 계정을 확인한다. 대상은 현재 저장소 `wrangler.jsonc`의 Worker와 D1, 기존 R2이며 다른 계정에서 명령을 실행하지 않는다. CLI 계정이 일치하지 않거나 D1 권한이 없으면 중지한다. 인증 토큰을 출력하지 않는다.
3. 기존 배포와 `origin/main`의 차이를 검토한다. #290의 기존 출시·개인정보·운영 권한 HOLD를 자동 해제하지 않는다. 이 PR 병합만으로 과거 미배포 변경 전부가 검증된 것으로 보지 않는다.
4. D1 migration 목록을 읽어 새로 실행할 항목이 정확히 `0037_student_invitations.sql`, `0038_student_tasks.sql`인지 확인한다. 더 이전의 미적용 항목이 있으면 이 작업에서 일괄 적용하지 않고 그 항목의 승인·영향을 먼저 확인한다.
5. 현재 Worker version과 D1 Time Travel bookmark/백업을 지정 운영자가 기록한다. 보존기간·학생 안내·시험 계정 준비를 확인한다.

검토용 명령은 병합된 `main`에서만 실행한다. 운영 migration 적용은 아래 순서와 한도를 전제로 한다.

```sh
pnpm exec wrangler whoami
pnpm exec wrangler d1 migrations list DB --remote --config wrangler.jsonc
# 위 목록, 계정, 백업, 승인 범위가 모두 확인된 경우에만:
pnpm exec wrangler d1 migrations apply DB --remote --config wrangler.jsonc
pnpm run build
pnpm run deploy
```

최초 도입은 false 배포 후 공개 HTTP와 기존 RSI 호출 이력을 확인하고 활성화했다. 새 배포의 RSI 경로별 결과는 미확인이다. 2026-10-15 학생 경로를 열면서 지정 운영자가 `STUDENT_WORKSPACE_ENABLED=true`로 활성화했으며, 이번 운영 설정에 true를 반영하여 다음 배포에서도 유지한다. 배포 후 실제 검증의 미실행 항목은 아래 기준대로 PENDING을 유지한다. `REVIEW_PHOTO_UPLOAD_ENABLED`, AI 관련 설정, 기존 두 cron은 바꾸지 않는다.

## 실제 검증과 한도

2026-10-15 추가 인수 시험은 운영 A~D 링크를 보존하기 위해 격리된 Workers/D1에서 수행한다. 실제 signup→이메일 인증→로그인→개별 초대 수락 route를 연결하고 점포·리뷰·QA 제출과 다른 계정의 교차 확인을 검증한다. 외부 이메일 전송만 fake이며 실제 수신함 전달은 이 시험 범위가 아니다. 가입 전 주입한 학생 세션만으로 전체 가입 검증을 대신하지 않는다. 운영 초대는 재발급·수락·취소하지 않고 사전/사후 DB 상태와 전달 파일 hash를 비교한다.

정기 RSI 결과는 [보존 결정](../decisions/2026-10-15-rsi-result-evidence.md)에 따라 기존 운영 감사 테이블에서 확인한다. Cron 성공만으로 6개 경로 통과를 주장하지 않는다. 학생 전체 흐름 시험과 정기 공개 GET RSI는 별도 검증이다.

초기 검증은 동의한 전용 시험 계정으로 한다. 운영 학생 계정에 관리자를 부여하지 않는다.

1. 네 경로의 미인증 접근, 일반 회원의 관리자 거부, 학생의 미배정 대상 거부, 캐시 제한을 확인한다.
2. 초대 하나의 정상 수락·재사용 거부·재발급 이전 링크 거부를 확인한다. 실제 A~D용 링크 발급은 관리자 네 번으로 제한하고 화면에 남은 링크를 별도 공유 공간에 저장하지 않는다.
3. 점포·리뷰·QA 시험 작업 각 1건 이내, 1차·교차 확인·보완·등록 인가·접근 중지를 확인한다. 실제 점포 공개·리뷰 수정·평가 변경·불특정 메일 발송은 이 확인에 포함하지 않는다.
4. DB에는 토큰 digest만 있고 분류·검수 단계·리뷰 원문이 변하지 않았음을 읽기 전용으로 확인한다. 시험 메모에는 개인정보를 넣지 않는다.
5. 배포 후 Workers Observability의 `RSI_SELF_CHECK` 또는 기존 토큰 인증 경로로 라이브 RSI를 확인한다. 기존 RSI는 공개 화면 HTTP 점검이며 학생 권한·업로드 무결성 검증을 대신하지 않는다. 새 스케줄이나 무인 반복 호출을 만들지 않는다.

실제 사용 URL·검증 시각·배포 version·실행 migration·남은 실패를 인수 기록에 남긴다. 한 항목이라도 미실행이면 실제 운영 검증 PENDING을 유지한다.

## 중지와 되돌리기

- 잘못된 접근·초대·자료 노출: 해당 좌석 중지 후 전체 스위치 false. 필요 시 기존 Worker version으로 rollback한다.
- 새 테이블은 additive이므로 삭제하거나 기존 migration을 되감지 않는다. 이력과 관계를 보존하고 후속 PR로 수정한다.
- 별도 운영 관리자 폐기: 해당 신규 계정만 USER로 내리고 비밀번호 해시·salt를 비활성화하며 그 계정 세션을 폐기한다. 계정·감사·학생 이력은 삭제하지 않는다. 실제 식별자는 사용자 비공개 인수 기록으로 확인한다. 수신 메일함이 없는 운영 ID의 비밀번호 복원도 Cloudflare 지정 운영자가 처리한다.
- 프로젝트 종료: 좌석 만료 확인 → 작업 목록과 증빙 인수 → 공식 보존기간에 따른 개인 정보·초대·메모 정리. 성과자료에 실제 건수와 미실시를 분리한다.
