# 학생 작업공간 운영과 인수

관련: [결정 기록](../decisions/2026-10-15-student-workspace.md), #295. 운영 승인의 원본은 이 계획을 명시한 병합 PR이며, 로컬 시험이나 화면 캡처는 배포 완료 증거가 아니다.

## 화면과 일상 운영

- 기존 ADMIN: `/admin/students`에서 A~D 개별 초대 발급. 새 링크는 해당 action 응답에서만 원문을 볼 수 있으므로 해당 학생에게만 전달한다. 문서·소스·위키·PR·이슈·화면 증거에 붙이지 않는다.
- 학생: 전달된 `/student/join#<개별토큰>`을 열고 개인 가입·이메일 인증·로그인을 새 창에서 마친다. 원래 초대 화면의 로그인 상태 확인 → 본인 계정 확인 → 수락 → `/student` 순서다. 일반 회원 가입 약관과 개인정보 안내를 그대로 따른다.
- 운영자: 점포는 단계·검색·페이지로 찾고 한 건 또는 현재 목록 최대 25건 배정. 리뷰는 아직 배정하지 않은 최근 50건씩 제공되며, 배정 후 다음 자료를 고를 수 있다. QA는 공개 경로를 지정한다. 1차와 교차 확인 학생은 다르게 선택한다.
- 학생: 배정 자료 확인 → 분류와 근거 제출 → 지정 학생의 교차 확인/보완 요청. 최종 검수 조건을 갖춘 신규 점포는 A·B가 서로의 자료에 등록 인가 기록을 남길 수 있다.
- 운영자: 등록 인가를 확인해 기존 `/admin/place-operations?step=5`에서 최신 원천·업종·중복과 수동 근거를 다시 검토하여 공개한다. 학생 기록만으로 공개하지 않는다.
- 참여 중단: 좌석 접근 중지. 미사용 초대는 함께 취소되고 기존 로그인도 학생 경로를 사용할 수 없다. 좌석을 다른 학생에게 넘기는 재연결 기능은 제공하지 않는다. 잘못 연결한 계정은 운영자가 본인 확인 후 별도 변경을 검토한다.

## 배포 전 조건

1. 권한 있는 유지보수 담당자가 PR 코드·새 테이블·권한·아래 운영 범위를 확인하고 병합한다. CI 네 잡, 학생의 데스크톱·모바일 시험과 실제 diff를 확인한다.
2. 지정 운영자가 올바른 Cloudflare 계정을 확인한다. 대상은 현재 저장소 `wrangler.jsonc`의 Worker와 D1, 기존 R2이며 다른 계정에서 명령을 실행하지 않는다. CLI 계정이 일치하지 않거나 D1 권한이 없으면 중지한다. 인증 토큰을 출력하지 않는다.
3. 기존 배포와 `origin/main`의 차이를 검토한다. #290의 기존 출시·개인정보·운영 권한 HOLD를 자동 해제하지 않는다. 이 PR 병합만으로 과거 미배포 변경 전부가 검증된 것으로 보지 않는다.
4. D1 migration 목록을 읽어 새로 실행할 항목이 정확히 `0037_student_invitations.sql`, `0038_student_tasks.sql`인지 확인한다. 더 이전의 미적용 항목이 있으면 이 작업에서 일괄 적용하지 않고 그 항목의 승인·영향을 먼저 확인한다.
5. 현재 Worker version과 D1 Time Travel bookmark/백업을 지정 운영자가 기록한다. 보존기간·학생 안내·시험 계정 준비를 확인한다.

검토용 명령은 병합된 `main`에서만 실행한다. 운영 migration 적용은 아래 순서와 한도를 전제로 한다.

```sh
pnpm exec wrangler whoami
pnpm exec wrangler d1 migrations list DB --remote --config wrangler.jsonc
# 위 목록, 계정, 백업, 승인 범위가 모두 확인된 경우에만:
pnpm exec wrangler d1 migrations apply DB --remote --config wrangler.jsonc
pnpm run build
pnpm run deploy
```

배포 기본 스위치는 false이므로 먼저 기존 공개 경로와 RSI를 확인한다. 네 학생 경로를 여는 시점에는 지정 운영자가 동일 Worker의 `STUDENT_WORKSPACE_ENABLED`를 `true`로 변경하고 배포한다. 이 설정은 이후 설정 배포 때 덮어써질 수 있으므로 저장소의 다음 운영 설정 PR에 기록한다. `REVIEW_PHOTO_UPLOAD_ENABLED`, AI 관련 설정, 기존 두 cron은 바꾸지 않는다.

## 실제 검증과 한도

초기 검증은 동의한 전용 시험 계정으로 한다. 운영 학생 계정에 관리자를 부여하지 않는다.

1. 네 경로의 미인증 접근, 일반 회원의 관리자 거부, 학생의 미배정 대상 거부, 캐시 제한을 확인한다.
2. 초대 하나의 정상 수락·재사용 거부·재발급 이전 링크 거부를 확인한다. 실제 A~D용 링크 발급은 관리자 네 번으로 제한하고 화면에 남은 링크를 별도 공유 공간에 저장하지 않는다.
3. 점포·리뷰·QA 시험 작업 각 1건 이내, 1차·교차 확인·보완·등록 인가·접근 중지를 확인한다. 실제 점포 공개·리뷰 수정·평가 변경·불특정 메일 발송은 이 확인에 포함하지 않는다.
4. DB에는 토큰 digest만 있고 분류·검수 단계·리뷰 원문이 변하지 않았음을 읽기 전용으로 확인한다. 시험 메모에는 개인정보를 넣지 않는다.
5. 배포 후 Workers Observability의 `RSI_SELF_CHECK` 또는 기존 토큰 인증 경로로 라이브 RSI를 확인한다. 기존 RSI는 공개 화면 HTTP 점검이며 학생 권한·업로드 무결성 검증을 대신하지 않는다. 새 스케줄이나 무인 반복 호출을 만들지 않는다.

실제 사용 URL·검증 시각·배포 version·실행 migration·남은 실패를 인수 기록에 남긴다. 한 항목이라도 미실행이면 실제 운영 검증 PENDING을 유지한다.

## 중지와 되돌리기

- 잘못된 접근·초대·자료 노출: 해당 좌석 중지 후 전체 스위치 false. 필요 시 기존 Worker version으로 rollback한다.
- 새 테이블은 additive이므로 삭제하거나 기존 migration을 되감지 않는다. 이력과 관계를 보존하고 후속 PR로 수정한다.
- 프로젝트 종료: 좌석 만료 확인 → 작업 목록과 증빙 인수 → 공식 보존기간에 따른 개인 정보·초대·메모 정리. 성과자료에 실제 건수와 미실시를 분리한다.
