# Re:Taste AI 분류·운영 가이드

작성일: 2026-08-06

## 분류 원칙

- 모델은 `@cf/meta/llama-3.1-8b-instruct-fast`, 프롬프트는 `place-category-v1`로 고정한다.
- 전송 정보는 상호명, 공공데이터 업태, 지역 코드, 활성 카테고리 이름·slug뿐이다.
- AI 응답은 JSON Schema 요청 후 서버에서 slug·confidence·근거를 다시 검증한다.
- 규칙 분류와 AI가 일치하고 AI confidence가 0.85 이상이며 규칙 신뢰도도 HIGH일 때만 자동 승인 후보다.
- 자동 승인 후보도 관리자 선택 전에는 공개되지 않는다. AI는 자동 공개·자동 병합을 하지 않는다.
- 실패, 알 수 없는 slug, 규칙 불일치, confidence 0.85 미만은 모두 수동 검수로 남는다.

## 실행 한도

- 같은 입력 해시는 30일간 성공 결과를 재사용한다.
- 수동 또는 예약 실행은 한 번에 최대 100곳이다.
- UTC 날짜 기준 AI 실행 이력은 하루 최대 500건이다. 캐시 실행도 감사 이력과 한도에 포함한다.
- 예약 작업은 공공데이터·평가·장소 재검증과 함께 하루 한 번 실행된다.

## 관리자 화면

- `/admin/candidates`: AI 대기 후보 분류, AI/규칙 출처와 신뢰도 확인, 수동 카테고리 선택.
- `/admin/operations`: 24시간·7일·30일 처리량, 좌표 누락, AI·동기화·재계산 실패와 열린 알림.
- 실패 알림은 원인이 해결된 뒤 근거를 입력해 해결 처리한다. 외부 이메일은 운영 문의 주소 확정 후 연결한다.

## 장애 대응

1. AI 실패 시 후보 데이터는 삭제하거나 반려하지 않는다.
2. `AI_FAILED` 후보가 수동 카테고리로 승인 가능한지 확인한다.
3. 모델·프롬프트·입력 해시·오류는 `ai_classification_runs`에서 확인한다.
4. 동일 오류 반복은 `operational_alerts.occurrence_count`로 확인한다.
5. 모델 변경은 기존 프롬프트 버전을 덮어쓰지 않고 새 버전과 회귀 표본으로 배포한다.
