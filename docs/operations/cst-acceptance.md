# CST 기술 검수 실행서

일정·요구·결정 원본은 [12/10 SSOT](../plans/2026-11-13-cst-service-ssot.md)다. 이 문서는 PDF p8의 T01~T08을 실행 가능한 확인 절차로 풀어 쓴 하위 문서다. **최초 상태는 전부 NOT_RUN**이며 기존 시험 파일 존재는 합격 증거가 아니다.

## 1. 공통 준비

1. 각 시험에 필요한 SSOT DEC-01~08과 합의된 환경·표본·역할·산식 버전을 확인한다. 미정 정책의 적용·수용만 BLOCKED로 남기며, 무관한 합성 검증·현행 회귀는 계속 진행한다.
2. exact SHA/PR, 로컬/preview/live 환경, 실제 배포 version, flag(이름과 공개 여부만), 실행 시각과 실행자를 기록한다. 비밀값/토큰/쿠키·원문 참여정보는 기록하지 않는다.
3. 기본 기술시험은 격리 D1·합성 장소/계정·mock 외부 서비스를 사용한다. 관리/리뷰어/일반/비회원과 두 소유자를 분리하고 public/hidden/pending·중복·폐업·표본부족·위치미확인·사진권리미확인 fixture를 준비한다. 실제 운영 대상 시드 금지.
4. 본문 설명의 수치/산식은 결정 전 임의 고정하지 않는다. 현행 코드 기준은 합의값과 비교할 관측값이다. 결함을 고치려고 기존 적용 migration을 수정하지 않는다.
5. raw 오류/메일/초대/서명·자격증명/학생 개인자료는 공개 증적에 넣지 않는다. 화면은 합성 데이터만 사용하거나 비식별 처리하고 권한 있는 내부 증거 참조를 남긴다.

## 3. 자동 시험 연결

기존 unit/integration/E2E에서 해당 조건을 골라 실행하고 이름·수·skip·exit code를 기록한다. 변경 경계는 먼저 RED→GREEN으로 확인한다. 예시 명령은 로컬만 대상으로 한다.

```sh
pnpm test
pnpm run test:integration
pnpm run typecheck
pnpm run build
pnpm exec playwright test tests/e2e/release.spec.ts --project=chromium
```

위 명령의 성공만으로 T01~T08 전체 또는 실제 이용자 실증 완료가 되지 않는다. CI smoke 목록과 종합 검수 범위를 구분한다. 외부 서비스·메일·운영 D1을 테스트가 기본 호출하지 않게 확인한다. 운영 배포가 필요하면 해당 exact SHA의 PR에 대상·한도·비용·privacy·검증·rollback·담당을 명시하고 병합 승인 범위로만 실행한다.

## 4. 증거·결함·재시험

[execution-log.csv](../evidence/cst-20261210/execution-log.csv)에 한 실행당 한 행을 추가한다. `case_id/run_id/source_sha/environment/decision_refs/executed_at_kst/executor/result/evidence_ref/defect_ref/retest_of`를 기록한다. 결과는 `NOT_RUN / BLOCKED / FAIL / PASS / SKIP`로 제한한다. PASS에는 실행시각·SHA·환경·증거가 필요하며 SKIP/BLOCKED는 분모에 숨기지 않는다. 기존 행을 덮어쓰지 않고 재시험을 새 run으로 연결한다.

부분 실행은 `T03.GUEST_MERGE_SERVER`처럼 하위 case로 기록한다. 해당 PASS를 T03 전체 합격으로 합산하지 않는다. CI는 로그의 실제 checkout SHA·시험 종료시각을 남기고, PR source head/병합 SHA와 구분한다. 원래 T01~08 행의 NOT_RUN은 전체 절차 완료 전까지 보존한다.

결함은 요구/T번호·재현·기대/실제·영향/우선순위·소유·수정 PR·회귀명·재시험 결과를 기록한다. 계약/정책 값의 미확정은 결함과 구분해 SSOT DEC에 연결한다. 개인정보/비공개 자료 접근/권한/중복집계·복구 불가 같은 안전 실패는 실제 실증/공개를 차단한다.

## 5. 연구팀 실증·최종 수용

연구팀 실제 실증은 교수/CST의 확정 설계·동의 범위로만 수행한다. 기술시험 fixture·개발자가 대신 클릭한 결과를 참여자 성공으로 세지 않는다. 익명 세션코드·기기·버전·과업·성공/실패·시간·막힘·도움요청·관찰을 별도 권한 저장소에 남기고 공개 저장소에는 비식별 집계와 승인된 참조만 둔다.

12/10 수용 기록은 검토자·날짜·source/deploy version·T01~08 결과·콘텐츠/권리·정책·운영/복구·실증 준비/실행 상태·미완료·잔여 기한·조건부/NO-GO 이유를 함께 담는다. 12/18 업체 최종 납품과 차이를 명시한다. 실제 수용 서명·실명·성과 수치는 미제공이면 빈칸으로 둔다.
