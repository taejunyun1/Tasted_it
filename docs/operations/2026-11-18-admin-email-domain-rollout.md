#454 구현 범위. #470의 범위는 코드 병합까지다. 0059 적용·Worker 배포·운영 검증은 [B17 부분 적용 기준](2026-11-18-admin-b17-rollout.md)을 확정하는 별도 운영 PR의 승인 전까지 HOLD다. 담당 Codex root. #397 HOLD.

## 대상과 기능

기존 retaste-beta Worker/retaste-production D1만 대상이며 신규 provider·secret·binding·cron·요금제 변경은 없다. 기존 지정 도메인과 발신 도메인의 일치 여부, 관측 상태, 단발 요청 영수증을 표시한다. GET은 공급자를 호출하지 않는다. 수동 조회 최대 2GET, 생성 최대 1POST, 검증 최대 1GET+1POST이며 자동 재시도하지 않는다. B02 현재 권한·최근 인증·관측 revision 검증과 영수증을 한 트랜잭션에 저장한 단 하나의 승자만 외부 요청 권한을 갖는다.

생성 응답의 ID를 보존하고 그 ID가 관측될 때까지 새 변경을 잠근다. 응답 유실은 실제 미전송일 수도 있는 UNKNOWN이며 재전송하지 않는다. 조회에서 현재 도메인이 보인 사실은 유실된 요청이 성공했다는 증거로 승격하지 않는다. 확인할 수 없는 불명 상태는 공급자 상태를 별도로 대조해야 한다. 검증 접수와 실제 verified 상태, 메일 수신 성공은 구분한다.

## 순서와 한도

1. #448(B10), #455(0053), B12 0054, B13 0055, B14 0056을 먼저 통합하고 0059의 kind union이 전체 선행 값과 일치하는지 검증한다. 0057/0058은 불필요하면 만들지 않는다.
2. 최종 head의 필수 CI·독립 리뷰 통과 후 병합 main에서 빌드한다. 기존 점검 fence·이전 실행 drain·TimeTravel/export·기존 세 operation 원장과 사용자 권한의 정렬 digest를 확보한다.
3. 0059 한 번 적용 후 원장 rowid/기존 값·영수증 불변·FK0·신규 세 표 빈 상태를 확인한다. 이전 미적용 migration은 각 병합 PR의 선행 계획에 따라 먼저 적용한다.
4. 기존 설정 그대로 main을 배포한다. 0059 단위 한도는 수동 HTTP12, D1 조회/관리10명령, 고유 기존 ADMIN 임시 세션1개/30분, RSI1회다. 선행 배포와 합치는 경우 같은 세션·백업·RSI를 재사용하고 최종 통합 계획에 합산한다.
5. 공개 기본 경로·익명/일반회원 차단·ADMIN 메일 화면의 미설정 잠금/no-store/잘못된 POST만 확인한다. **운영 Resend GET/POST·도메인 생성/검증·메일 발신은 0**이다. 설정이 이미 제공돼 있으면 저장 관측의 읽기만 검증한다. 새 secret이나 임의 도메인을 설정하지 않는다.
6. 같은 Worker의 기존 RSI 고정 경로 결과와 감사·현재 버전을 대조하고 임시 세션 및 이번 PENDING만 정확 ID로 정리한다. 결과를 SSOT/기존 위키에 기록한다.

## 실패와 제약

GitHub 계정 결제/지출 한도로 필수 runner가 시작되지 않는 동안 merge/deploy는 BLOCKED다. 이를 로컬 통과로 대체하지 않는다. 전환 실패 시 maintenance fence를 유지하고 전진 수정하며 DB 전체 복원/secret 변경/실제 외부 작업은 하지 않는다. 도메인 복구의 실제 성공은 해당 공급자 관측과 운영자 판단이 필요하며 이번 mock 검증으로 대체하지 않는다.
