# 일반 장소 사진 후속 세 장 운영 반입

이 문서를 포함한 실행 PR이 병합되고 #556 운영 전환과 첫 사진 육모정의 공개를 확인한 뒤 Jay/Codex가 아래 범위를 실행한다. 기존 Re:Taste 운영 `tastedit-production`, Worker `retaste-beta`, D1 `DB`와 비공개 사진 바인딩을 사용한다. Cloudflare 계정·Worker·D1·R2는 #556 영수증과 일치해야 한다.

## 조건

- #556의 영수증에 운영 Worker 100%, 정기 RSI 6개 성공과 같은 시각 D1 감사, 59개 장부, 원장 856·검수 연결 83, 육모정 원본 해시·출처·공개 기록이 확인되어야 한다. 실행 직전에 #556 영수증으로 `CLOUDFLARE_ACCOUNT_ID`를 고정한다. Wrangler의 현재 배포 상태에서 영수증의 정확한 버전 단독 100%를 확인하고 해당 버전의 일반 사진 표시 활성, 직접인증 좌석 미지정과 기존 전역 사진 업로드 비활성을 대조한다.
- 대상은 정확한 기존 장소 ID와 상세주소를 고정한다. 대상의 현재 B09 공개 자격, 최근 영업 상태와 중복 여부, 시작 전 사진 원장·R2의 해당 키 미존재, 최신 사진별 원문 이용 조건을 읽어 확인한다. 같은 ID로 이미 적용된 경우 실제 상태와 기존 감사부터 확인한다. 첫 실행 시 사진 원장에 #556의 육모정 공개 한 건만 있는지 확인한다. 이어서 실행할 때는 이 절차에서 각각 확인한 준비·공개·회수 행만 더 허용한다. 동일 대상에 다른 준비 행이 있으면 해당 행을 보류한다.

## 실행 범위

1. Jay/Codex가 고정한 SQL 파일 하나를 `pnpm exec wrangler d1 execute DB --remote --config "$selected_db_config" --profile tastedit-production --file "$staged_file"`로 적용한다. 기존 D1·계정 고정 설정을 재확인한다. `STAGED` 상태와 정확한 대상 장소·출처·SHA, 비로그인 GET·HEAD 404를 확인한다.
2. 기존 운영 관리자가 최근 재인증을 완료하고 정확한 ID의 원본 첨부에서 지정 JPEG만 올린다. 비공개 미리보기 원본 바이트, 조건부 저장 성공과 감사 한 건, 익명 GET·HEAD 404를 확인한다. 응답이 모호하면 같은 행과 키를 조회한 뒤 필요한 경우 같은 파일로 한 번 재시도한다.
3. 같은 대상의 공개 확정을 별도로 수행한다. 승인 감사, GET·HEAD 200과 원본 길이·SHA, 상세와 모바일의 화면·출처를 확인한다. 대상별 초기·검수·공개를 기록하며 같은 출처 또는 장소로 인한 중복을 확인한다.
4. 이상이 생기면 해당 사진만 회수한다. 익명 GET·HEAD와 관리자 미리보기 404를 보고 나머지 사진과 공개 장소를 읽어 확인한다. 원본과 감사·D1 등록을 보존한다. 기존 운영 버전 회수는 이 범위가 아니다.

최대 D1 STAGED 세 행, 조건부 원본 저장 세 건, 공개 승인 세 건, 문제가 있는 정확한 사진의 회수 최대 세 건이다. 요청은 기존 구독·Worker·D1·R2의 사용량만 발생시킨다. 개인정보와 비밀값을 기록하지 않는다. 신규 API·메일·자리 승인·외부 연락은 범위 밖이다. B17과 #397은 보류한다.

같은 #556 Worker 소스 `2911bd4`와 59개 격리 장부에서 교체 전 세 원본의 JPEG·바이트·캡션·별도 공개를 확인했다. 대표 한 장의 회수 뒤 해당 사진만 404였다. 새 부산집 원본은 준비 도구로 JPEG와 지문을 검증했고, 격리 D1에서 새 SQL의 `STAGED` 한 행과 같은 출처를 쓰는 별도 행의 중복 검출을 확인했다. ## #563 신청 전용 전환 이후에 남은 사진

이 절을 포함한 PR이 병합되면, Jay/Codex가 #563 신청 전용 버전에서 #556·#558의 미완료 작업을 이어간다. #556 운영 중에는 각 기존 실행 절차를 적용한다. 전환 중엔 두 절차의 진행 중인 관리자 작업을 정리하고 정확한 행·원본 키·감사 상태를 기록한다.

- #556 동일 버전의 정기 점검 6개와 D1 감사 및 #563 신청 전용 전환 영수증을 확인한다. 실제로 업로드된 버전의 단독 100%, #563의 전환 후 운영 검증과 해당 버전의 RSI·D1 감사를 대조한다. 고정 소스는 `8da68cfd1d10901df86be6aecce0a0e89a02a685`, 신청 전용 빌드 해시는 `6e68b78dd7ea40d88863a779dc0df24f7513b237978621c74c0d88163fbc17d6`, 설정 해시는 `02845cee0b3299d2c33826db0f42b0c1f06ed80e89fdd0b718690f68454b1743`이다. 이 단독 버전의 검증 기록으로 위 조건의 #556 실운영 버전 확인을 대체한다. [#563 신청 전용 절차](2026-11-26-cst-direct-verification-ab-activation.md)
- 계정, 기존 D1·두 비공개 R2, 두 예약 작업, 59개 장부 해시 `c968f4252c2ef02399a8d615b22b4c6ef8cd8b87fb073c65915ca7b4ed55cce2`, 원장 856곳·검수 연결 83건을 대조한다. 일반 사진 표시가 켜져 있고 전역 사진 업로드가 꺼져 있어야 한다. 직접인증 접수 좌석은 미지정이다. 두 고정 빌드에서 일반 사진 서버 경로, D1 제약과 바인딩이 일치한다.
- 육모정은 #556에서 등록한 검수 대기 한 행을 사용한다. 대상 행이 사라졌거나 지문·출처·이력이 다르면 그 건을 보류한다. #556에서 확정한 원본으로 첨부·공개 각 최대 한 건을 이어가고, 이미 성공한 단계는 기존 R2·감사·익명 응답을 대조한다. 실제 공개와 원본이 확인되면 위 부산집 `4163518`·오얏리 돌솥밥·새집추어탕 중 아직 완료하지 않은 사진을 기존 방식으로 진행한다. 장소마다 현재 B09 공개 자격, 상세주소, 개별 이용 조건과 동일 원본·출처에 대한 중복을 다시 확인한다. 부산집 `4163517`은 보류다.
- 두 Worker 버전에 걸쳐 원래 한도를 적용한다. 육모정 신규 등록은 0건이며, 후속 세 사진의 STAGED·첨부·공개는 대상별 최대 한 건이다. STAGED는 같은 승인 SQL과 기존 D1에만 적용한다. 기존 관리자 화면의 최근 재인증, 첨부 감사, 비공개 미리보기 바이트와 공개 전 GET·HEAD 404를 확인한 뒤 별도 공개를 확정한다. 공개 감사, 익명 GET·HEAD 200, 길이·지문과 데스크톱·모바일 출처를 대조한다. 응답이 모호하면 같은 행·R2·감사를 먼저 읽고 기존 절차에서 허용한 범위만 재시도한다.
- 이 절의 범위는 위 네 사진의 기존 원장·저장·심사 경로와 동일 대상 회수다. 기존 Worker·D1·R2와 익명 화면 요청 사용량을 적용한다. 운영 버전이 바뀌면 해당 절차를 멈춘다. 문제가 있는 공개 사진은 기존 관리자 회수 후 미리보기와 익명 GET·HEAD 404를 대조하고 원본과 감사 이력을 보존한다.
