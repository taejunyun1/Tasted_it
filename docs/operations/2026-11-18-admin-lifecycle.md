# 비회원·보존 정리 운영 조회

#462의 범위는 A18/A20의 읽기 전용 집계와 앞으로의 온보딩 정리 결과 관측이다. `/admin/lifecycle`은 현재 ADMIN만 조회하고 모든 POST를 405로 거절한다. 관리자 대리 승계·수동 정리·삭제 요청 확정은 제공하지 않는다. #397 HOLD와 #360의 실제 보존/법적 사실 OPEN을 유지한다.

각 표에서 최근 저장순 최대 1,000행과 초과 여부만 조사한다. 표본 안의 진행/완료/건너뛰기/계정 연결 표식, 만료 조건, 임시 저장/배지 잔존, 제품 이벤트와 요청 제한 시간창을 집계한다. 표마다 표본 범위가 달라 합산한 전체 수나 실패율로 사용할 수 없다. 개별 guest/user/session ID, 쿠키, 회원 정보와 자유문안은 반환하지 않는다.

guest 최대 30일·진행 중 갱신/종료 후 비갱신, 임시 저장 50곳, 제품 이벤트 30일, rate window 24시간은 현재 코드의 기술 기준이다. 새 법적 기간이나 관리자 삭제 권한을 만들지 않는다. `merged_user_id` 표식과 별도 `GUEST_CONVERTED` 이벤트는 성공률이 아니며, 이벤트 저장 누락과 이미 정리된 자료 때문에 현재 잔존 수가 과거 전체 성공을 뜻하지 않는다. 실패/재시도 이력은 아직 미측정이다.

기존 scheduled lifecycle 함수의 완료/예외 뒤에 기존 감사 표로 최소 관측만 남긴다. 성공은 삭제 함수가 반환한 guest/product 건수이며 rate window 삭제 건수는 미측정이다. 기존 순차 삭제의 예외는 이미 일부 삭제가 진행됐을 수 있어 `PARTIAL_OR_UNKNOWN`과 건수 null로 저장하고 원래 오류를 다시 던진다. 성공 뒤 관측 저장만 실패하면 정리 결과는 그대로 성공 반환하고 식별자 없는 관측 실패 로그를 남긴다. 원래 삭제 조건·처리 순서·cron 두 개는 변경하지 않는다.

조회는 최근 감사 1,000행 안에서 최신 온보딩 관측을 찾는다. 적용 전 이력·관측 실패·프로세스 중단은 알 수 없으므로 기록 없음을 미실행으로 표시하지 않는다. 이 관측은 온보딩 정리만 다루며 전체 maintenance·사진 삭제·운영 복원을 증명하지 않는다.

새 migration·dependency·provider·secret·환경 설정은 없다. 기존 Worker에 코드가 배포된 이후 다음 기존 scheduled 실행부터 관측이 생긴다. worker는 실제 운영 정리/배포를 실행하지 않으며, root의 승인된 합동 계획에 따라 통합·필수 CI·읽기/권한거부 live 검증을 진행한다. 실패 시 기존 TTL을 유지하고 읽기 화면 및 관측 코드만 전진 수정한다.
