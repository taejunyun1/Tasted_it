# 정기 RSI 결과 보존과 실패 상태

- 상태: ACCEPTED — 이 변경을 포함한 PR 병합 시 적용
- 소유자: Jay/Codex, 사용자 요청에 따른 지정 배포 담당
- 추적: [Issue #297](https://github.com/taejunyun1/Tasted_it/issues/297)
- 범위: 기존 정기 RSI의 결과 보존과 오류 전달. 공개 6경로·두 cron·인증 경계는 유지한다.

## 문제와 결정

운영 Workers Logs는 호출의 10%를 저장한다. 2026-10-15 최근 24시간 `RSI_SELF_CHECK` 조회는 0건이며, Cron Events의 성공 상태만으로 경로별 성공을 입증할 수 없다. 기존 코드는 실패 결과·예외를 정상 반환하여 Cron 성공으로 표시될 수 있다. 한 경로의 네트워크 오류는 다른 다섯 경로의 결과까지 잃게 한다.

정기 실행 결과를 기존 `admin_audit_logs`에 회당 1개 보존한다. actor는 NULL, action은 `RSI_SELF_CHECK`, target은 `OPERATIONS` / `rsi-scheduled`다. 고정 경로·HTTP 상태·성공 여부·호스트와 결과 시각만 저장하며 리디렉션 원문·요청 본문·쿠키·토큰·이메일·상호를 넣지 않는다. 이 변경은 기존 계획의 **정기 RSI D1 금지에 대한 한정 예외**다. 온디맨드 요청과 kill switch false는 D1을 변경하지 않는다.

네트워크/timeout 실패는 해당 경로의 status 0으로 남기고 나머지 결과를 보존한다. 점검 실패, 활성 상태의 origin 누락, 감사 저장 실패는 scheduled `waitUntil`에 거부로 전달하여 Cron 실패 상태를 남긴다. on-demand는 기존 토큰 인증과 HTTP 200/503 계약을 유지한다.

## 비용·개인정보·운영 경계

- 기존 6시간 cron 기준 하루 4개 감사 레코드와 회당 고정 INSERT 1개다. 공개 점검은 기존 6개 GET만 수행한다.
- 새 테이블·migration·binding·cron·Worker·공급자·AI·이메일·알림 전송은 없다. 기존 로그 sampling도 유지한다.
- 감사 이력은 기존 운영 감사 데이터의 접근·보존 정책을 따른다. 이 변경에서 자동 삭제를 추가하지 않는다.
- 장소·리뷰·학생 초대/좌석/작업은 수정하지 않는다. 사용자 A~D 초대는 읽기 검증만 한다.
- 학생 가입/수락/분류/교차 확인 시험은 별도 로컬 Workers/D1와 합성 이메일 전송 fake로 격리한다. 실제 수신 메일함이나 운영 초대를 사용한 시험으로 표현하지 않는다.
- 브라우저 시험의 메일 수신 보조 기능은 loopback 전용 별도 시험 entrypoint에만 둔다. production entrypoint는 유지하며 운영 배포물에 시험 메일함이나 가짜 키를 넣지 않는다.

## 검증과 복원

RED 회귀 4개는 전체 경로 결과 유실, 정기 감사 미저장, Cron 실패 은폐, 감사 실패 무시를 재현했다. 동일 회귀와 D1 통합 시험으로 수정 결과를 검증한다. 학생 시험은 네 계정의 실제 signup/verify/login/join/task route를 연결하고 자기 확인·재수락·재확인을 거부하며 원본 점포와 작성자 평가를 보존한다.

지정 계정의 `retaste-beta`에 병합 main을 배포한다. 사전 Worker는 `fa76558c-0e37-4ff2-89ba-9eb545459d5c`이며 문제 발생 시 그 버전으로 복원한다. 새 감사 레코드는 이력으로 보존하며 역 migration이나 초대 재발급을 하지 않는다. 실제 정기 실행은 Cron Events와 같은 시각의 D1 감사 결과로 검증하며, 로컬 통과나 예정 시각을 실제 실행 증거로 쓰지 않는다.
