## 문제와 명칭

현재 `rsi-self-check.ts`는 고정된 공개 6경로의 HTTP 상태와 로그인 리디렉션을 확인한다. `rsi-self-check.server.ts`는 결과를 감사에 보존하고 실패를 Cron에 전달한다. 기존 파일·환경 변수·감사 action의 RSI 이름은 호환을 위해 유지하되, 이 동작의 제품 설명은 **운영 정기 헬스체크**로 한정한다. 2026-10-15 실제 정기 6/6 PASS는 HTTP 계약의 증거다. [실제 실행 기록](https://github.com/taejunyun1/Tasted_it/issues/297#issuecomment-6192581799)은 자기개선 효과를 입증하지 않는다.

장애를 고치는 에이전트만 추가하면 자동 복구다. 이번 설계의 목표는 **개선 주체의 진단·수정 알고리즘을 스스로 변경하고, 이전 세대보다 유효한 수정을 더 잘 만드는지 외부 평가한 뒤, 채택된 절차를 다음 개선에 실제 사용하는 제한된 RSI**다. 기반 모델의 가중치·학습 알고리즘 개선이나 일반 지능 상승은 범위에 없다.

## 결정

1. Cloudflare Worker는 현재 헬스체크·감사만 담당한다. 장시간 코드 편집·평가는 별도 격리 실행기로 분리한다. 실행기는 기존 GitHub Actions의 명시적 `workflow_dispatch`를 우선하며 새 상시 서버·Cloudflare cron·Queue·Durable Object·Workers Builds를 추가하지 않는다.
2. 사건 관측→근거 있는 원인 가설→최소 패치→고정 검증→성공·실패 이력 축적을 서비스 복구 루프로 만든다. 같은 사건의 중복 실행·재시도·토큰·시간·금액을 외부 감독기가 제한한다.
3. 복구 이력을 입력으로 개선 에이전트가 자신의 `diagnostic-policy.ts`와 `repair-policy.ts` 후보를 만든다. 변경 가능 영역은 진단 순서, 증거 선택, 수정 탐색과 회귀시험 선택이다. 이 코드가 후속 세대의 복구와 자기개선 후보 생성에도 사용되어야 한다. 회고 텍스트 저장만으로는 완료가 아니다.
4. 평가기·정답·보안 경계·예산·허용 경로·배포 권한·승격 조건은 후보가 수정하지 못한다. 후보 실행기는 운영 D1·메일·학생 초대·계정·GitHub 쓰기·Cloudflare 자격증명을 받지 않는다.
5. 모델은 Cloudflare Workers AI의 고정된 단일 모델을 제안한다. 새 모델 사용은 현재 후보 분류 AI의 유지보수 승인을 승계하지 않는다. 구체 모델·자격증명·전송 데이터·금액의 한정 GO가 담긴 후속 PR 전에는 실호출하지 않는다. 새 공급자 도입이나 자동 모델 교체는 하지 않는다.
6. 기존 에이전트, 기록만 추가한 에이전트, 알고리즘까지 개선한 에이전트를 동일 조건에서 비교한다. 별도 보관한 새로운 사건 집합에서 개선이 재현되고 후속 세대에 실제 반영돼야 자기개선 효과를 주장한다. 소표본·예산 부족·평가 오염·효과 미달은 INCONCLUSIVE 또는 REJECTED로 남긴다.
7. 서비스 수정 PR과 에이전트 절차 승격 PR을 구분한다. 배포는 기존 병합 main·지정 담당자 원칙을 유지한다. 사람은 범위·평가 계약과 채택을 승인하고, 그 사이 분석·후보 생성·검증·학습 반영은 에이전트가 수행한다. 무승인 운영 자기 배포는 넣지 않는다.

## 현재 규칙과의 관계

이 계획 PR의 병합은 문서 채택이다. `AGENTS.md`, `COWORK.md`, [스택 거버넌스](./2026-08-10-tech-stack-governance.md), 기존 RSI Stage 1–4의 HOLD와 2026-10-15 한정 GO를 변경하지 않는다. 실행 계획의 R1–R6은 기존 Stage 번호와 별개다.

후속 R3·R4 구현 PR은 기존의 “로컬 Node를 RSI로 사용하지 않음”, Workers AI 확장 금지와의 관계를 명시적으로 심사한다. 제안 예외는 **격리된 에이전트 연구·평가 실행기와 한정 모델 broker**에만 적용한다. Node 로컬 통과를 라이브 Worker 정상 증거로 바꾸지 않는다. 운영 정상은 기존 Worker의 실제 정기 감사로 계속 확인한다.

## 대안과 선택 이유

| 대안 | 판단 |
| --- | --- |
| 기존 헬스체크 이름만 RSI로 유지 | 자기개선 주체·평가·세대 간 반영이 없어 기각 |
| 실패를 모델에 보내 패치만 생성 | 서비스 복구 단계로 사용하되 RSI 완료 기준으로는 부족 |
| 회고·검색 기록만 누적 | 대조군으로 채택. 알고리즘 변경의 추가 효과를 분리할 수 있음 |
| 기반 모델을 재학습하거나 새 에이전트 플랫폼 도입 | 현재 서비스에 비해 비용·권한·개인정보 표면이 큼. 범위 밖 |
| 고정 감독기 아래 제한된 에이전트 코드의 자기 수정 | 기존 CI·테스트·Worker 관측을 재사용하고 효과·권한 경계를 분리할 수 있어 제안 |

## 도입과 종료 조건

R1은 [PR #320](https://github.com/taejunyun1/Tasted_it/pull/320)으로 로컬 합성 계약·원장·조회만 구현됐다. R2–R6은 별도 단계이며, 이 설계 채택만으로 실모델·운영 실행을 시작하지 않는다. 후속 구현 PR은 대상·소유 파일·고정 명령·허용 경로·예산·승인 역할·검증·rollback을 적고 해당 단계만 GO로 전환한다. 이번 PR에는 실행 코드·workflow·migration·의존성·운영 권한 변경이 없다.

새 영속 DB를 만들지 않는다. 초기 증거는 비공개 CI artifact와 Git으로 관리하는 익명화된 사건·절차 버전으로 나눈다. 원시 로그·계정·학생 자료는 학습 저장소로 복사하지 않는다. artifact 보존·검증·익명화 책임과 중단 조건은 실행 계획에서 고정한다.

채택된 에이전트에 회귀·권한 위반·평가 조작이 발견되면 감독기가 즉시 후보 실행을 중단하고 마지막 검증 세대로 되돌린다. 기존 Worker 헬스체크는 독립적으로 계속된다. 서비스 코드는 별도 배포 PR에 기록된 Worker 복원 절차를 따른다. 감사·거절 이력과 학생 초대는 되감지 않는다.

## 참고와 적용 범위

- [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954v3): 자신의 에이전트 코드를 수정하고 실제 과제 평가로 선택하는 접근을 참고한다. 해당 논문의 성능 수치를 이 서비스의 기대치나 현재 실적으로 사용하지 않는다.
- [Self-Taught Optimizer](https://arxiv.org/abs/2310.02304v3): 개선 프로그램 자체의 변경을 참고한다. 기반 모델 고정의 한계를 명시하고 에이전트 절차 수준의 효과만 측정한다.
- [GitHub Actions 보안](https://docs.github.com/en/actions/reference/security/secure-use): 신뢰할 수 없는 후보 코드와 자격증명이 있는 단계를 분리한다.
- [Workers AI REST API](https://developers.cloudflare.com/workers-ai/get-started/rest-api/): 모델 호출 broker의 후속 구현 근거다. 문서 확인은 계정 연결이나 실행 승인이 아니다.

연구를 바탕으로 한 위 구조·승격 문턱·표본 수·예산은 이 프로젝트의 제안이며, 이미 검증된 성능이나 연구의 보장으로 해석하지 않는다.
