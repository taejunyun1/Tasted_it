Re:Taste 다음 의사결정 요약
작성일: 2026-08-05
상태: 초안 - 구현 승인 문서가 아님

확정된 결정

- D-07 지도 공급자: NAVER Maps Dynamic Map SDK
- 주소와 좌표 변환: NAVER Maps Geocoding
- 내부 위치 기준 원본: Re:Taste D1의 WGS84 위도와 경도
- 확정일: 2026-08-05

목적

1주차 기술 베타 이후 다음 구현을 시작하기 전에 확정해야 할 내용을 정리한다.
결정되지 않은 항목은 임의로 구현하지 않는다.


1. 지금 결정해야 할 12개 항목

D-01. 서비스 공개 범위
- 권장안: 법적 정보와 실데이터 검수가 끝날 때까지 초대형 비공개 베타로 운영한다.

D-02. 사용자 로그인
- 권장안: 이메일 매직링크 로그인 1종으로 시작한다.
- 소셜 로그인은 실제 필요성이 확인된 뒤 추가한다.

D-03. 관리자 인증
- 권장안: Cloudflare Access와 앱 내부 ADMIN 권한 검사를 함께 사용한다.

D-04. 만 14세 미만 가입
- 권장안: MVP에서는 가입을 차단한다.

D-05. 장소 위치 기준값
- 권장안: D1에 저장된 WGS84 위도와 경도를 내부 기준 원본으로 사용한다.

D-06. 장소 검색과 주소 보정
- 권장안: NAVER Maps Geocoding으로 주소와 좌표 후보를 찾고 운영자가 핀 위치를 확인한다.
- 장소명 검색 후보를 가져올 공급자는 별도로 결정한다.

D-07. 지도 렌더러와 타일
- 확정: 웹, iOS, Android 모두 NAVER Maps Dynamic Map SDK를 사용한다.
- 기존 MapLibre 지도는 전환 검증이 끝난 뒤 제거한다.

D-08. 실데이터 공개 조건
- 권장안: 영업 상태, 주소, 좌표를 사람이 확인한 장소만 공개한다.

D-09. 이미지 정책
- 권장안: 직접 촬영했거나 이용 허락 및 라이선스가 확인된 이미지만 R2에 저장한다.

D-10. 카테고리 구조
- 권장안: 대표 카테고리 1개와 복수의 보조 태그를 사용한다.

D-11. 평가 v1
- 권장안: Beta(2,2) 계산과 최소 8표 공개 기준을 첫 베타까지 유지한다.
- 리뷰어 가중치는 실제 평가 실험 후 결정한다.

D-12. 분석 도구
- 권장안: 초기에는 필수 운영 이벤트와 Workers 로그만 수집한다.
- 외부 분석 도구는 개인정보와 국외 이전 조건을 검토한 뒤 도입한다.


2. 공개 베타 전 법무·운영 정보

다음 정보는 아직 미정이며 정식 공개 전에 확정해야 한다.

- 운영자 또는 사업자의 법적 명칭
- 사업장 주소
- 개인정보 문의 이메일
- 문의 전화번호 또는 전화 미운영 정책
- 만 14세 미만 가입 차단 여부
- 개인정보 처리 위탁 및 국외 이전 내역
- 계정 삭제 방법과 데이터 보존기간
- 업주와 권리자의 장소·이미지 정정 요청 절차

개인정보 처리방침은 kimlawtech/korean-privacy-terms 저장소를 기준 초안으로 사용한다.
실제 서비스의 데이터 흐름과 공급자를 먼저 확정한 뒤 문구를 작성한다.
법적 주체와 연락처가 비어 있는 상태에서는 정식 공개 또는 결제를 시작하지 않는다.


3. 인증과 관리자 보안 구조

권장 구조

- 일반 사용자: 이메일 매직링크 로그인
- 관리자: 검증된 로그인과 서버의 ADMIN 역할 검사
- 관리자 화면: Cloudflare Access 추가 보호
- 역할 판정: 브라우저가 아니라 서버 세션과 D1을 기준으로 처리
- 관리자 작업: 작업자, 이유, 변경 전 값, 변경 후 값, 시각을 감사 로그로 저장

현재의 이메일 직접 입력 방식은 기술 데모 전용이다.
공개 사용자의 실제 인증 수단으로 사용하지 않는다.

추가로 결정할 내용

- 이메일 발송 공급자와 발신 도메인
- 매직링크 만료 시간과 재사용 방지 규칙
- 소셜 계정 연결 허용 여부
- 탈퇴와 재가입 시 기존 투표·저장 데이터 처리
- Reviewer 승급과 Admin 지정 책임자


4. 지도·위치 데이터 권장 구조

역할 분리

- NAVER Maps Dynamic Map SDK: 웹, iOS, Android 지도 화면과 마커 표시
- NAVER Maps: 한국어 도로, 지명, 배경 지도 제공
- NAVER Maps Geocoding: 주소와 좌표 후보 제공
- Re:Taste D1: 검수된 좌표, 주소, 영업 상태, 출처, 변경 이력의 기준 원본

특정 지도 사업자의 장소 ID를 Re:Taste 장소의 기본키로 사용하지 않는다.
공급자가 바뀌거나 외부 ID가 사라져도 내부 장소 데이터는 유지되어야 한다.

권장 위치 데이터 필드

- placeId: Re:Taste 내부 불변 ID
- name, shortName: 원래 이름과 표시용 이름
- latitude, longitude: WGS84 기준 좌표
- roadAddress: 도로명 주소
- parcelAddress: 지번 주소
- region1, region2, neighborhood: 광역, 시군구, 동 정보
- source: Kakao, OSM 등 데이터 출처
- sourcePlaceId: 공급자의 장소 ID
- sourceUrl: 공급자 상세 페이지
- locationPrecision: 출입구, 건물, 필지, 근사 위치 구분
- verificationStatus: 검수 상태
- verifiedAt, verifiedBy: 검수 시각과 담당자
- lastCheckedAt: 마지막 영업 상태 확인 시각
- closedAt: 폐업 확인 시각

한 장소가 Kakao ID와 OSM ID를 동시에 가질 수 있으므로 장소와 외부 출처 정보는 별도 구조로 관리한다.


5. 장소 등록 및 검수 절차

검색 후보
→ 중복 확인
→ 주소와 좌표 확인
→ 핀 위치 보정
→ 영업 상태 확인
→ 이미지 권리 확인
→ 검수 완료
→ 공개

운영 원칙

- 신규 장소 후보는 기본적으로 DRAFT 상태다.
- 이름만 같다고 같은 장소로 합치지 않는다.
- 주소, 전화번호, 좌표, 외부 ID를 함께 비교한다.
- 자동 입력된 좌표는 실제 건물 또는 출입구 위치인지 확인한다.
- 이전이나 폐업 제보가 들어오면 검토 상태와 변경 이력을 남긴다.
- 초기에는 공개 장소를 90일 단위로 다시 확인한다.


6. 이미지 저작권 기준

- 직접 촬영한 이미지는 촬영자와 촬영일을 기록한다.
- 업주가 제공한 이미지는 제공자, 동의 일시, 허용 범위, 원본을 기록한다.
- 라이선스 이미지에는 출처와 라이선스 조건을 기록한다.
- 외부 지도나 배달 플랫폼 이미지를 임의로 복제하지 않는다.
- 삭제 요청이 들어오면 공개 중단, 원본 삭제, 처리 이력을 구분한다.
- 이미지가 없는 장소는 중립적인 플레이스홀더를 사용한다.
- 이미지가 없다는 이유로 장소 평가 점수에 불이익을 주지 않는다.


7. 평가·리뷰어 운영 규칙

리뷰어 권장 운영안

- 초기 리뷰어는 초대제로 모집한다.
- 서비스에는 닉네임을 표시하되 운영자는 신원과 연락 수단을 확인한다.
- 본인, 가족, 고용, 금전 관계가 있는 장소 평가는 제한한다.
- 평가 수정 기간과 철회 규칙을 정한다.
- 활동 중지와 자격 박탈 기준을 정한다.
- 보상을 제공할 경우 세무 처리 기준을 정한다.

평가 원칙

- 첫 베타는 Beta(2,2)와 최소 8표 기준을 유지한다.
- 일반 사용자 평가와 리뷰어 평가를 원시 데이터에서 구분한다.
- 유료 캠페인은 점수나 Golden Pick을 구매하는 수단이 될 수 없다.
- Golden Pick의 최소 표본, 평가 기간, 유효기간, 회수 조건을 정한다.
- 점수 공식 변경 시 버전을 올리고 이전 결과를 재현할 수 있게 한다.


8. B2B 상품·결제 전 결정사항

- 판매 주체와 사업자 정보
- 상품의 산출물, 수행 기간, 수정 횟수
- 가격의 부가세 포함 여부
- 견적 유효기간
- 결제사와 결제 수단
- 현금영수증과 세금계산서 처리
- 작업 시작 전후의 취소·환불 기준
- 결제 웹훅 검증과 중복 처리 방지
- 캠페인 콘텐츠의 광고·협찬 표시
- 결제와 평가·추천·배지 로직의 기술적 분리

첫 결제 버전의 권장 흐름

문의
→ 관리자 견적
→ 만료 시간이 있는 결제 링크
→ 캠페인 수행
→ 결과 리포트

첫 버전에는 업주 계정과 셀프서비스 결제를 만들지 않는다.


9. 앱 출시 전 결정사항

- React Native와 Flutter 중 사용할 기술
- 웹과 앱의 공통 API 버전 정책
- 소셜 로그인 및 계정 연결 여부
- 위치 권한 요청 기능과 거부 시 동작
- 푸시 알림 종류, 기본값, 해지 방법
- 앱 안에서 완료되는 계정 삭제 흐름
- Apple과 Google 개인정보 표시
- 앱 내 판매 상품의 인앱결제 적용 여부
- 딥링크와 외부 지도 앱 연결
- 웹과 앱의 저장 장소 동기화
- 크래시 및 분석 도구의 개인정보 처리

첫 소비자 앱은 탐색, 투표, 저장에 집중한다.
B2B 주문과 결제는 웹에서 처리한다.


10. 한 번에 승인 가능한 권장 기본안

1. 법적 정보와 실데이터 검수가 끝날 때까지 초대형 비공개 베타로 운영한다.
2. 만 14세 미만 가입은 MVP에서 차단한다.
3. 일반 사용자는 이메일 매직링크를 사용한다.
4. 관리자는 앱 권한 검사와 Cloudflare Access를 함께 사용한다.
5. NAVER Maps Dynamic Map SDK를 웹, iOS, Android 지도에 사용한다. 확정.
6. NAVER Maps Geocoding은 주소와 좌표 보정에 사용한다.
7. D1의 WGS84 좌표를 내부 위치 기준 원본으로 사용한다.
8. 장소는 영업 상태, 주소, 좌표를 사람이 확인한 뒤 공개한다.
9. 카테고리는 대표 1개와 복수의 보조 태그 구조로 만든다.
10. 직접 촬영 또는 이용 허락이 확인된 이미지만 R2에 저장한다.
11. 첫 베타는 Beta(2,2)와 최소 8표 기준을 유지한다.
12. 리뷰어 가중치는 실제 평가 실험 후 결정한다.
13. 초기에는 필수 이벤트와 Workers 로그만 수집한다.
14. B2B 결제는 법적 주체, 상품, 환불, 세금 문서 확정 후 시작한다.
15. 첫 앱은 소비자 탐색, 투표, 저장에 집중한다.
16. B2B 결제는 앱이 아니라 웹에 둔다.
