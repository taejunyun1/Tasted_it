## 문제와 선택

비개발자 학생에게 점포·리뷰 분류와 QA를 배정하면서 전체 관리자 접근을 주지 않아야 한다. 기존 로그인·이메일 인증과 USER/REVIEWER/ADMIN 역할을 유지하고, 별도 학생 좌석 A~D를 개인 계정에 연결한다. 새 인증 공급자나 상위 역할을 추가하지 않는다.

| 좌석 | 업무 | 확인 범위 |
| --- | --- | --- |
| A·B | 점포 분류, QA, 신규 등록 인가 기록 | 배정된 1차 작업 또는 지정 교차 확인 작업 |
| C·D | 리뷰·사진 품질 분류, QA | 배정된 1차 작업 또는 지정 교차 확인 작업 |
| 기존 ADMIN | 초대·배정·접근 중지, 결과 확인 | 기존 서버 관리자 검증 유지 |

등록 인가는 비공개 근거 기록이다. 공개 실행·원천 자료 변경·업종 반영·점포 병합·복원·리뷰 수정·점수 변경을 수행하지 않는다. 운영자는 기존 5단계 장소 운영 화면에서 다시 확인한 뒤 공개한다. 학생의 분류와 AI 결과가 기존 검수 단계를 대체하지 않는다.

## 신뢰 경계와 방어

1. 브라우저 → 서버: 모든 loader/action에 기존 세션 인증 후 현재 좌석·활성·기한·이메일 인증·업무 권한·배정을 검증한다. ADMIN은 학생 초대 수락 대상에서 제외한다. UI에 버튼이 없어도 서버가 권한을 확인한다.
2. 초대 → 계정: 암호학적 난수 32바이트, 7일 이내·프로젝트 기한 이내, SHA-256 digest만 저장한다. 토큰은 URL fragment로 전달하고 화면 진입 시 주소에서 제거한다. DB batch의 조건부 좌석 연결·초대 소진으로 동시 수락 한 명만 허용한다. 계정 한 개는 좌석 한 개에만 연결한다.
3. 학생 → 다른 학생: 대상 ID로 직접 요청해도 담당·지정 확인자가 아니면 거부한다. 1차 작성자와 확인자가 달라야 한다. 최초 제출·교차 확인·인가 시 버전으로 중복 제출을 막고 이력을 같은 D1 transaction에 기록한다.
4. 원천 자료 → 인가: 주소·업종·원천 상태·검수 단계·중복 판단 fingerprint를 비교한다. 활성 최종 검수 단계의 새 PUBLIC_DATA 또는 DRAFT 제안만 인가 대상으로 삼고, 기존 점포 복원·호출 회수는 허용하지 않는다. 원천 변경 시 재제출한다. 이후 공개 직전 운영자가 최신 조건을 다시 검증한다.
5. HTTP → 변경: 같은 Origin 필수, 엄격한 Zod 입력·허용 intent, 실제 본문 16KiB 제한, 중복 필드 거부, 사용자별 15분당 초대 10회·작업 60회 제한. QA 링크는 내부 공개 경로만 허용한다. SQL은 매개변수화하고 React 텍스트 출력으로 escape한다.
6. 서버 → 클라이언트: 학생 목록에는 배정·상태만, 상세에는 업무에 필요한 사실·공개 사진만 보낸다. 원천 raw payload·타인 이메일·토큰 hash는 보내지 않는다. 비공개 응답은 `no-store, private` 및 `Referrer-Policy: same-origin`; 외부 근거 링크는 `noreferrer`로 연다. `no-referrer`는 JS 시작 전 POST의 Origin을 null로 만드는 브라우저 동작 때문에 사용하지 않는다.

파일 업로드나 Workers AI 호출은 이 변경에 포함되지 않는다. 파일·이미지·모델 출력의 추가 신뢰 경계는 [업로드 검사 검토안](../operations/upload-integrity-ai-review.md)에 분리한다.

## 데이터와 수명

- `0037_student_invitations.sql`: `student_seats`, `student_invitations`, 익명 좌석 4개. 학생 이름·이메일·비밀번호·원문 초대는 seed하지 않는다.
- `0038_student_tasks.sql`: `student_tasks`, `student_task_revisions`. 작업 취소는 접근만 중지하고 기록을 보존한다. 같은 활성 점포·리뷰를 중복 배정하지 않는다.
- 프로젝트 기한은 exclusive `2026-12-31T15:00:00.000Z`로, KST 2026-12-31 23:59:59.999까지다. 매 요청에서 기한을 확인하며 추가 cron이 필요하지 않다.
- 좌석 접근 중지는 기존 세션에도 즉시 적용한다. 회원 탈퇴·이메일 인증 제거·ADMIN 승격 시 학생 접근이 거부된다. 연결 계정 삭제 시 FK는 null로 바뀌고 감사 이력에는 A~D만 남길 수 있다.
- 계정 연결·배정·접근 변경은 기존 감사 로그, 작업 변경은 버전 이력에 기록한다. 초대 원문을 로그나 분석 이벤트에 넣지 않는다.
- 기한 만료는 접근 종료이며 자동 삭제를 뜻하지 않는다. 운영자는 개인정보 방침과 과제 증빙 보존기간을 확정하고, 목적 달성 후 초대 digest·계정 연결·업무 메모를 삭제 또는 익명화한다. 현재 자동 파기 작업을 추가하지 않았다. 학생 안내·보존 결정 전 실제 학생의 개인정보를 대량 적재하지 않는다.

## 비용·운영·제거

기존 D1의 작은 기록과 기존 세션만 사용한다. npm 의존성, AI 모델, R2 binding, Queue, Durable Object, cron, 자동 메일, 유료 API를 추가하지 않는다. 신규 D1 read/write/storage는 계정 기존 한도에 합산된다. 실수 재발급은 과거 초대를 무효화하며 복구할 원문은 없다.

운영 기본 스위치는 `STUDENT_WORKSPACE_ENABLED=false`다. 운영 적용 대상·명령·중지 조건은 [런북](../operations/student-workspace.md)을 따른다. 승인 전 원격 migration·배포·실제 초대 발급을 하지 않는다. 스위치를 끄면 네 경로와 메뉴가 닫히며 기존 데이터는 남는다. 이전 Worker로 되돌려도 추가 테이블은 보존한다. 제거는 프로젝트 종료 후 기록 인계·보존 결정이 끝났을 때 별도 migration/PR로 진행한다.
