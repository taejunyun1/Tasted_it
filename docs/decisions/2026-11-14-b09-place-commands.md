# B09 장소 공개·병합·회수 실행 계약

- 상태: ACCEPTED_IMPLEMENTATION — #439. 운영 실행은 [B09 배포 계획](../operations/2026-11-14-admin-b09-rollout.md)의 범위를 따른다.
- 단위: 공개는 검수 항목 1개, 병합은 원본/대상 1쌍, 회수와 회수 복원은 장소 1개다. 기존 1–4단계 검수와 외부 조회 한도는 바꾸지 않는다.

## 원천과 미리보기

`PLACE_ADMIN_CHANGE`는 현재 ADMIN과 세션에 결속되고, 확정에는 최근 재인증을 요구한다. 입력은 변경별 엄격한 스키마와 최대 300자 사유로 제한한다. 공개는 기존 최종 단계, stage version, claim 미점유, 활성 말단 카테고리, 인허가 OPEN/PENDING·제외 없음, 지역 식당 근거와 중복 DISTINCT 기준을 유지한다. 순수 판정 함수를 사용하며 미리보기에서 제외 상태나 검수 감사 기록을 쓰지 않는다.

하나의 SQL에서 관련 행을 고정 키 순서와 정렬 순서로 읽고 SHA-256을 계산한다. 원천/표시값, 검수 근거, 현재 반응과 불변 이벤트·무효화, 명시 저장 선택과 guest 저장, 연결된 원천·분류·정정·리다이렉트, 방문·사진·별도 평가 원장, 관련 회원/리뷰어/제한 및 TEMP 상태가 포함된다. 원문 행은 메모리와 파라미터로만 사용하고 영속 작업에는 해시·내부 대상 ID·계획 선택·영향 건수만 보관한다. 자유 사유는 기존 작업 입력이며 영수증에 복제하지 않는다.

관계별 최대 1,000행, 공개 중복 비교용 장소 최대 2,000행, 전체 직렬화 768KiB를 넘으면 명시적으로 차단한다. 병합 SQL이 공통 1,000문장 한도를 넘는 경우도 차단한다. 일부 행을 잘라 실행하지 않는다. 관련 변화가 많으면 보수적으로 충돌할 수 있다.

## 원자성·결과

확정 시 같은 SQL을 다시 읽어 해시와 유효 조건을 비교한다. 읽은 원문과 같은 SQL의 결과가 여전히 같은지 확인하는 검사문을 공통 확정 batch의 첫 도메인 검사로 넣는다. 이 검사, 실제 변화, 도메인 감사, 중앙 확정·감사·결과는 하나의 D1 트랜잭션이다. 동일 timestamp 편집과 검사 직후 경합도 전체 취소한다. 시간 경과로 유효성이 변하는 근거는 현재 시각에 다시 평가한다.

병합은 일반 반응의 현재 유효 이벤트만 기존 CAS 규칙으로 전달하고 대상의 기존 선택을 우선한다. 리뷰어 이벤트·방문·사진·별도 평가 원장은 옮기거나 재승인하지 않는다. 회원 명시 저장 해제와 guest 중복·50개 상한을 보존한다. 이미 별도 목적지로 향하는 원본/대상 slug는 차단하며, 원본을 가리키는 이전 alias는 같은 트랜잭션에서 새 대상으로 재결속한다. 대상의 DRAFT/HIDDEN 상태를 PUBLISHED로 바꾸지 않는다.

회수는 장소를 HIDDEN으로 전환하고 새 CATEGORY_RECALL 검수 항목을 남긴다. 사진 파일·원장·검수 상태는 보존하며, 서버 공개 조건에서 노출과 참여 자격을 차단한다. 회수 복원은 정확한 기존 RECALL 확정 영수증·원 작성자/세션/종류/시각·중앙 감사 1건과 회수 직후 전체 해시가 맞을 때만 가능하다. 현재 ADMIN의 새 세션에서도 재인증 후 실행할 수 있다. 원 세션이 삭제된 경우에도 보존된 확정 세션 식별자와 나머지 근거를 검증한다. 중간 편집이나 이후 다른 회수가 있으면 차단한다.

복원은 해당 회수의 역작업이며 병합 전체 undo나 임의 revision의 공개 상태 덮어쓰기가 아니다. 기존 임의 복원 HTTP 경로는 차단하고 이력을 읽기 전용으로 남긴다. 정정 HTTP 경로의 status 입력은 거절하며, 영업 상태 HTTP 처리는 status를 SQL SET에서 제외한다. 숨김 장소의 OPEN 근거는 갱신할 수 있으나 숨김 상태를 유지하고 별도 B09 공개를 요구한다. 공개 장소의 폐업·숨김 전환은 B09 회수를 먼저 안내한다. 내부 helper의 기존 기본 동작은 보존한다. 완료는 검증된 중앙 영수증으로만 표시하며 같은 요청 재실행은 같은 결과를 돌려준다. 응답이 불명확하면 성공이나 적용 0건으로 단정하지 않는다. B06에는 안전한 처리 건수만 제공한다.

## 영향 표시의 한계

현재 연결 총수와 실제 예정 변화는 구분한다. 미리보기의 이름·주소·현재 상태는 조회 시점 표시값이고 영향 건수는 준비 시점 값이다. 관련 행이 달라지면 stale 표시 후 새 미리보기를 요구한다. 공개 상태, 목록 노출 조건, 추천·리뷰어 참여 조건, 리뷰/사진의 실제 공개 조건은 각각 구분한다. 개인화 순위나 재계산 작업의 완료를 예측하지 않으며 기존 epoch/revision 갱신 규칙과 평가 처리 방식을 유지한다.
