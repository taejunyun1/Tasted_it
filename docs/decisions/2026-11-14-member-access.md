# B07 회원 검색·접근 제한·세션 회수

- 운영 절차: [B07 운영 적용 계획](../operations/2026-11-14-admin-b07-rollout.md)

회원 접근 상태는 `users.role`, 리뷰어 자격, 학생 좌석, 공개 콘텐츠와 별도로 관리한다. `/admin/members`는 이름·이메일·ID 검색, 최대 50건 cursor, 마스킹된 이메일, 현재 제한과 활성 세션 참조만 제공한다. 제한 사유는 현재 상태 상세와 해당 작업의 미리보기에서만 보인다. B06 이력에는 자유 입력 사유를 내보내지 않는다.

## 변경 계약

제한 설정과 해제는 사유 및 최근 10분 재인증이 필요하다. 설정은 즉시 시작하며 1~90일 이내의 명시적 만료가 필수다. UI는 1·7·30일을 제안한다. 미래 예약 제한은 지원하지 않는다. 본인 제한은 금지하고, 시스템용 미인증 계정을 제외한 마지막 유효 관리자는 제한·강등·삭제할 수 없다.

공통 B02 미리보기/확정 계약에 `MEMBER_ACCESS_CHANGE`를 추가한다. 대상 계정/제한 version과 세션 집합이 달라지면 확정을 거절한다. 변경, 기존 세션 폐기, 불변 감사 영수증을 D1 batch로 처리한다. 설정과 해제 모두 기존 세션을 지운다. 만료는 시각 비교로 자동 비활성화하며 삭제된 세션은 복원하지 않는다. 해제/만료 이후에도 새 로그인만 가능하다.

비밀번호·Google·NAVER 로그인과 기존 세션 조회에 동일 접근 제한을 적용한다. DB의 세션 INSERT/UPDATE guard가 로그인 경쟁 조건을 닫는다. 계정에 묶인 OAuth 요청도 제한 변경 시 폐기한다. 리뷰 작성 전환, 투표와 저장, 학생 업무 capability의 쓰기 경계도 제한 상태를 확인한다. 공개 평가·미디어의 기존 노출 기준은 변경하지 않는다.

이미 시작된 외부 OAuth 교환·토큰 폐기 호출을 네트워크 중간에 취소할 수 있다고 보장하지 않는다. 호출 직전에 접근을 재검사하고, 제한이 도중 적용되면 이후 연결 정보 변경과 세션 발급을 DB에서 거부한다.

인증 시작 시각이 마지막 접근 상태 변경보다 이르면, 그 사이 제한이 해제되었더라도 옛 인증 흐름의 세션/연결 쓰기를 거부한다. 제한 이후 새로 시작한 로그인만 허용한다.

## 데이터·migration

새 `member_access_restrictions`는 현재 상태 한 행을 유지한다. 사유는 2~300자로 제한하고 개인정보·인증정보 입력을 피한다. 계정 삭제 시 cascade로 제거하며 지난 자유 입력 사유는 별도 이력으로 복제하지 않는다. 공통 영수증은 대상 참조/상태/만료/세션 수만 보존한다.

0047은 기존 0042를 수정하지 않고 kind CHECK 확장을 위해 operations/commits/checks 세 테이블을 재구성한다. 모든 열과 rowid를 먼저 복사하고 자식부터 제거한 뒤 이름을 복원한다. 기존 FK·인덱스·불변/재인증 guard를 재설치한다. `defer_foreign_keys`와 자식 우선 순서를 사용하며 마이그레이션 전후 영수증 fixture 및 `foreign_key_check`로 확인한다. [Cloudflare D1 migration](https://developers.cloudflare.com/d1/reference/migrations/), [D1 foreign keys](https://developers.cloudflare.com/d1/sql-api/foreign-keys/)

운영은 짧은 fence, 백업, 세 테이블의 사전/사후 digest를 포함한 연결된 계획으로 한정한다. 원격 실행·배포 담당자는 root이며 이 구현 작업은 운영 계정을 변경하지 않는다. 새 공급자·의존성·binding·cron은 없다. 테스트의 별도 `MIGRATION_DB`는 로컬 Workers pool 전용이며 운영 binding이 아니다.

## 검증과 복구

로컬 synthetic 계정으로 USER/REVIEWER/ADMIN/탈퇴 상태, 만료/해제, 새 로그인, 중복·경쟁·stale 확정, 세션 선택/전체 회수, 마지막 유효 관리자, 이력 보존과 로그인 403을 확인한다. UI는 데스크톱/모바일에서 확인한다. 실제 운영에서는 기존 운영자 읽기 및 재인증 없는 거절, 전용 USER fixture의 제한/해제와 신규 로그인만 계획에 따라 검증한다. 실제 회원·역할·공개 기록·메일/OAuth 공급자 호출은 변경하지 않는다.

장애 시 같은 schema의 fence로 닫고 전진 수정한다. 새 테이블 또는 이력을 즉시 DROP하지 않는다. 제한을 되돌려도 이미 삭제된 세션은 되살리지 않는다.
