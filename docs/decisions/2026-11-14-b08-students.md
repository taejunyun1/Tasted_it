# B08 학생 관리 변경·경합·일괄 결과

- 상태: 구현 검토 — #435 및 학생 구현 PR 병합 시 ACCEPTED
- 소유: 학생 관리 구현 담당, 배포·공통 계약은 통합 담당
- 전제: B02/B03/B06 및 공통 0048. 기존 학생 workspace flag, A–D 역할·기한을 유지한다.

## 변경 계약

`/admin/students`의 초대 발급·재발급, 좌석 접근 허용/중지, 배정·취소는 미리보기 → 최근 재인증 → 확정 순서로 처리한다. 미리보기 자체는 업무 상태를 바꾸지 않는다. 동일 세션/관리자에 결합된 10분 B02 작업 하나를 사용하며, 일괄 배정은 최대 25개 선택을 고정한다.

일괄 미리보기는 각 항목을 배정 예정, 이미 배정되어 건너뜀, 원천 확인 불가로 구분한다. 확정은 좌석과 실제 변경할 원천/배정의 스냅샷을 DB에서 다시 비교하고 모든 예정 변경을 한 트랜잭션으로 수행한다. 한 예정 항목이라도 달라졌으면 적용 0건이며, 새 미리보기가 필요하다. 이미 건너뛴 항목은 미리보기 시점의 판정으로 남긴다. 성공 영수증은 적용/건너뜀 수와 고정 이유, 내부 대상 ID·종류를 기록한다. 대상의 현재 제목은 ADMIN 화면에서만 다시 조회하며 제목·메모를 영수증에 저장하지 않는다. 삭제된 대상은 내부 참조와 대상 없음 상태를 표시한다. 공통 B06 목록에는 수량만 노출하며 학생 메모·초대·개인 식별값을 추가하지 않는다.

공통 `getVerifiedAdminOperation`으로 확정 작업/commit/세션/관리자/시각/감사 1건의 연결을 확인한 뒤 영수증을 표시한다. 응답 유실 시 같은 작업 주소에서 결과를 확인하고 같은 확정을 재전송해도 중복 배정·감사를 생성하지 않는다.

## 초대 비밀값

초대 원문은 확정 실행의 메모리에서 생성하고 기존 초대 테이블에는 SHA-256 digest만 저장한다. B02 미리보기/결과/감사에는 원문과 digest를 저장하지 않는다. 최초 성공 HTTP 응답에서만 원문 링크를 제공하며 replay·새로고침·영수증에서 재표시하지 않는다. 응답을 잃었으면 새 미리보기와 확정으로 재발급한다. 재발급은 스냅샷에 포함된 이전 미사용 링크를 무효화한다. 메일·외부 전달을 수행하지 않으며, UI는 발급/대기/수락/취소/만료만 표현한다.

## 좌석·작업 보존과 경합

공통 0048의 좌석 `version`은 모든 UPDATE에서 증가한다. 발급/재발급도 좌석을 갱신하므로 수락·접근 변경과 경쟁하면 하나만 확정된다. 기존 좌석 소유자, capability, 기한을 임의로 변경하지 않는다. 접근 중지는 기존 로그인으로 수행하는 학생 작업도 즉시 거절한다. 중지 후 재개 사이에 진행 중이던 요청은 읽어 둔 좌석 버전과 최종 SQL의 버전 비교로 거절한다.

배정 취소는 active/version을 비교하고 task version을 증가시킨다. 학생 제출과 취소가 경쟁하면 이후 요청은 충돌로 끝난다. 이전 분류·교차 확인·학생 역할·작업 이력을 삭제하지 않는다. 접근 재개는 원래 소유자와 이력을 유지하며 기존 전역 계정 접근 제한을 해제하지 않는다. 기존 학생 제출/교차검수의 작업 버전, 담당자, 별도 학생의 확인, 현재 capability 검사는 유지한다.

## 기술·운영 경계

새 공급자, 라이브러리, binding, cron, 저장소, 메일 발송을 추가하지 않는다. 기존 D1/B02와 한 좌석 버전 필드를 사용한다. 공통 순번 0048 및 배포 절차는 통합 PR의 승인된 운영 계획을 따른다. 기존 legacy service 호출은 내부 호환성을 유지하되 조건부 좌석/작업 비교를 보강한다. 웹 변경 경로는 모두 새 명령 경로를 사용한다.

검증은 로컬 합성 계정/자료와 Worker D1 pool에서 수행한다. 브라우저 긍정 흐름의 assurance는 spec-local 합성 세션에만 넣으며 실제 재인증 성공이라고 주장하지 않는다. 부정 흐름은 assurance 없이 미리보기 확정이 재인증으로 이동하고 업무 상태를 바꾸지 않는 것을 확인한다. 운영 검증은 기존 사람의 좌석·초대·배정을 변경하지 않는 읽기와 거절 흐름으로 제한한다. 운영에서 초대 발급/수락·실제 학생 재인증·실제 일괄 변경은 미검증으로 남긴다.

문제 발생 시 학생 workspace flag를 끄고 확정 경로를 닫는다. 이미 확정된 배정/이력/감사/좌석 버전은 보존한다. DB migration을 역으로 제거하거나 버전을 낮추지 않고 전진 수정한다. 되돌리기 전에 변경 전 업무 상태 및 현재 소유자를 확인하며 저장 이력을 일괄 삭제하지 않는다.
