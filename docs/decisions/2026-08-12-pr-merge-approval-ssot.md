# Pull Request 병합 승인 SSOT

- **상태:** ACCEPTED — 이 문서를 포함한 Pull Request 병합 시 적용
- **작성일:** 2026-08-12
- **추적:** [GitHub Issue #90](https://github.com/taejunyun1/Tasted_it/issues/90)
- **적용 범위:** 코드, 문서, migration, 외부 연동, rollout, 배포와 원격 운영 작업의 승인 기록

## 결정

앞으로 Re:Taste 저장소에서 별도 승인과 사전 승인을 반복해 확인하지 않는다. 저장소 소유자 또는 권한 있는 유지보수 담당자가 Pull Request를 병합한 기록을 승인 단일 기준 원본(SSOT)으로 사용한다.

> **표준 문구:** 별도·사전 승인은 PR 병합으로 대체한다.

Pull Request 본문에 명시된 다음 항목은 병합과 동시에 승인 완료로 본다.

- 코드와 문서 변경
- 신규 migration과 적용 순서
- 외부 API·SaaS·Cloudflare 기능의 사용 범위
- 운영 contract smoke와 제한된 실제 호출
- rollout, feature flag, 배포와 rollback 계획
- 대상과 범위가 구체적으로 적힌 원격 D1 및 운영 작업

병합 뒤에는 동일 범위에 대한 채팅, 댓글 또는 별도 메시지 승인을 다시 요청하지 않는다.

## 승인과 실행의 구분

Pull Request 병합은 명시된 작업을 실행할 권한을 부여한다. 실제 migration, 배포, 외부 호출 또는 데이터 작업이 완료됐다는 뜻은 아니다. 지정된 운영 담당자가 실행하고 결과와 실패·rollback 여부를 Pull Request 또는 운영 기록에 남긴다.

## Pull Request 필수 승인 범위

운영 영향이 있는 Pull Request는 최소한 다음을 적는다.

1. 대상 환경과 작업 대상
2. 실행할 명령 또는 외부 작업
3. 데이터·개인정보·비밀값 경계
4. 호출량과 비용 상한
5. 테스트와 실제 확인 방법
6. 장애 중단 조건과 rollback
7. 실행 담당자와 실행 후 남길 증거

이 정보가 빠졌으면 병합으로 승인되는 범위에도 포함되지 않는다.

## 병합으로 승인되지 않는 항목

- Pull Request에 적히지 않은 운영 데이터 변경
- 대상이나 행 수가 정해지지 않은 삭제·덮어쓰기
- 비밀값의 화면 출력, 로그 기록, 문서·댓글 공유
- 다른 서비스, 계정 또는 환경으로의 임의 확장
- `PROPOSED` 또는 `HOLD` 상태를 유지한 문서의 구현

이 항목이 필요하면 먼저 Pull Request 범위를 갱신하고 권한 있는 담당자가 해당 내용이 포함된 상태로 병합해야 한다.

## 문서 상태 규칙

- `ACCEPTED`, `GO`: 병합된 범위의 구현·운영 승인 완료
- `CONDITIONAL GO`: Pull Request에 적힌 조건을 충족하는 범위만 승인
- `PROPOSED`, `HOLD`, `NO-GO`: 병합돼도 구현 승인이 아님

문서 자체를 기록 목적으로 병합하는 경우가 있으므로, 병합만으로 문서 상태를 추정하지 않고 문서의 명시적 상태를 함께 확인한다.

## 기존 규칙과의 관계

- `AGENTS.md`의 feature branch → Pull Request → checks → merge → merged `main` 배포 순서를 유지한다.
- `COWORK.md`는 이 결정을 공동작업 절차에 반영하는 실행 규칙이다.
- 긴급 hotfix의 직접 `main` push 예외는 `AGENTS.md`의 명시적 사용자 승인 규칙을 따른다.
- 보안·개인정보·비밀값·파괴 작업 금지는 승인 방식이 바뀌어도 완화되지 않는다.

## 이전 방식에서의 변경

기존에는 설계 승인, migration 승인, 실제 호출 승인, 병합 승인과 배포 승인을 채팅에서 각각 다시 요청할 수 있었다. 이제는 관련 항목을 하나의 Pull Request 본문에 명확히 모으고, 권한 있는 담당자의 병합을 최종 승인 기록으로 사용한다.

따라서 작업자는 병합 전에는 필요한 증거와 범위를 완성하고, 병합 후에는 같은 범위의 승인을 재요청하지 않고 승인된 rollout을 진행한다.
