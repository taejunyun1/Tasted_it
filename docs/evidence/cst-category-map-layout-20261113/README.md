# CST T07 카테고리 검색·지도 실패 화면 검증

추적 #383 / SSOT #354 U02·U03·T07의 부분 검증이다. 운영 지도 장애나 T07 전체 검수 완료로 해석하지 않는다.

## 재현과 수정 범위

- 원래 main `4c18dd4`에 시험만 추가한 `6e0d876`에서 2026-11-13 22:39:51~22:40:29 KST에 실제 모바일 RED 2건을 확인했다. 320×1000에서 검색버튼 텍스트는 두 줄, SDK 요청을 명시 차단한 뒤 지도 영역은 733px였다. [red.json](./red.json)에 비민감 측정값을 보존했다. 최초 trace/context 원본은 공개 저장소 밖의 소유 임시 증거에 유지한다.
- 좁은 카테고리 검색 form을 grid와 줄바꿈 방지로 조정한다. 지도는 기존 error 상태만 data 속성으로 노출하고 모바일 카테고리 실패 상태에만 작은 안내 영역을 적용한다. 정상 지도 규칙과 검수 전용 `app.css`는 수정하지 않는다.
- 오류 문구는 사용자가 장소 목록으로 계속 탐색할 수 있게 안내하며 SDK·키 설정 상세를 보여 주지 않는다.

## 검증 상태

최신 main의 backend #381과 평가 fixture 후속을 통합한 checkpoint `ce476f0`에서 2026-11-13 22:53:40~22:54:38 KST에 실제 desktop/mobile E2E 8/8을 통과했다(Playwright 실행24.8초). [green.json](./green.json)에 source SHA·실행 범위·한계를 기록했다. 관련 기존 map unit9, 타입·빌드, 시험 코드 타입 검사, production audit0과 독립 정적 리뷰도 통과했다. 개발 의존성을 포함한 audit46(low4/moderate26/high15/critical1)은 기존 잔여이며 이 수정에서 의존성을 변경하지 않는다.

독립 리뷰의 검증 공백 2건은 버튼 높이 외 폭44px 검사와 정상 지도 기존 최소 영역498/518px 보존 검사로 보강했다. 실패 반복마다 SDK 차단 증가와 일반/확대 두 크기의 목록→상세 이동을 확인하며, 합성 초기화에서는 pageerror0도 확인했다.

새 시험은 320px 및 640px에서 CSS `zoom:2`로 콘텐츠를 확대해 버튼 한 줄·44px 폭/높이·키보드·수평 넘침을 확인한다. SDK 실패는 브라우저 요청 abort, 초기화된 정상 크기 비교는 합성 SDK만 사용한다. 실제 NAVER 타일 로딩·등록 도메인·native 브라우저 200% 확대·실기기 핀치 확대·다른 브라우저 지원의 증거가 아니다.

기존 지도/목록 전환의 q/bbox/selected·장소 ID 집합·새로고침 회귀도 SDK 네트워크를 명시 차단한 채 확인한다. 실패 안내→목록→상세 연결은 일반 크기와 콘텐츠 확대에서 각각 확인한다. 실제 장소·계정·초대·메일·외부 API·과금·운영 배포/remote D1은 실행하지 않는다.

- [desktop-ready-synthetic.png](./desktop-ready-synthetic.png): 실제 desktop 브라우저에서 합성 SDK 초기화와 기존 지도 영역 크기. 실제 지도 타일이 아니다.
