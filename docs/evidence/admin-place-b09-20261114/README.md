# B09 장소 통제 화면 검증

2026-11-14, 격리된 로컬 D1의 합성 장소와 QA 관리자 세션으로 검증했다. 운영 데이터·메일·유료 외부 호출은 사용하지 않았다.

## 최종 결과

- JavaScript 비활성, 기본 30초 제한, 재시도 0, 일반 모션과 기본 클릭으로 3개 시나리오 × desktop/mobile 총 6개가 통과했다.
- 단일 공개 선택과 병합 미리보기·최근 인증 차단은 4/4 통과했다. 회수용 fixture를 정정한 뒤 공개 회수·영수증 재조회는 2/2 통과했다.
- FINAL_APPROVAL에서 native radio는 한 곳만 선택되며, 공개 POST 없이 선택 동작만 확인했다. 병합 미리보기는 동명 대상의 주소·ID를 구분하고, 최근 인증 없는 확정은 해당 작업을 보존한 재인증 주소로 이동했다.
- 공개 회수는 로컬 합성 세션의 인증 증거로 확정한 뒤, 같은 작업 URL 재조회에서 실제 영수증·적용 1건·확정 버튼 없음·회수 복원 미리보기 진입을 확인했다.
- 별도 HTTP 계약 검증은 7/7 통과했다. 이 화면 증거를 운영 배포나 실제 관리자 재인증의 증거로 사용하지 않는다.

## 화면 판독

4장을 직접 판독했다. 수정한 미리보기·영수증 영역에서 이름·주소·ID, 공개 조건과 건수 단위가 구분되며 가로 넘침 검증이 통과했다. 원장·사진 보존 안내와 병합 자동 되돌리기 미지원 안내가 보인다. 기존 하단 검수 영역과 가로 스크롤 탭은 그대로다.

이미지는 최종 문구 정정 전 capture다. 회수 영수증의 `숨김 → 숨김` 상태 열은 현재 조회 상태에서 만들어진 것으로 관측됐으며, 과거 상태 전후 이력의 증거가 아니다. 최종 문구는 현재 상태와 확정 요청 상태를 구분하도록 정정했다. 이 한 줄 정정 뒤 추가 화면 캡처는 하지 않았다.

## 초기 실패와 정정

- 처음 결합 시나리오는 30초 제한에 실패했다. 초기 SSR 비용이라는 추정은 철회했다. trace의 첫 탐색은 392/52ms였고, 병합 클릭의 안정성 대기가 약 28.5초였다.
- 별도 위치 측정에서는 입력 직후 스크롤이 약 300ms 후 안정됐다. 고정 대기·강제 클릭·모션 비활성화·제한시간 확대 없이, 최대 3초 내 100ms 간격으로 버튼 위치가 연속 두 번 같은지 확인한 뒤 기본 스크롤·viewport 검사·클릭을 수행한다.
- 분리 실행 중 회수 2건은 fixture에 남아 있던 ACTIVE FINAL_APPROVAL 작업 때문에 정상 거절됐다. 회수 시나리오에서만 자기 합성 작업을 COMPLETED로 준비하고 미리보기 영역 존재를 먼저 확인한 뒤 2/2 통과했다.
