# D01·D02의 누락 수용 사례 보완

기준 통합 코드 `c3147a9`의 기존 동작에 assertion을 추가했다. 수집·중복 판정·이전 처리의 제품 코드는 바꾸지 않았다. 여섯 새 사례는 첫 실행에서 통과했으며, 결함 수정 또는 RED→GREEN으로 표현하지 않는다.

## 확인한 경계

- 같은 원천을 서로 다른 완료 수집 run에서 읽어도 원천 ID·최초 확인일·검수 작업이 늘어나지 않는다. 마지막 확인일·원천 수정일과 실행별 결과는 갱신된다. 공개 장소 수는 그대로다.
- `DISTINCT`, `LINK_EXISTING`, `MERGE`는 이 단계의 검토 판정이다. 사유·담당·시각·감사를 기록하고 미판정 수를 줄이지만, 장소 병합이나 공개는 수행하지 않는다. 실제 병합은 별도 B09 미리보기·확정 절차다.
- 상호가 변경되어 동일 후보가 아닌 현재 자료는 stale로 거절하며 새 판정·감사·장소 변화가 없다.
- `MOVED`는 기존 위치의 공개 상세·목록·추천을 차단한다. 확인하지 못한 새 위치를 만들지 않고 기존 주소·좌표·확인일을 보존한다. 사건 처리와 revision·감사를 한 번 기록한다.

## 실행 결과

[실행 요약](summary.json)에 명령·기준 SHA·수정 시험 파일 해시를 기록했다. 수집/중복 파일 전체 16건과 MOVED 지정 1건이 통과했다. MOVED 명령의 나머지 9건은 이름 필터로 실행 대상에서 제외됐다. 타입 검사와 운영 의존성 감사도 통과했다.

이번 결과는 로컬 격리 D1의 해당 경계 증거다. 전체 T05/T08, 실제 영업 사실, 외부 원천 호출, 운영 배포 또는 필수 CI 통과를 의미하지 않는다. #397 HOLD와 실제 정책 확인 필요 상태는 유지한다.

Codex root의 독립 검토에서 세 시험 파일과 실제 서비스 경로를 대조했고 새 차단 문제는 없었다. stale 검증은 요청 전에 변경된 후보를 거절한 범위이며 진행 중 원자 경합으로 확대하지 않는다.
