## 4. 결정 원장 — 값은 임의로 확정하지 않는다

## 7. 시험·실증·콘텐츠 운영

기술 검수는 [실행서](../operations/cst-acceptance.md)의 T01~08로 관리한다. 기본 제안은 desktop Chromium 1440×900, mobile 390×844·320px 폭, 200% 글자/zoom·키보드다. 이 값은 DEC-07 전까지 계약상 지원환경/성능 목표가 아니다. Safari/Firefox/실기기 범위는 결정 후 추가한다. 성능은 목표를 정하기 전 수치 관측만 한다.

콘텐츠 표본 기록은 장소 내부번호로 연결하되 공개 저장소·Wiki에는 실제 상호·주소·학생/참여자 개인정보·비밀값·원문 자료를 싣지 않는다. 권한 있는 비공개 운영 저장소의 식별자/증거 참조와 비식별 집계만 공유한다. 사진은 장소·촬영일·제공자/권리·노출검토·승인 확인, 외부 원문·사진·평점·외부 ID 축적 금지 원칙을 따른다. 반입은 후보이며 자동 공개하지 않는다.

연구팀 기록은 `익명 세션코드 / 동의 확인 / 기기 / 과업 / 성공여부 / 시간 / 막힘 / 도움요청 / 관찰 / 버전`을 남긴다. 기술시험 합격을 이용자 실증 성과로 세지 않는다. 인원/목표값 미확정은 DEC-07 OPEN으로 남기고 참여자를 임의 모집·연락하거나 동의를 추정하지 않는다.

## 8. 승인·배포·복원과 위험 대응

현재 스택·불변 migration·두 cron·기존 권한을 따른다. 새 storage/provider/유료 API·원격 D1·인증/평가/사진 활성화는 tech-stack governance의 구체 PR과 비용·privacy·한도·rollback 증거를 요구한다. **본 계획 채택만으로 미정 정책이나 원격 실행을 포괄 승인하지 않는다.** 학생 초대/배정·중지한 감시·기존 서비스는 보존한다.

기능마다 최신 origin/main feature/worktree → scope/owner Issue → 코드·RED/GREEN → desktop/mobile(해당 UI) → PR/diff 독립 리뷰 → 필수4CI → squash merge → Wiki → local Archive/원격삭제 순서다. 운영 배포는 병합 main·지정 운영자·명시된 PR 범위로 하고 현재 정상 version과 rollback을 먼저 기록한다. 배포 후 기존 live Worker RSI·HTTP/권한·관련 흐름 확인이 없으면 `VERIFIED_LIVE`가 아니다. 문서만 변경한 PR은 배포하지 않는다.
